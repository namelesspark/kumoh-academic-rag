# 데이터 반입·공개 정책

커밋하기 전에 이 문서를 확인한다. 한 번 푸시된 파일은 히스토리에서 지우기 어렵다.

---

## 1. 절대 커밋하지 않는 것

### 학적 데이터
학번, 성명, 이수 학점, 성적, 장학 수혜 이력, 연락처.
**테스트 픽스처도 예외 없다.** 필요하면 명백히 가상인 값을 쓴다 (`학번: 00000000`, `이름: 홍길동`).

### 학칙·규정 원문
학교 저작물이다. `data/raw/` 는 `.gitignore` 로 막혀 있고, `*.pdf` / `*.hwp` 는 경로와 무관하게 전면 차단된다.

### 인덱스 파일
`.faiss`, `chroma/` 등은 임베딩에서 원문을 상당 부분 복원할 수 있고 용량도 크다. 산출물이지 소스가 아니다.

### 시크릿
API 키, `.env`, 학적 시스템 접근 정보. `.env.example` 만 커밋한다.

---

## 2. 커밋해도 되는 것

- 소스 코드, 설정 YAML (값이 아닌 스키마)
- `docs/`
- 평가 질문셋 — **단, 개인 식별 정보를 제거한 뒤**
  실제 학생 문의를 그대로 옮기지 말고 일반화한다.
  `"20220680 오의진인데 졸업 가능?"` → `"컴퓨터공학전공 4학년, 졸업 요건 충족 여부"`

---

## 3. 저작권 및 리포 공개 범위

공모전 신청서 유의사항:

> 당선 주제에 대한 저작권, 사용권 등 모든 저작재산권의 권리는 국립금오공과대학교에 귀속됨

**따라서 다음을 권장한다:**

1. **초기에는 private 리포로 시작한다.** 공개 전환은 AX교수학습센터 담당자에게 확인한 뒤.
2. **임의로 오픈소스 라이선스(MIT 등)를 붙이지 않는다.** 저작재산권이 학교에 귀속된 산출물에
   개인이 라이선스를 부여할 권한이 없다. 라이선스 표기는 담당 부서와 협의 후 결정한다.
3. 포트폴리오·취업용으로 공개가 필요하면, 공개 전에 담당자에게 범위를 서면으로 확인받는다.
   (코드만 공개 / 데이터 제외 / 캡처만 등)

이 항목은 나중에 문제 삼기 어렵게 만들어두는 게 목적이다. 확인받은 내용은 이 문서에 날짜와 함께 기록한다.

### 확인 이력

| 날짜 | 확인 내용 | 담당 |
|---|---|---|
| (미확인) | 리포 공개 범위 및 라이선스 표기 가능 여부 | AX교수학습센터 |

## 4. 사고 대응

민감 파일을 커밋해버렸다면:

1. **푸시 전이면** — `git reset --soft HEAD~1` 후 `.gitignore` 수정하고 다시 커밋.
2. **푸시했다면** — `git filter-repo` 또는 BFG로 히스토리에서 제거 후 force push.
   그리고 노출된 것이 키라면 **반드시 재발급**한다. 히스토리를 지워도 이미 노출된 것으로 간주한다.
3. 학적 데이터가 노출됐다면 즉시 리포를 private으로 전환하고 담당 부서에 보고한다.

---

## 5. 커밋 전 체크

```bash
git status              # 의도하지 않은 파일이 staged 되어 있지 않은지
git diff --cached       # 실제 내용에 개인정보가 없는지
git check-ignore -v data/raw/some.pdf   # ignore가 실제로 동작하는지
```

노트북을 커밋한다면 실행 결과(output)를 반드시 클리어한다. 셀 출력에 데이터가 그대로 남는다.
