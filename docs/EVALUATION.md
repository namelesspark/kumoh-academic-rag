# 평가 설계

제안서에 명시한 정량 검증 지표를 어떻게 측정할지 정의한다.
**코드를 짜기 전에 평가 기준을 먼저 고정한다.** 나중에 만들면 잘 나온 숫자에 맞춰 기준을 고르게 된다.

---

## 질문셋

빈출 질문 50~100개. 수집 경로:

- 학과 사무실·행정실에 실제로 자주 오는 문의 (담당자 인터뷰)
- 학교 홈페이지 FAQ
- 에브리타임 등 학생 커뮤니티의 학사 질문 (개인정보 제거 후 일반화)

### 유형 분류 (유형별로 따로 측정한다)

| 유형 | 예시 | 검증 포인트 |
|---|---|---|
| A. 단순 조회 | "성적장학금 지급 기준이 뭐야?" | 기본 Recall |
| B. 조문 지정 | "학칙 제30조 내용 알려줘" | BM25 기여도 |
| C. 다중 조건 | "전과하려면 학점이랑 학기 조건이 어떻게 돼?" | 여러 청크 동시 검색 |
| D. 개인화 | "내 학적으로 졸업하려면 몇 학점 더?" | Agent 루프 (api 리포에서 측정) |
| E. 답변 불가 | "내일 날씨 어때?" | 거부 정확도 — **환각 통제의 핵심** |

E 유형을 반드시 넣는다. 정확도만 재면 "무조건 뭐라도 답하는" 시스템이 유리해진다.

---

## 지표

### 1. Retrieval Recall@k
정답 조문이 상위 k개 안에 들어왔는가. `k = 5` 기준, `k = 1, 3, 10` 도 함께 기록.

각 질문에 정답 `article_path` 리스트를 라벨링해둔다. 이게 평가의 기준선이다.

```
Recall@5 = (정답 조문이 top5에 포함된 질문 수) / (전체 질문 수)
```

**측정 조건을 나눠서 기록한다** — 리랭커 기여도를 분리해야 한다:

| 조건 | Recall@5 |
|---|---|
| BM25 단독 | |
| Dense 단독 | |
| Hybrid (RRF) | |
| Hybrid + Reranker | |

### 2. 답변 정확도
LLM 답변이 정답 조문 내용과 일치하는가. 3단계 수동 채점:

- **2점** — 정확하고 근거 조문을 올바르게 인용
- **1점** — 방향은 맞지만 조건 누락 / 인용 부정확
- **0점** — 틀림, 또는 근거 없는 서술

정확도 = 총점 / (문항 수 × 2)

### 3. 거부율 (E 유형)
소스에 근거가 없을 때 답변을 만들지 않고 "행정실 문의" 안내로 넘겼는가.
**이 지표가 낮으면 나머지 숫자는 의미가 없다.** 환각하는 시스템이기 때문이다.

### 4. 응답 지연
검색 / 리랭킹 / 생성 단계별 소요 시간. sLLM 경량화 검토의 근거 데이터가 된다.

## 평가 실행

```bash
python scripts/run_eval.py --config configs/eval.yaml --output data/eval/results/
```

결과는 조건·날짜별로 저장한다. 파라미터를 바꿔가며 비교하는 게 목적이므로
"어떤 설정에서 나온 숫자인지"가 결과와 함께 남아야 한다.

---

## 라벨링 주의

정답 조문 라벨링은 시간이 오래 걸리고 한 번 잘못하면 모든 측정이 오염된다.
- 한 질문에 정답 조문이 여러 개일 수 있다 (C 유형). 리스트로 라벨링한다.
- 학칙 개정 시 라벨도 갱신해야 한다. 라벨 파일에 기준 시행일을 명시한다.
- 애매한 질문은 라벨링하지 말고 질문셋에서 뺀다. 억지로 라벨을 붙이면 노이즈가 된다.
