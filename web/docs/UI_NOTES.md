## 화면 구성

학사 행정 인공지능(AI) 비서는 한국어로 아이오, 영어·중국어로 AIO라고 부른다. 입력창 안내, 답변, 대화 목록·알림, 생각 과정, 안내 모드 인사에는 이 이름을 쓴다. 테크모는 삼족오 캐릭터 이름으로, 그림의 대체 글과 캐릭터 말풍선에 쓴다.

```
┌─────────────────────────────────────┐
│  금오공대 학사 안내            [설정] │
├─────────────────────────────────────┤
│                                     │
│   ┌───────────────────────┐         │
│   │ 전과 조건 알려줘        │  (사용자)│
│   └───────────────────────┘         │
│                                     │
│ ┌─────────────────────────┐         │
│ │ 전과는 2학년 이상, 직전   │  (AI)   │
│ │ 학기 평점 2.5 이상...    │         │
│ ├─────────────────────────┤         │
│ │ 📄 학사운영규정 제30조 ①  │  (인용) │
│ │    시행 2025-03-01       │         │
│ │    공식 원문 보기         │         │
│ └─────────────────────────┘         │
│                                     │
├─────────────────────────────────────┤
│ [내 학적 반영 ○ ]  질문 입력...  [↑] │
└─────────────────────────────────────┘
```

## 시연 계정 로그인과 둘러보기

로그인 화면은 소개와 440px 카드를 56px 간격으로 놓는다. 학번과 비밀번호를 입력하거나 시연 계정을 눌러
칸을 채운 뒤 로그인한다. 서버가 성공을 확인한 뒤 학생 ID 하나만 탭 저장 공간(`sessionStorage`)의
`demo-student-id`에 남긴다. 실제 학교 인증이 아니며 학번·비밀번호·둘러보기 상태는 저장하지 않는다.

소개에는 Gugi 제목 그림 `/chat-assets/title-lettering.png`와
`근거 조문과 함께 답하는 금오공대 학사 안내` 한 줄을 둔다. 그림이 없으면 `졸업까지,`와
`아이오와 함께`를 들여쓰기 없는 두 줄 제목으로 보인다. 위에는 도면 치수선, 아래에는 24px 간격의
눈금 줄을 두고 둘 다 화면 읽기에서 뺀다. 제목 그림은 넓은 화면에서 `clamp(280px, 40vw, 507px)`,
390px에서는 화면 폭의 78%로 보인다. 기능 이름 알약 여섯 개와 긴 소개 글은 제거했다.
시연 학번은 `20990002`, `20990003`, `20990004`다. 입력란은 숫자 키보드·최대 여덟 자리이며,
이 세 값에 정확히 일치해야 로그인 요청을 보낸다. 다른 학번은 요청 전에 같은 계정 불일치 문구를 보인다.

- **성공과 오류** — `POST /api/v1/demo-login`의 200 응답에서 가상 학생을 확인한다. 틀린 계정은
  `학번 또는 비밀번호가 맞지 않아요`를 표시한다. 성공하면 테크모가 `OO 이수 내역으로 들어왔어요`라고
  알리고 기존 축하 예약을 이용해 0.65초 뒤 메인으로 간다. `OO`는 응답의 학생 이름이다.
- **테크모** — 평소에는 `학번으로 들어와 보세요!`, 시연 계정으로 채우면 `좋아요, 로그인을 눌러 보세요`,
  오류에는 정숙 자세로 `쉿, 시연 계정으로만 들어올 수 있어요`를 표시한다. 폭 112px, 카드 오른쪽 -30px·
  위 -92px에 놓고 3.6초마다 8px 오르내린다. 움직임 줄이기에서는 멈춘다.
- **둘러보기** — `로그인 없이 둘러보기`로 규정 질문·사진으로 묻기·학사 일정·캠퍼스 안내를 쓴다.
  졸업 체크·비교과 추천은 로그인 화면으로 안내하며 상단에는 `로그인` 버튼을 둔다.
- **나가기와 복원** — 로그아웃은 입력값·선택한 학생·저장 ID·졸업 결과를 지운다. 일반 질문은 남긴다.
  새로고침하면 기존 학생 목록으로 ID를 확인한다. 사라진 ID는 지우고 일시적인 조회 실패에는 남긴다.
  재제출·로그아웃·둘러보기 이후 늦은 응답과 축하 콜백은 학생이나 화면을 되살리지 못한다.
- **배치** — 메인 질문 입력창을 기능 카드보다 위에 둔다. 입력창은 밝은 판 위 경계에 걸치고 카드 여섯 개는
  3열, 880px 이하는 2열이다. 로고는 로그인 카드와 넓은 상단에서 30px, 680px 이하에서 22px이다.
- **색과 대비** — 색은 라이트·다크 두 벌이다(아래 「밝은 색과 다크 모드」). 로그인 카드와 상단 띠는
  테마 색의 유리이고 흐림은 최대 1.5px이다. 메인 판은 위쪽 56px 뒤부터 반투명 면으로 이어진다.
  질문 입력 줄은 불투명 면이다. 색은 반투명 색까지 `:root`와 두 다크 블록의 변수로 모은다.
  어두운 사진 #041426과 흰 사진 양쪽에 섞어 네 테마 상태에서 글자 4.5:1, 테두리와 초점 3:1을 검사한다.
  밝은 학교 로고는 흰 글자라 라이트에서는 그림에 남색 받침을 깔고, 다크에서는 받침 없이 올린다.
  로그인·상단 띠 흐림은 1.5px이며 메인 판 자체는 흐리지 않는다.

## 유리 화면의 배치와 대비 보완

961~1463px에서는 테크모 판과 버튼이 128px이며 본문 양쪽에 각각 152px를 확보한다.
1464px 이상에서는 판과 버튼이 168px이고 한쪽 예약 폭은 192px다.
테크모 판 오른쪽은 화면에서 24px 떨어진다. 기본 자리 말풍선의 최대 폭은 예약 폭에서 16px를 뺀
136px·176px이며 머리 가운데에 맞춘 뒤 예약 영역 안으로 민다. 본문 오른쪽 끝과 화면 오른쪽 가장자리에서
각각 8px 이상 떨어지게 두고, 꼬리는 머리를 계속 가리킨다.

| 화면 폭 | 한쪽 예약 | 판·버튼 | 홈 본문 | 채팅 대화 열 |
|---:|---:|---:|---:|---:|
| 961 | 152 | 128 | 657 | 373 |
| 1280 | 152 | 128 | 976 | 692 |
| 1384 | 152 | 128 | 1080 | 760 |
| 1463 | 152 | 128 | 1080 | 760 |
| 1464 | 192 | 168 | 1080 | 760 |
| 2000 | 192 | 168 | 1080 | 760 |

표는 CSS 수식으로 계산했다. 브라우저 실제 치수와 바닥글 겹침은 통합 후 확인한다.

예시 질문은 입력창 안내문 바로 아래에 놓을 알약 줄로 꾸민다. `.topics`의 순서 지정과 위 여백을 없애고
가로로 흐르다 줄바꿈하게 한다. 이름표 `.topics-label`이 별도 안내 한 줄을 대신한다.
알약은 `--glass-dense` 바탕, `--ink` 글자, `--content-line` 테두리를 쓴다.
680px 이하에서도 줄바꿈하며 긴 알약의 최대 너비와 글자 줄바꿈으로 가로 넘침을 막는다.
1280px과 680px 이하의 최종 선언은 자동 검사로 확인하며 브라우저 가로 넘침 실측은 미확인이다.

알약 테두리 `--content-line`(라이트 `rgba(10,37,64,.16)`, 다크 `rgba(140,220,255,.28)`)은 약 2:1인 내용 구분선이다.
요청한 색을 적용해 버튼 경계의 3:1 검사에서 제외하고 알약·이름표 글자 4.5:1과 키보드 초점 3:1을 검사한다.
알약 높이는 요청에 따라 32px 안팎으로 두며 다른 버튼의 최소 44px 기준에 대한 예외로 기록한다.

학사 일정 제목은 `#panel-calendar [data-panel-content] > h5`만 골라 16px·굵기 700·`--ink`·여백 0을 쓴다.
같은 내용 칸의 `.evidence` 위 여백도 0으로 맞춰 제목 아래와 일정 상자 사이에 기존 격자 간격 12px만 남긴다.
캠퍼스 안내 제목과 답변의 근거 상자는 이 선택자 밖에 있다.

밝은 판은 `.composer-row`에만 두고 바깥 `.composer`는 투명하게 만든다.
클립 버튼은 44px 누름 영역과 22px 선 아이콘 규칙을 제공한다. 첨부 상태·제거·안내문은 진한 보강 면인
`.composer-meta`에 놓는다. 안내문은 보조 글자색(`--muted`)이며 한 문단을 쓸 자리를 둔다.

근거·추천·사진 결과·보류 상자 경계, 졸업 표 칸 선, 추천 목록과 예시 질문의 내용 구분선은
`--content-line`으로 분리했고 3:1 검사에서 제외한다. 이 선은 내용을 나누는 보조 표시이며 제목·표 머리글·항목 글자와
여백으로도 구분한다. 예시 질문 알약을 제외한 버튼·입력창·판의 경계와 키보드 초점은 3:1 검사를 유지한다.
색 값과 대비 결과는 아래 「밝은 색과 다크 모드」에 모았다.

## 밝은 색과 다크 모드(#131)

2026-11-18 팀원 피드백(화면이 어둡다)에 따라 라이트를 기본으로 바꾸고 다크를 따로 두었다.

- **조건** — `html`의 `data-theme`이 `dark`이거나, 속성이 없으면서 시스템 설정이 다크(`prefers-color-scheme: dark`)일 때 다크다.
  `data-theme="light"`는 시스템이 다크여도 라이트다. 속성은 `chat.js`가 적는다(선택값 `data-theme-mode`는 시스템·라이트·다크).
  CSS는 속성이 없을 때도 시스템을 따르므로 스크립트가 늦거나 실패해도 다크 사용자의 첫 화면이 밝게 번쩍이지 않는다.
- **블록** — 라이트 값은 `:root`, 다크 값은 `:root[data-theme="dark"]`와 `@media (prefers-color-scheme: dark)` 안
  `:root:not([data-theme])` 두 블록에 같은 선언으로 적는다. 두 블록이 같은지는 `landing_design.test.mjs`가 비교한다.
  `color-scheme`도 라이트 `light`, 다크 `dark`로 맞춘다. 테크모 말풍선의 다크 크림 `#F3E7BF`도 이 두 블록이 넣는다.
- **이름표** — 역할 변수(`--ink`, `--muted`, `--link-ink`, `--good` 등)는 아래 이름표를 가리킨다.

| 이름표 | 라이트 | 다크 |
|---|---|---|
| 바탕 `--bg` | #F5F8FC | #0B1626 |
| 면 `--surface` / 올린 면 `--raised` | #FFFFFF / #FFFFFF | #13233A / #1A2B44 |
| 글자 `--text` / 보조 `--text-muted` | #0A2540 / #4A5D75 | #E8EEF6 / #9DB0C7 |
| 강조 `--accent` | #005B96 | #3DB8E8 |
| 글자용 하늘 `--sky-text`(링크) | #0071A4 | #3DB8E8 |
| 노랑 `--yellow` / 코랄 `--coral` | #FFD100 / #FF7A59 | #FFD100 / #FF8F73 |
| 충족 / 확인 필요 / 부족 | #0F7A43 / #9A5B00 / #C62F2F | #4ADE80 / #FBBF24 / #F87171 |

- **채움 전용** — 하늘색 `#00A3D9`(`--sky`)는 흰색과 약 2.9:1이라 도형·그라데이션 채움에만 쓰고 글자·테두리·초점에는 쓰지 않는다.
  노랑 채움에는 남색 글자를 얹는다(준비 중 표시, 안전 문구 느낌표). 노란 글자는 불투명 남색 면 위 준비 중 표시에만 쓴다. 사진 위 대체 제목의 강조 글자(`아이오`)는 흰 글자에 노란 굵은 밑줄이다.
  노란 글자는 흰 사진 위 막과 약 2.2:1이라 큰 글자 기준 3:1에도 못 미친다.
  대체 제목(로그인 `.title-fallback`, 홈 `.main-title-fallback`)은 화면 높이 25% 안팎에 놓인다. 그 자리의 막은 약 .30까지 옅어져
  흰 글자도 흰 사진 위에서 약 1.9:1이라, 소개 글과 같은 남색 .62 받침을 깔았다(막 없이 약 4.5:1).
  코랄은 읽지 않은 답변 점에 쓴다(라이트는 남색 테두리 포함).
- **반투명 면** — 라이트는 흰 면이다. 큰 면 .70 사이로 사진이 비치고 말풍선·카드(.80)를 겹친 합성 불투명도는 .94다.
  다크는 바탕색 면이다. 큰 면 .50에 말풍선 .76을 겹치면 .88이다. 다크 말풍선은 예전 .66보다 진하다.
  부족 글자 `#F87171`이 흰 사진 가정에서 4.5:1을 넘으려면 이 값이 필요하다.
  안쪽 상자 덧판은 라이트 흰색 .55, 다크 .30이다. 라이트에서 남색을 덧칠하면 링크 글자가 4.5:1 아래로 내려가서다.
  다크 로그인 카드의 학번 입력 안내 글자는 보조 글자 `#9DB0C7`보다 밝은 `#B8C7D8`이다. 입력칸 면 위에서 보조 글자는 4.5:1에 못 미친다.
  흐림 미지원 브라우저에서는 큰 판이 불투명 바탕(`--panel-surface`, 테마의 `--bg`)이 되고 글이 놓이는 면은 진한 면(`--glass-dense`)이 된다.
- **사진 위** — 사진 위 막은 위쪽을 남색(라이트 .50, 다크 .62)으로 두어 흰 제목 그림과 소개·인사말 흰 글자를 받친다.
  라이트의 아래쪽은 옅은 바탕색 막이라 밝은 판 주변의 사진이 밝게 보인다. 제목 그림은 테마별 그림자
  (`drop-shadow(0 2px 12px var(--lettering-shadow))`)를 받침으로 깐다. 사진 위 알약(언어 버튼·소개 배지)은 두 테마 모두 남색 .62에 흰 글자다.
- **음각·양각** — 불투명 입력 줄 안에서만 쓴다. 질문 칸은 오목(`--deboss`), 답변 모드 버튼은 볼록(`--emboss`)이고
  메뉴가 열린 동안은 오목으로 바뀐다. 경계는 `#6E8098`이다. 그림자 수치는 피드백 값 그대로다.
  사진 위 반투명 패널에는 쓰지 않는다. 지능 피커 세그먼트와 달력 「오늘」 버튼은 아직 없어 이번에 만들지 않았다.
- **상태와 초점** — 초점은 어디서나 2px 실선 고리다. 라이트는 남색, 다크는 흰색이라 반투명 판 위에서도 3:1을 넘는다.
  예외는 배경 일시정지 버튼(흰 고리와 남색 띠)과 메뉴 항목(안쪽 고리)이다. 고른 메뉴 항목은 바탕색·테두리·체크 표시·
  `aria-checked`로, 열린 모드 버튼은 테두리 색·오목 그림자·`aria-expanded`로 알린다.
- **조작 영역** — 퀵링크 ‹ › 버튼(38·32px), 대화 메뉴 버튼(가로 36px), 좁은 화면 머리글 버튼(40px)을 44px로 키웠다.
  채팅 머리글의 대화 목록·홈 버튼은 가로도 44px 이상이고, 깊이 생각의 요약 토글은 한 줄이어도 높이 44px다.
- **깊이 모드 경계** — 세 색 고리는 흰 면과 약 1.6~2.9:1인 장식이다. 닫힌 동안은 고리 바로 안쪽 1px `#6E8098` 선이 3:1 경계이고,
  메뉴가 열린 동안은 고리 대신 `--focus-ink` 테두리와 오목 그림자를 쓴다.
- **사진 위 소개 글** — 로그인 소개 문구(`.intro-description`)와 홈 인사말(`#main-greeting`)은 본문 크기라 막만으로는
  흰 사진 가정에서 약 2.9:1이다. 남색 .62 받침 위 불투명 흰 글자로 바꿔 막 없이 계산해도 약 4.5:1을 넘긴다.
  대체 제목(h1·h2)도 같은 받침을 쓴다(아래 노랑 항목). 실제 사진 네 장 위 모습은 브라우저에서 다시 봐야 한다.
- **로그인 설정 묶음** — 언어·테마 버튼을 `.login-lang` 묶음에 담으면 묶음 자체에는 바탕·hover가 없다. 안의 두 알약이 각자
  남색 .62 면과 흰 글자를 쓰고 hover는 불투명 남색이다. 묶음에 hover 바탕을 주면 라이트에서 남색 바탕 위 남색 글자(1:1)가 된다.
  두 버튼은 판 없이 사진 위에 있어 라이트 남색 초점 고리가 어두운 사진·위쪽 막 위에서 약 1.1:1로 묻힌다.
  그래서 배경 일시정지 버튼처럼 흰 2px 고리 뒤에 남색 6px 띠를 깔아 테마·사진과 상관없이 3:1을 넘긴다.
  끌어 옮긴 테크모 버튼(`.pet`)도 판 없이 사진 위에 놓일 수 있어 같은 초점 표시를 쓴다.
  두 버튼의 테두리는 불투명 흰색이다. 예전 흰색 .28 테두리는 흰 사진 위에서 약 1.3~2.1:1이었다. 지금은 어두운 사진에서는 흰 선이,
  흰 사진에서는 남색 .62 면(약 4.5:1)이 3:1 경계가 된다.
- **좁은 채팅 머리글** — 680px 이하 채팅 화면에서는 로고 그림을 감춘다. 머리글 한 줄에 대화 목록·홈 버튼과
  언어·테마 알약을 두면 로고 자리(약 140px)가 모자라 설정 버튼이 홈 버튼 쪽으로 밀리기 때문이다. 480px 기준으로는 481px 화면에서
  영어 버튼 이름일 때 약 500px가 필요해 457px 머리글을 넘었다. 681px 이상은 머리글이 657px 이상이라 함께 들어간다. 로고를 받지 못했을 때 대신 보이는
  학교 이름 글자도 같은 화면에서는 화면 낭독기용으로만 남긴다.
- **480px 이하 머리글** — 320px 로그인 채팅 머리글은 대화 목록·홈 버튼을 빼면 약 196px라 언어·테마·로그아웃 버튼이 한 줄에 서기 빠듯하다.
  언어 버튼은 현재 언어 이름(#116)을 남기고 지구본만 뺀다. 테마 버튼은 아이콘과 꺾쇠만 보이고 이름은 낭독기용으로 둔다(버튼 이름이 현재 값을 읽는다).
  오른쪽 버튼 묶음과 로그인 상자는 버튼들의 최소 폭(`min-content`) 아래로 줄지 않고 학생 이름만 말줄임으로 줄어든다.
  로고는 남은 폭에 맞춰 비율을 지킨 채 줄어든다. 라이트 로고 그림은 받침 좌우 여백 9px(`--logo-pad-x`)가 폭 밖에 더해지는
  content-box라, 최대 폭을 `calc(100% - 2 * var(--logo-pad-x))`로 잡아 여백까지 로고 칸 안에 가둔다.
  로고 칸(`.brand`) 자체는 넘침을 잘라 내고, 그 안의 두 갈래(로고 그림, 로고를 받지 못했을 때 보이는 학교 이름 글자)는 모두
  `min-width: 0; max-width: 100%`라 칸보다 넓어지지 않는다. 이름 글자는 자르지 않고 칸 안에서 줄을 바꾼다
  (0.8rem 세 줄이 약 46px라 72px 머리글 안에 든다). 말줄임은 학생 이름·대화 제목에만 쓴다는 기존 약속을 따른다.

  투명 띠가 있으면 초점 고리가 사진 위에 놓이기 때문이다. 대비 계산 도구는 그라데이션 안의 `transparent`를 색으로 세지 않으므로,
  검사는 이 선언에 `transparent`가 없는지를 글자로 확인한다.
- **출처 링크** — 답 아래 따로 놓이는 `공식 원문 보기` 같은 출처 링크(`.source-link`)는 높이·너비 모두 44px 이상인 누름 영역이다.
  제목이 한 글자인 출처도 한 글자 폭만 누르게 되지 않는다.
- **다시 연 대화** — 저장한 대화를 열면 출처 링크와 작성자 이름(`.reply-author`)이 말풍선 밖, 대화 칸(`.turn`) 바로 아래에 붙는다.
  그 자리는 큰 면 한 장뿐이라 라이트·어두운 사진 가정에서 링크가 약 2.7:1이었다. 지금은 말풍선과 같은 보강 면을 깐다.

  흰 2px 고리(안쪽 2~4px)라 띠에 걸려도 3:1을 넘는다.
  실제 줄바꿈 여부는 통합 브랜치 브라우저에서 다시 재야 한다.
- **사진 위 이름** — 961px 이상 화면 아래쪽 사진 이름·진행 칸(`.campus-caption-text`)은 남색 .62 받침 위 흰 글자다.

## 캠퍼스 사진 배경

로그인과 메인은 고정된 전체 화면 배경을 함께 쓴다. 학교 사진은 저장소에 넣지 않으며 사진이 없어도
남색 바탕에서 로그인과 기능을 계속 쓴다. 사진 이름은 양호동 캠퍼스 → 디지털관과 금오산 자락 → 정문의 밤 →
대운동장의 저녁 순서다. 파일 이름은 `campus-aerial.jpg`, `campus-hill.jpg`, `campus-gate.jpg`,
`campus-field.jpg`이며 `/chat-assets/`에서 읽는다.

- **사진과 물결** — 멈춘 CSS 배경을 먼저 보여 주고 브라우저 그래픽 기능(WebGL)이 준비되면 캔버스를 보인다.
  사진은 24초 머물고 6초 겹쳐 넘어간다(#128, 예전 9초·3.2초). 겹침 비율은 기존 ease-in-out 곡선(smoothstep)을 쓴다.
  물결의 변위·명암 계수와 잔잔한 흔들림(still)은 예전 값의 절반 이하로 낮췄다. 포인터가 70ms 이상 간격으로 26px 이상 움직이거나 누를 때
  물방울을 넣고 최근 16개를 그린다. 처음 0.3·0.9·1.5초에 자동 물방울 세 개를 넣는다.
  물방울은 1.8초 동안 포인터 근처에서만 작게 일렁인다. 패널 자체를 흔들지 않고 배경 캔버스만 굴절한다.
  포인터는 `window`에서 먼저 받는 단계로 듣고 입력란의 전파 중단에도 반응한다.
  위치는 화면 기준 `x = clientX / innerWidth`, `y = 1 - clientY / innerHeight`로 넘긴다.
- **사진 흐름** — 한 사진은 나타나기 시작해 사라질 때까지 36초(전환 6초 + 노출 24초 + 전환 6초) 동안 같은 방향으로 흐른다.
  확대율은 사진 순번에 따라 1.00→1.05와 1.05→1.00을 번갈아 아주 느리게 바뀌고, 교차 전환 앞뒤로 같은 사진의 확대율이 이어진다.
  교체 직전 다음 사진 위치와 교체 직후 현재 사진 위치를 같은 식으로 계산한다. 방향은 누적 순서의
  홀짝으로 정하며 사진 이름·진행 칸은 합성 비율이 0.5를 넘을 때 다음 사진으로 바꾼다.
  다음 그림이 준비되지 않은 첫 주기는 현재 그림을 유지하고, 그다음 주기부터 받은 사진끼리 순환한다.
  한 장뿐이면 부드럽게 왕복하며 계속 흐르고, 늦은 사진이 합류할 때도 현재 위치를 이어 간다.
- **시계** — 사진 교체와 물방울은 그리기 반복의 시각만 쓴다. 탭이 가려지면 멈추고 가려진 시간은 빼고 잇는다.
  움직임 줄이기에서는 사진 흐름·물결·물방울을 모두 끄고 사진 한 장만 남긴다.
- **캡션과 일시정지(#128, WCAG 2.2.2)** — 캡션(`#campus-caption`)은 낭독기에서 숨긴 배경 묶음(`.campus-backdrop`)
  밖, 그 바로 뒤에 있는 고정 줄이다. 사진 이름·진행 칸은 `aria-hidden`이고 낭독기는 캡션 안 버튼
  `button#campus-motion-toggle`만 읽는다. 버튼 이름은 「배경 움직임 일시정지」로 고정하고, 멈춘 상태는
  `aria-pressed="true"`로 알린다. 아이콘만 그 값에 따라 일시정지(❚❚) ↔ 재생(▶)으로 바뀐다.
  캡션은 고정 문구 번역에서 건너뛰는 자리(`staticSkip`)라 버튼 이름의 영어·중국어는 `chat.js`가 `t()`로 넣는다.
  - 저장 — 선택은 기기 저장소의 `kumoh-campus-motion:v1`에 남긴다. 값이 `paused`일 때만 멈춘 상태로 읽고,
    저장이 실패해도 지금 화면에서는 멈춤·재생이 된다.
  - 멈춤 — 화면 갱신 예약과 물결 입력을 멈추고 마지막 장면과 캡션은 그대로 둔다. 재개하면 멈춘 시간을 빼고 잇는다.
    저장된 정지 상태로 열면 첫 장면에서 멈춘다. 멈춘 사이 탭 복귀나 늦게 온 사진이 재생을 다시 켜지 않는다.
    창 크기가 바뀌면 시간은 흐르지 않은 채 한 장면만 다시 그린다. WebGL 그림판은 크기가 바뀌면 지워지기 때문이다.
  - 보이는 때 — 캡션과 버튼은 배경이 실제로 움직일 때만 보인다. 움직임 줄이기나 그래픽 기능 실패로 정지 배경이면 함께 숨긴다.
  - 모양 — 44×44px 원형, 불투명 남색 바탕(`--navy`)에 흰 1.5px 선이라 밝은 사진에서는 남색 면이, 어두운 사진에서는
    흰 선이 경계가 된다. 초점은 흰 2px 실선 고리이고 그 뒤에 남색 6px 띠를 깔아 어느 사진 위에서도 3:1을 넘는다.
    사진 이름·진행 칸은 누름을 통과시키고(`pointer-events: none`) 버튼만 누름을 받는다. 겹침 순서(z-index 21)는
    옮겨 놓은 테크모(20) 위라, 테크모를 버튼 자리에 놓고 새로고침해도 버튼을 누를 수 있다. 대화 메뉴(30)·확인 창(40)보다는 아래다.
  - 감추는 때 — 대화 목록 서랍(`data-conversation-drawer="open"`)이 열려 있거나 답변 도착 알림(`#conversation-toast`)이
    떠 있는 동안에는 `visibility: hidden`으로 캡션을 감춘다. 이 값은 키보드 초점과 낭독기에서도 버튼을 빼므로,
    서랍 가림막 뒤의 버튼으로 초점이 새지 않는다. 알림은 960px 이하에서 버튼과 같은 오른쪽 위 자리에 뜬다.
  - 자리 — 961px 이상 첫 화면·로그인은 예전처럼 왼쪽 아래(왼쪽 28px, 아래 22px)에 이름·진행 칸과 버튼을 함께 둔다.
    채팅 화면은 왼쪽 아래가 대화 목록, 오른쪽 아래가 테크모·입력창이라 버튼만 머리글 바로 아래 오른쪽
    (`top: calc(var(--chat-header-height) + 12px)`, 오른쪽 12px)에 둔다. 넓은 화면에서 이 자리는 테크모 몫으로 비워 둔
    오른쪽 여백의 위쪽 끝이다. 960px 이하(390px 포함)는 화면 아래쪽 전체가 펫 줄이고 채팅 화면은 그 바로 위가 입력창이라,
    모든 화면에서 버튼만 같은 머리글 아래 오른쪽 자리에 둔다. 로그인 화면에서는 오른쪽 위 언어 알약 바로 아래다.
    기본 자리 기준으로 입력창·테크모와 겹치지 않는다. 테크모를 끌어 이 자리로 옮기면 버튼이 테크모 위에 남는다.
- **사진 일부 실패** — 내려받거나 풀지 못한 사진은 그 사진만 건너뛴다. 받은 사진이 한 장이면
  그 사진의 흐름과 물결을 유지하고, 두 장 이상이면 받은 사진들끼리 순서대로 넘어간다.
  이름과 진행 칸도 받은 사진 수에 맞추고, 받기 전에는 빈 이름과 진행 칸을 숨긴다.
- **실패 대체** — 캔버스·그래픽 기능·셰이더가 실패하거나 사진을 한 장도 받지 못하면 멈춘 배경으로 돌아간다.
  사진은 `fetch`·`createImageBitmap`으로 받고 1920×280인지 확인한 뒤 그린다. 다른 크기는 그 사진만 제외한다.
  텍스처 가장자리를 고정하며 선형 보간만 쓴다. 화면 배율은
  1.5까지만 반영한다. 외부 라이브러리, 문서 안 실행 코드·스타일, style 속성은 추가하지 않는다.
  테크모의 위치와 그림 칸 배치만 `style.setProperty("--techmo-…", 값)`과
  `style.removeProperty("--techmo-…")`로 바꾼다. 화면 보안 정책(CSP)은 문서 안 스타일을 막지만,
  스크립트의 style 객체를 통한 개별 속성 변경은 허용하므로 이 방식으로 좌표를 전달한다.
  `cssText`, `setAttribute("style", …)`, 다른 style 속성 대입은 쓰지 않는다.
- **가독성** — 사진 위 위쪽 남색 그러데이션과 `0 2px 18px var(--shadow-text)` 글자 그림자를 쓴다. 그림자 색은 라이트
  `rgba(4,20,38,.55)`, 다크 `rgba(0,0,0,.65)`다. 사진 위 흰 글자는 자동 대비 계산 대신 실제 사진 네 장을 브라우저에서 보고 확인해야 한다.
- **브라우저 확인** — 1280×800에서 카드 위·아래, 390×844에서 상단 띠 100px 이하와
  질문 입력창의 첫 화면 노출을 잰다. 가로 넘침 없음·로고 20px 이상·버튼 44px 이상도 확인한다.
  실제 실행 결과와 확인하지 못한 항목은 아래 검증 기록에 구분해 남긴다.

## 세 가지 메시지 상태

동일한 말풍선 컴포넌트로 처리하지 않는다. 상태마다 의미가 다르다.

### 1. 근거 기반 답변 (`answered: true`)
답변 + 인용 카드. 인용은 접지 않고 항상 펼쳐둔다.

### 2. 답변 불가 (`answered: false`)
```
┌─────────────────────────────────────┐
│ 보유한 규정 문서에서 확인할 수 없는   │
│ 내용입니다.                          │
│                                     │
│ 학사지원팀 054-478-XXXX  [전화 걸기] │
└─────────────────────────────────────┘
```
**빨간 에러 스타일을 쓰지 않는다.** 정상 동작이다.
근거 없이 답을 지어내지 않는 게 이 시스템의 설계 의도이므로, UI가 그걸 실패로 보이게 하면 안 된다.

### 3. 시스템 오류 (HTTP 5xx)
이때만 에러 스타일. 재시도 버튼 제공.

## 인용 카드

```
📄 학사운영규정 제30조(전과) ①
   시행일 2025-03-01
   "전과는 2학년 이상인 학생으로서..."
   공식 원문 보기
```

- **시행일을 반드시 표시한다.** 학칙은 개정되고, 학번에 따라 적용 기준이 다르다.
  시행일이 없으면 학생이 자기에게 해당되는 조문인지 판단할 수 없다.
- 스니펫은 2줄까지, 클릭하면 전체 펼침.

### 공식 원문 보기 링크

서버가 인용마다 주는 주소(`source_url`)가 안전한 HTTPS일 때만 카드에 링크를 붙인다.
문 앞에서 신분증을 한 번 더 보는 것과 같다. 서버가 시작할 때 주소를 검사하지만,
화면도 받은 값을 그대로 믿지 않고 같은 규칙으로 다시 본다.

- **보이는 글자** — `공식 원문 보기`. 화면 낭독기만 읽는 숨김 글자로 문서명·조문과
  새 탭으로 열린다는 안내를 덧붙인다. 카드가 여러 개여도 링크를 구분할 수 있다.
- **새 탭** — `target="_blank"`와 `rel="noopener noreferrer"`로 연다. 대화 내용은 페이지
  메모리에만 있어, 같은 탭으로 열면 학생이 읽던 대화를 잃는다.
- **붙이는 조건** — 아래를 모두 만족해야 한다. 서버의 주소 검사와 같은 규칙이다.
  - 값이 문자열이고 공백·제어 문자가 없다.
  - 입력 글자가 `https://`로 시작한다. 대소문자는 가리지 않아 `HTTPS://example.invalid/`도
    받는다.
  - 호스트(주소에서 서버 이름 부분)가 비어 있지 않고, 점으로만 이루어지지 않았으며,
    그 자리에 `@`와 역슬래시가 없다. `https://./`는 호스트가 점뿐이라 받지 않는다.
  - 브라우저의 주소 읽기 기능(`URL`)으로 읽은 결과가 `https:`이고 아이디·비밀번호가 없다.
- **숨기는 경우** — `null`, 필드 없음, 빈 문자열, `javascript:`·`data:`·`http://`, 상대 경로,
  `//`로 시작하는 주소, `https:example.invalid`, 호스트가 비었거나 점뿐인 주소,
  아이디·비밀번호가 든 주소, 공백이나 탭이 든 주소, 문자열이 아닌 값. 이때 카드는 링크가
  없던 때와 같은 요소만 가진다. 빈 자리나 비활성 버튼을 남기지 않는다.
- **주소는 고치지 않는다** — 통과한 주소는 입력 글자 그대로 `href`에 넣는다.
- **내용 보존** — 링크가 있든 없든 문서명·조문 경로·시행일·인용문은 서버 응답과 같다.
- **가상 데모** — 배포 데모의 인용은 `source_url`이 `null`이라 링크가 없다. 링크는 가상
  목록으로 로컬에서 확인한다. 절차는 `api/docs/RENDER_DEPLOY.md`에 있다.

## 졸업 체크 아래 BISKIT 추천 카드

졸업 체크 응답에 교내 비교과 시스템(BISKIT) 추천(`biskit_recommendations`)이 들어 있으면
졸업 표와 가상 데이터 안내 문구 아래, 같은 답변 안에 추천 영역을 그린다. 요청은 졸업 체크 한 번뿐이다.

```text
내 BISKIT 480/500점 · 20점 부족
목록 확인 2026년 11월 13일 · 접수 상태와 정원은 공식 페이지에서 확인

┌ 2026학년도 제2차 학습법 특강
│ 학부 재학생 · 신청 11월 26일까지
│ 마일리지 30점                          ← 공개(published) 점수일 때만
│ 공식 공지 보기   BISKIT 로그인 후 프로그램명으로 검색
└
BISKIT 열기
```

추천은 식당 메뉴판과 같다. 서버가 오늘 주문할 수 있는 것만 골라 적고, 화면은 적힌 대로 보여 준다.
화면은 프로그램을 고르거나 줄 세우지 않고, 점수를 더하지도 않는다.

- **제목 줄(#128)** — `내 BISKIT 480/500점 · 20점 부족`. 졸업 체크 응답 `items`의 `extracurricular` 아래
  `mileage` 행에서 `current`와 `required`를 읽는다. 두 값이 모두 「정수+점」 형식(`480점`)이고 그 차이가
  `shortfall_points`와 같을 때만 이 제목을 쓴다. 조건이 하나라도 어긋나면 예전 제목 `BISKIT 추천 · N점 부족`을 쓴다.
  N은 서버가 준 정수(`shortfall_points`)이고 표의 부족 글자를 다시 읽지 않는다. 학생의 BISKIT 점수는
  BISKIT에 로그인해야 볼 수 있어 화면이 따로 얻을 수 없으므로, 졸업 체크 응답의 값만 쓰고 지어내지 않는다.
- **목록 확인일** — `listed_on`을 `2026년 11월 13일` 꼴로 적고 접수 상태와 정원은 공식
  페이지에서 확인하라고 덧붙인다. 확인일이 없으면 뒤 문구만 적는다.
- **대상·날짜 줄** — `대상 · 신청 11월 26일까지 · 행사 2026년 11월 23일`. 행사일은 연도를
  함께 적는다. 제목의 연도와 행사 연도가 다른 공지가 있어서다. 날짜가 `2026-11-26` 꼴이
  아니면 받은 글자를 그대로 보여 주고, 마감일이 없으면 `신청 마감 확인 필요`라고 적는다.
- **확인 필요 표시** — `eligibility`가 `eligible`이 아니면 `대상 확인 필요`,
  `deadline_status`가 `open`이 아니면 `마감 시각 확인 필요`를 졸업 표의 확인 필요와 같은
  노란 표시로 붙인다. 모르는 값도 확인 필요로 본다.
- **점수 문구(#128)**
  - `mileage_status`가 `published`이고 점수가 1 이상 정수 — `마일리지 N점`
  - `announced`, `undisclosed`, 모르는 값, 점수가 빠지거나 잘못된 `published` — 마일리지 줄을 아예 만들지 않는다.
    얻을 수 없는 값은 빈 자리나 「미공개」 글자로도 표시하지 않는다.
  - 부족 점수를 채운다거나 졸업 요건을 충족한다고 약속하는 문구는 쓰지 않는다.
- **링크** — 인용 카드와 같은 안전 주소 검사를 통과한 주소만 새 탭 링크로 만든다. 학교
  주소인지는 서버가 판정한다.
  - `notice_url` — `공식 공지 보기`. 주소가 없거나 위험하면 링크 대신 `공식 공지 확인 필요`.
  - `application_url` — `신청 페이지 열기`. 주소는 받은 그대로 쓴다. `login_required`가
    참이면 링크 옆에 `BISKIT 로그인 필요`를 눈에 보이는 글자로 적는다. 로그인 화면을 거치는
    주소여도 학생이 누르기 전에 알 수 있다.
  - 신청 주소가 없고 `login_required`가 참이면 `BISKIT 로그인 후 프로그램명으로 검색`.
  - `portal_url` — 영역 맨 아래 `BISKIT 열기`. 안전하지 않으면 링크를 숨긴다.
- **빈 목록** — `지금 신청할 수 있는 프로그램을 확인하지 못했어요`와 `BISKIT 열기` 링크.
- **추천 영역을 그리지 않는 경우** — 항목이 없거나 `null`일 때, 부족 점수가 1 이상 정수가
  아닐 때, `programs`가 배열이 아닐 때, 프로그램이 객체가 아니거나 제목이 비지 않은 글자가 아닐 때(숫자 제목 포함),
  `login_required`가 참·거짓 값이 아닐 때(`"true"` 같은 글자, 숫자, `null`, 누락). 이때도
  졸업 표는 그대로 나오고 오류 문구를 띄우지 않는다.
- **지우기** — 추천 영역은 졸업 체크 답변 안에 있어, 버튼을 다시 누르면 새 결과로 바뀌고
  `새 대화`를 누르면 표와 함께 사라진다.

## 채팅 입력창의 사진 첨부

별도의 `현수막으로 행사 찾기` 칸은 없앴다. 질문 입력창 아래 `사진 첨부`에서 사진 한 장을
고르고 `보내기`를 누른다. 사진만 보내도 되고 질문과 함께 보내도 된다. 화면은 택배 접수
창구와 같다. 상자 크기와 종류만 보고 받아 넘기고, 안에 든 것이 행사인지 규정 질문인지
장소 질문인지는 서버가 판정한다.

### 요청 순서

1. **사진 주소** — 사진이 붙어 있으면 `POST /api/v1/photo-input`에 사진 바이트를 한 번 보낸다.
   응답은 기존 행사 필드에 사진에서 읽은 글자(`recognized_text`, 아래에서는 판독문)가 더해진 모양이다.
2. **행사 확인** — `event_match`가 `confirmed`면 아래 행사 카드를 그리고 요청을 끝낸다.
   질문을 함께 보냈더라도 글자 주소를 부르지 않고, 질문은 편집 칸에 남긴다.
3. **글자 주소** — 행사가 확인되지 않았으면 사진 없이 `POST /api/v1/photo-question`에
   `question`, `recognized_text`, `session_id`만 보낸다. 사진만 보냈으면 `question`은 빈 글자이고
   판독문이 질문 노릇을 한다.
4. **보내지 않는 경우** — 질문과 판독문이 모두 비었거나 판독문이 2,000자를 넘으면 글자 주소를
   부르지 않고 노란 확인 필요 카드와 편집 칸만 보여 준다.

질문만 보내면 전과 같이 `POST /api/v1/chat`으로만 간다.

### 글자 주소의 응답 표시

`kind` 값에 따라 그린다. 모르는 값이거나 필요한 필드가 빠졌으면 서버 오류 문구를 보여 준다.

- `event` — `event` 필드로 사진 주소와 같은 행사 카드를 그린다. 응답에 `reasons`와
  `identified_by`가 있으면 마감 차이 안내와 확인 단서 줄에 쓴다.
- `regulation`, `campus` — 제목(`규정 검색`, `캠퍼스 안내`), 답변 글, 출처 목록. 출처는
  `sources`의 `title`과 `url`만 쓴다. 안전 주소 검사(`sourceLink`)를 통과한 주소만 링크가 되고,
  통과하지 못하면 `제목 · 링크 확인 필요`를 글자로 적는다.
- `hold` — 노란 확인 필요 카드. 서버가 출처나 행사를 함께 보냈더라도 그리지 않는다.
  `hold_reason`이 화면이 아는 사유 이름(`no_readable_clue` 등)이면 그 문구를, 아니면 일반
  보류 문구를 적는다. 받은 값을 그대로 화면에 적지는 않는다. 빨간 오류 스타일은 쓰지 않는다.

### 읽은 글자 고쳐 다시 묻기

사진 답변 아래에 편집 칸을 붙인다.

```text
사진에서 읽은 글자
읽은 글자     [ 가상관 101호            ]
함께 물을 질문 [ 여기 어디야?            ]
[고쳐서 다시 묻기]
```

- **일반 글자** — 판독문은 입력 칸의 값으로만 넣는다. 주소처럼 생긴 글자가 들어 있어도 링크가
  되지 않고, 화면이 그 주소를 열지도 않는다. 링크는 서버가 응답에 실어 준 출처로만 만든다.
- **다시 묻기** — `고쳐서 다시 묻기`는 두 칸의 글자만 글자 주소로 보낸다. 사진은 다시 보내지
  않는다. 새 답은 같은 대화 칸의 답변 자리를 바꿔 그린다.
- **2,000자 한도** — 서버처럼 글자 수로 센다. 넘으면 요청을 보내지 않고 편집 칸 아래에 줄여
  달라고 적는다. 두 칸이 모두 비어도 보내지 않는다.
- **글자 질의 실패** — 통신 실패나 서버 오류면 `다시 시도`가 같은 글자만 다시 보낸다. 사진은
  이미 읽었으므로 다시 올리지 않는다. 서버가 글자를 거절(422)하면 `다시 시도` 없이 고쳐
  달라고 안내한다.
- **읽지 못한 까닭** — 사진 주소가 `text_reader_unavailable` 같은 사유를 보냈는데 질문이 있어
  글자 주소로 넘어간 경우, 그 사유 문구를 편집 칸 위쪽에 적는다.

### 행사 카드

```text
가상 해외 취업 설명회
확인 단서 · 사진 글자
행사일 2026년 11월 23일
공식 신청 마감 2026년 11월 22일
[확인 필요] 사진에는 마감이 11월 20일로 적혀 있어요. 공식 공지의 마감을 따르세요.
[신청 접수 중]
마일리지 미공개 · 공식 공지에서 확인
공식 공지 보기   신청 페이지 열기   BISKIT 로그인 필요
확인일 2026년 11월 13일 · 현재 정원과 접수 상태는 공식 링크에서 다시 확인
```

- **보내는 것** — 고른 파일의 바이트를 본문에 그대로 싣고 형식은 `Content-Type`으로 알린다.
  파일에서 바이트만 잘라 내 보내므로 파일명은 요청에 실리지 않고 화면에도 적지 않는다.
  질문 말풍선에는 `사진 1장`이라고만 적는다.
- **보내기 전 검사** — JPEG·PNG가 아니거나 5MB(서버 한도와 같은 5,000,000바이트)를 넘으면 사진도
  질문도 보내지 않고 입력 칸 아래 알림 영역에 이유를 적는다. 적어 둔 질문과 고른 사진은 그대로
  남는다. 서버도 같은 제한으로 다시 검사한다.
- **중복 제출 방지** — 질문·졸업 체크와 같은 잠금(`setBusy`)을 쓴다. 사진 주소와 글자 주소가
  이어지는 동안 잠금을 한 번 걸고 한 번 푼다. 그동안 `보내기`, `사진 첨부`, `첨부 제거`,
  `고쳐서 다시 묻기`, `다시 시도`, 첫 화면의 소개 버튼과 패널 안 시작 버튼(`내 졸업 체크 보기` 등), `새 대화`가 함께 잠긴다.
- **첨부 비우기** — 사진은 보내는 즉시 입력창에서 비운다. 남겨 두면 다음 질문에 같은 사진이 또
  실린다. `첨부 제거`는 사진을 고른 동안에만 보이고, 누르면 고른 사진만 비운다.
- **날짜 순서** — 제목, 행사일, 공식 신청 마감 순으로 적는다. 서버가 `deadline_mismatch`를
  붙였을 때만 그 아래에 사진 마감을 `11월 20일` 꼴로 적는다. 사진 마감에는 연도를 붙이지 않는다.
- **신청 상태** — `open`은 `신청 접수 중`, `closed`는 `신청 마감`, `needs_check`과 모르는 값은
  `신청 상태 확인 필요`. `deadline_day`가 있으면 오늘이 마감일이라는 안내를 덧붙인다.
- **링크** — 인용 카드와 같은 안전 주소 검사(`sourceLink`)를 통과한 주소만 새 탭 링크로 만든다.
  - `notice_url` — `공식 공지 보기`. 통과하지 못하면 `공식 공지 확인 필요`.
  - `application_url` — `신청 페이지 열기`. `login_required`가 참이면 옆에 `BISKIT 로그인 필요`.
  - 신청 주소가 없고 `login_required`가 참이면 `BISKIT 로그인 필요 · 로그인 후 프로그램명으로 검색`.
    링크를 만들지 못해도 로그인이 필요하다는 말은 빠뜨리지 않는다.
- **새 대화** — 결과 카드와 알림을 지우고 고른 사진과 적어 둔 질문도 비운다. 요청 중에는
  `새 대화`가 잠겨 있어 아무것도 바뀌지 않는다.
- **확인 필요** — `event_match`가 `confirmed`가 아니면 서버가 행사 정보를 함께 보냈더라도 제목과
  링크를 그리지 않는다. 물을 글자가 있으면 글자 주소로 넘어가고, 없으면 노란 카드에 사유별
  문구만 적는다. 빨간 오류 스타일은 쓰지 않는다.
  - `no_readable_clue` — 글자나 QR을 찾지 못함
  - `ambiguous_event` — 행사를 하나로 정하지 못함
  - `text_reader_unavailable` — 서버가 글자를 읽을 수 없어 QR 사진이나 직접 입력을 권함
- **사진 주소의 오류** — 문구를 다섯 가지로 나눈다.
  - 413 크기 초과, 415 형식 불일치, 422 열 수 없는 사진·화소 초과. 같은 사진을 다시 보내도
    결과가 같아 `다시 시도` 버튼을 두지 않는다.
  - 통신 실패와 그 밖의 서버 오류(형식이 어긋난 응답 포함). `다시 시도`가 같은 바이트와 함께
    보낸 질문으로 처음부터 다시 한다.
  - 상태 코드는 받았지만 본문을 받는 중에 연결이 끊기거나 시간이 넘으면 통신 실패로 알린다.
    본문을 다 받고도 해석하지 못했을 때만 서버 오류로 알린다.
- **형식이 어긋난 확정 응답** — 행사가 객체가 아니거나, 제목이 비었거나, `login_required`가
  참·거짓 값이 아니면 카드를 그리지 않고 서버 오류 문구를 보여 준다.
- **알림** — 진행 중 문구(`사진에서 글자를 읽는 중…`, `읽은 글자로 답을 찾는 중…`)는 기존 상태
  줄(`#status`)에, 보내기 전 안내와 결과 한 줄은 입력 칸 아래 알림 영역(`#photo-note`,
  `role="status"`)에 써서 화면 낭독기가 읽게 한다.
- **하지 않는 것** — 사진 미리보기, 여러 장 올리기, 사진 보관, 글자 없는 사진 알아보기(건물 등),
  판독문 속 주소나 QR 주소 열기.

## 테크모 펫과 말풍선

배포 화면(`api/app/chat_web/`)의 테크모는 누를 수 있는 작은 펫이다. 지금 무슨 일이 일어나는지 자세와 말풍선의
한 줄 말로 알리고, 누르면 빈 새 대화를 열어 입력창에 초점을 준다. 왼쪽 칸의 비서와 `테크모에게 묻기` 글자 버튼은 없앴다.

- **자리** — 펫 줄(`#pet-dock`)은 대화 내용과 메인 판 뒤에 있다. 판의 유리 흐림이 고정 위치의 기준을 바꾸지 않게
  판 밖에 둔다. 질문 입력창은 기능 카드 위로 옮겼다. 첫 화면(`#empty`) 밖이라 첫 질문을 보낸
  뒤에도 남는다.
  - 680px 이하 — 버튼은 72px이고 하단 줄은 `--techmo-dock-height`의 96px를 확보한다.
  - 681~960px — 버튼은 104px이고 하단 줄은 같은 변수의 184px를 확보한다. 버튼을 줄 오른쪽 아래에 두어
    위 말풍선 공간을 남긴다. 채팅 본문 아래 확보 높이와 680px 이하 홈 최소 높이 식도 이 변수를 쓴다.
  - 961~1463px — 화면 오른쪽 아래에 판·버튼 128px를 고정하고 본문 양쪽에 각각 152px를 확보한다.
  - 1464px 이상 — 판·버튼 168px, 한쪽 예약 폭 192px를 쓴다.
- **누르면** — 첫 화면에서는 채팅 화면으로 전환하고 빈 새 대화를 연다. 채팅 화면에서는 새 대화 버튼과 같은
  처리를 쓴다. Enter·Space도 버튼의 기본 클릭으로 실행한다. 답변을 기다리는 중에 새 대화를 열어도
  늦게 온 답변은 원래 대화에 남는다.
- **옮기면** — 6px를 넘게 끌면 이동으로 판정하고, 버튼을 화면 가장자리 8px 안쪽으로 가둔다.
  위치는 화면 크기에 대한 비율로 저장한다. 로그인·학생 복원·둘러보기로 본문 화면을 연 뒤 실제 버튼 크기로
  복원하며, 그림이 늦게 오면 로드 뒤 다시 복원한다. 화살표는 16px, Shift와 함께는 64px 옮기고 Home은
  기본 자리로 돌아간다. 말풍선과 바라보는 방향은 위치를 따르며, 끄는 동안 말풍선을 숨긴다.
- **말풍선** — 기본 자리와 옮긴 자리 모두 버튼 사각형으로 계산한다. 머리 기준점은 버튼 가로 가운데와
  `윗변 + 높이 × 44/192`이며, 10px 꼬리 끝을 그 위 8px에 둔다. 말풍선은 머리에 가운데를 맞추고
  화면 가장자리 8px 안으로 민다. 961px 이상 기본 자리에서는 예약 영역 안에도 가두어 본문 오른쪽 끝에서
  8px 이상 띄운다. 옮긴 자리에서는 화면 가장자리만 계산한다. 꼬리는 머리를 계속 가리킨다. 위 공간이 부족하면
  버튼 아래로 뒤집고 꼬리를 위에 단다. 문구 변경·그림 로드·창 크기 변경·놓기·방향키 이동·기본 자리 복귀 때 다시 계산한다.
  680px 이하에서는 평소 대기 문구 「궁금한 점을 물어보세요」를 숨기고, 찾는 중·답변 도착·보류·오류·로그인 안내 등
  상태 문구만 4초 표시한 뒤 숨긴다. 움직임 줄이기 설정에서도 같은 표시 시간을 쓴다. 별도 상태 줄(`#status`)과
  로그인 오류 글은 계속 갱신한다. 681~960px에서는 대기·상태 말풍선을 계속 표시한다.
- **말풍선 모양(#128)** — 패널 색(`--glass-dense`)과 나눈 별도 물건이다. 크림 바탕 `#FFF6D6`(`--pet-bubble`),
  남색 `#0A2540` 1.5px 선, 흐림 없는 그림자 `3px 3px 0 #0A2540`, 남색 600 굵기 글자, `keep-all` 줄바꿈, 최대 폭 22em이다.
  다크 테마(직접 고른 다크 또는 속성 없는 시스템 다크, #131)에서는 한 단계 어두운 `#F3E7BF`(`--pet-bubble-dark`)를 쓴다.
  남색 글자는 두 크림 모두에서 4.5:1을 넘는다.
  로그인 화면 말풍선(`#login-pet-line`)은 이번 범위가 아니라 그대로다.
  - 꼬리 — `.pet-says` 안, `#pet-line` 밖에 둔 장식 SVG(`.pet-tail`, 20×12px) 한 장이다. 예전 삼각형 두 겹(`::before`·`::after`)은 없앴다.
    채움(`.pet-tail-fill`)의 위쪽 1.5px가 말풍선 아래 선을 덮고, 두 빗변(`.pet-tail-line`)만 선을 그어 외곽선이 끊기지 않는다.
    가로 위치는 `chat.js`가 주는 `--techmo-bubble-tail-x`에서 선 두께 1.5px를 뺀 자리이고, `data-bubble-below="true"`이면
    같은 그림을 위아래로 뒤집어 상자 위에 붙인다. `chat.js`는 말풍선 안쪽 구조를 건드리지 않는다.
  - 나타남 — `data-bubble-visible`이 `"true"`가 되는 순간 말풍선 판이 꼬리 끝을 기준점(`transform-origin`)으로 .92에서 1로
    0.2초 ease-out으로 커진다(`pet-says-grow`). 글자·대기 점·꼬리는 판이 거의 다 커진 뒤 투명도만 바뀌며 나타난다(`pet-says-fade`).
    넓은 화면은 처음 그릴 때, 680px 이하는 말풍선을 다시 띄울 때마다 돈다.
  - 커지는 층 — `chat.js`는 문구 변경·창 크기 변경·그림 로드 때마다 `.pet-says`의 `getBoundingClientRect` 높이로 자리를 잡는다.
    이 값은 그 요소와 조상의 변형(transform)만 반영하고 자식의 변형은 반영하지 않는다. 그래서 펫 줄 안의 `.pet-says` 자신은
    선·바탕·그림자를 투명하게 두고 어떤 규칙에서도 변형하지 않는다. 크림 판·남색 선·그림자는 자식 층 `.pet-says::before`
    (선 두께만큼 바깥으로 넓힌 `inset: -1.5px`, `z-index: -1`)가 그리고 그 층만 커진다. 커지는 도중에 다시 재도 원래 높이가 나온다.
    꼬리 그림은 이 판 위에 그려져 판의 아래(또는 위) 선을 덮는다.
    움직임 줄이기에서는 끈다. 끄는 동안 숨김과 680px 이하 표시 규칙은 그대로다.

| 상태 | 자세 | 한 줄 말 | 언제 |
|---|---|---|---|
| 평소 | 안내 | 궁금한 점을 물어보세요 | 처음, `새 대화` |
| 찾는 중 | 정숙 | 쉿, 찾아보는 중이에요… | 요청 잠금(`setBusy`)을 거는 순간 |
| 찾음 | 축하 | 찾았어요! 함께 확인해 봐요 | 답·졸업 표·확정된 행사·일정이나 장소 목록을 그린 직후 |
| 답변 표시 | 안내 | 근거와 함께 안내해 드릴게요 | 축하 0.8초 뒤 |
| 답변 보류 | 정숙 | 확인할 근거가 더 필요해요 | 근거 없음, 글자 주소의 보류, 읽은 글자가 없는 사진, 남은 일정이나 장소 없음 |
| 오류 | 안내 | 잠시 문제가 생겼어요. 다시 시도해 주세요 | 통신 실패, 서버 오류, 형식이 어긋난 일정·장소 응답, 서버가 거절한 사진·글자 |

- **한 곳에서만 바꾼다** — 자세·말·대기 점은 `showAssistant`만 바꾼다. 일반 질문, 사진 질문,
  읽은 글자 재질문, 졸업 체크, 학사 일정·캠퍼스 안내 조회가 같은 표를 쓴다.
- **그림은 갈아 끼우지 않는다** — 그림 여러 칸을 모은 한 장(스프라이트 시트)을 배경으로 쓴다.
  출처는 「공식 테크모를 바탕으로 새로 그린 동작 시트, 저장소에 보관」이다.
  서버가 전달한 `data-techmo-layout`과 실제 그림 크기가 맞을 때만 새 프레임 재생을 켠다.
  칸 크기와 줄·프레임 수는 전달값에서 읽고, 배경 위치를 한 칸씩 넘긴다. 필름을 창 뒤에서 당겨 보는 것과 같다.
  옛 960×192px 그림이거나 배치를 읽지 못하면 기존 `data-pose` 위치를 쓴다.
- **그림이 없어도 동작한다** — 펫 버튼은 로고와 같은 방식(`data-brand-slot`)으로 숨긴 채 시작하고, 버튼 안에
  둔 같은 주소의 그림이 로드에 성공해야 보인다. 그림이 없으면 버튼을 숨기고 말풍선은 앞의 표시 규칙을 따른다. 버튼 크기는
  680px 이하 72px, 681~960px 104px, 961~1463px 128px, 1464px 이상 168px로 고정해 그림이 늦게 와도 입력창이 밀리지 않는다.
  로그인 테크모는 112px 정사각형 칸과 같은 시트 배경 크기·줄 선택을 쓰며 부모는 그림을 잘라내지 않는다.
- **움직임** — 이동·좌우 뒤집기·배경 재생을 서로 다른 요소에 건다. 새 시트에서는 대기 1.6초 반복,
  안내 0.9초 한 번, 축하 0.8초 한 번, 정숙 2.4초 반복, 끌기 0.5초 반복으로 재생한다.
  놓기 축하가 끝나면 그때의 요청 상태에 맞는 동작으로 돌아간다. 옛 시트에서는 기존 떠 있기·튀기·쉬는 자세를 쓴다.
- **대기 점** — 찾는 중일 때만 말 옆에 점 세 개가 움직인다. 찾음·보류·오류에서 사라진다.
- **움직임 줄이기** — 기기의 움직임 줄이기 설정(`prefers-reduced-motion: reduce`)이 켜져 있으면
  새 시트는 각 동작의 첫 칸만 보이고, 기존 떠 있기·튀기·쉬는 자세·점의 움직임도 끈다. 상태에 따라
  정지 그림 칸이 바뀌는 것과 말·점 표시는 그대로 남는다.
- **잠금을 풀 때** — 요청이 남긴 축하·보류·오류를 덮어쓰지 않는다. 결과를 남기지 않고 끝난 요청이
  있을 때만 평소로 돌려 대기 점이 남지 않게 한다.
- **예약 취소** — 축하 뒤 전환을 기다리는 동안 새 질문이나 `새 대화`가 시작되면 예약한 전환을 취소한다.
- **낭독** — 진행 알림은 기존 상태 줄(`#status`)이 읽어 준다. 말풍선에는 알림 역할을 두지 않아
  화면 낭독기가 같은 일을 두 번 읽지 않는다. 펫 버튼의 읽기용 이름은 `아이오와 새 대화`이고, 그림의 대체 글은 `테크모`다.
- **예전 안내 상자** — 채팅 맨 위의 `학사 규정에 질문하기` 상자와 `가상 학생 졸업 체크` 버튼은 없앴다.
  졸업 체크는 소개 영역의 `내 졸업 체크 보기`와 패널의 `졸업 체크 시작`으로 부른다. 채팅 영역 제목은
  화면에서만 감춘 제목으로 남겨 화면 낭독기가 영역 이름을 읽는다.

## 기능 카드와 패널

첫 화면의 카드 여섯 개는 기능을 바로 부르지 않고 설명 패널을 연다. 카드는 책갈피다. 당기면 카드 목록이
있던 자리에 그 카드의 쪽이 펼쳐진다.

| 식별자 | 카드 | 패널 내용 | 시작 버튼 → 부르는 기능 |
|---|---|---|---|
| `graduation` | 졸업 체크 | 가상 학생의 이수 내역으로 남은 조건을 계산한다 | `졸업 체크 시작` → 졸업 체크 |
| `biskit` | 비교과 추천 | 졸업 체크 결과 아래에 부족한 점수를 채울 프로그램이 함께 나온다 | `졸업 체크와 추천 보기` → 졸업 체크 |
| `photo` | 사진으로 묻기 | 글자가 보이는 JPEG·PNG 한 장, 5MB 이하, 개인정보 제외 | `사진 선택` → 사진 선택 창 |
| `ask` | 규정 질문 | 질문을 적으면 근거 조문과 함께 답한다 | `질문 입력하기` → 입력창 초점 |
| `calendar` | 학사 일정 | 조회 범위의 남은 수강신청 일정과 출처 | 패널을 열 때 한 번 조회 |
| `campus` | 캠퍼스 안내 | 장소 이름·용도 목록과 선택한 장소의 상세 안내 | 패널을 열 때 한 번 조회 |

카드와 열린 패널의 제목 앞에는 같은 42×42px 배지를 둔다. 왼쪽 위만 각진 구슬 모양에 지정한 여섯
선 아이콘을 23×23px로 그린다. 아이콘은 문서 안 벡터 그림(SVG)이며 화면 읽기에서 빼고 색은 CSS 변수로 정한다.

- **자리** — 패널은 `#empty` 안, 카드 목록 바로 뒤의 글 흐름에 있다. 화면 위에 띄우지 않으므로 펫·말풍선·
  입력창을 가리지 않는다. 화면을 덮는 `<dialog>`와 접는 `<details>`는 쓰지 않는다.
  답변 위의 「생각 과정」 칸은 예외로 `<details>`를 쓴다. 깊이 생각하기에서 생각 조각이 오면
  펼쳐 쓰고, 답 글자가 오기 시작하면 접는다. 생각 과정은 대화 기록에 저장하지 않는다.
- **이름** — 화면(`index.html`)과 스크립트(`chat.js`)가 함께 지킨다.
  - 카드 — `button.card[data-feature=식별자]`, `aria-controls=panel-식별자`, `aria-expanded`. 카드에는
    `data-action`을 두지 않는다.
  - 카드 목록 — `ul.cards#feature-cards`.
  - 패널 — `section.feature-panel#panel-식별자[data-panel=식별자][hidden]`. 제목은 `[data-panel-title]`,
    닫기는 `button[data-panel-close]`, 시작 버튼은 `button[data-action]`.
- **열기** — 카드를 누르거나 초점을 두고 Enter·Space를 누르면 카드 목록 대신 그 패널이 보이고, 초점이 패널
  제목으로 간다. 제목은 `tabindex="-1"`이라 스크립트로만 초점을 받고 Tab 순서에는 들지 않는다.
- **닫기** — `닫기` 버튼이나 패널 안에서 누른 Escape로 닫는다. 초점은 눌렀던 카드로 돌아간다.
- **시작 버튼** — 패널을 닫고 이미 있는 기능을 부른다. `data-action` 버튼이라 요청 중에는 다른 버튼과 함께
  잠기고, 연달아 눌러도 졸업 체크 요청은 하나만 나간다.
- **일정·장소 조회** — 두 패널은 `[data-panel-content]`에 결과를 그린다. 패널을 열 때 기존 요청 잠금
  (`setBusy`, `whileBusy`)으로 한 번 조회한다. 다른 요청 중에 열면 안내와 `다시 시도`만 보여 주고 펫 상태는
  바꾸지 않는다. 실패하면 패널 안에서 다시 시도하며, 연달아 눌러도 요청은 하나만 나간다. 닫거나 다른 패널로
  옮긴 뒤 도착한 응답은 화면과 펫 상태에 반영하지 않는다.
- **학사 일정** — 스크립트의 조회 범위 상수로 학년도·학기 표시를 만든다. 한국 표준시의 오늘을 기준으로
  종료일이 오늘 이후인 일정을 시작일순으로 적고, 날짜는 연·월·일만 표시한다. 연도 없는 날짜와 실제로 없는
  날짜, 시작일보다 이른 종료일은 응답 전체의 형식 오류로 처리한다. 남은 일정이 없으면 조회 범위와 함께 알린다.
  출처에는 제목과 확인일, `공식 페이지에서 다시 확인` 안내를 붙인다.
- **캠퍼스 안내** — 서버 순서대로 장소의 이름·용도를 버튼 목록으로 적는다. 선택하면 같은 응답에서 `id`로
  찾아 위치와 값이 있는 선택 항목만 보여 준다. 새 요청은 보내지 않는다. 선택 시 상세 제목으로, `목록으로`를
  누르면 고른 장소 버튼으로 초점을 옮긴다. 장소 목록이나 필수 글자 필드가 어긋나면 형식 오류로 처리한다.
- **출처와 글자** — 안전 주소 검사(`isSafeSourceUrl`)를 통과하고 확인일이 날짜 꼴인 출처만 링크로 만든다.
  나머지는 제목만 적는다. 서버의 안내 글은 글자로 넣으므로 주소처럼 생긴 글자도 링크로 바뀌지 않는다.
- **새 대화** — 패널을 연 채 질문을 보냈더라도 카드 목록이 보이는 첫 화면을 되돌린다.
- **커지는 전환** — 브라우저가 바뀌기 전후 화면을 이어 그려 주는 기능(View Transitions,
  `document.startViewTransition`)이 있으면 카드가 패널로 커지고, 닫을 때는 카드로 줄어든다. 기능이 없거나
  전환이 실패하면 같은 상태 변경을 바로 한다.
  - 스크립트는 누른 카드에 `data-morph`를 붙였다 뗀다. 이어 그릴 짝을 정하는 이름
    (`view-transition-name: feature-morph`)은 CSS가 `.card[data-morph]`와 열린 패널에만 준다.
  - 같은 이름을 가진 요소가 한 화면에 둘 보이면 브라우저가 전환을 건너뛴다. 그래서 패널이 열려 있는 동안
    카드 목록은 그리지 않는다.
  - 상자는 .32초 동안 커지고 글자 그림은 왼쪽 위 원래 크기로 잘라 보여 준다. 옛 그림은 앞 40%에
    사라지고 새 그림은 30%부터 나타난다. 나머지 카드는 .2초 동안 흐려진다. 닫을 때는 역순이다.
  - `data-feature-direction`은 열기·닫기 방향을 표시하고 전환 종료 때 지운다. 닫힌 카드의
    `data-restored`는 포인터가 떠나거나 다시 조작할 때 지워, 닫은 직후 떠오름이 남지 않게 한다.
  - 카드 목록의 전환 이름은 `data-feature-direction`이 있는 동안만 붙인다. 채팅 화면을 오갈 때는
    카드 목록도 메인 판과 함께 움직인다.
- **펫 줄에 가리지 않기** — 960px 이하의 펫 줄은 화면 아래에 붙어 그 밑의 내용을 가린다. 첫 화면의 버튼과
  패널 제목에 아래쪽 여유(`scroll-margin`, 120px)를 두어, 초점을 받아 화면에 들어올 때 펫 줄 위에 멈춘다.
- **움직임 줄이기** — 스크립트는 전환을 시작하지 않고, CSS도 전환의 움직임을 끈다. 패널은 바로 열리고 닫힌다.

## 로그인과 카드 움직임

로그인 카드는 아래에서 0.8초 떠오르고 테크모는 3.6초마다 8px 오르내린다. 기능 카드는 마우스를 올리면
4px 떠오른다. 로그인 카드와 테크모의 규칙 이름은 `login-rise`, `login-float`다.
기능 카드는 상태를 따라가는 `transition`으로 .18초 동안 움직인다. 움직임 줄이기에서는
기존 펫·대기 점·화면 전환과 함께 끈다. 작은 화면에서도 제목과 안내를 자르지 않는다.

## 로딩 상태

Agent 루프는 여러 단계를 거쳐 응답이 2초를 넘길 수 있다. 스피너 하나로 두면 멈춘 것처럼 보인다.
단계를 텍스트로 노출한다.

```
규정 문서 검색 중...
→ 학적 정보 확인 중...
→ 답변 작성 중...
```

`latency_ms`를 응답에 포함시킨 이유도 여기 있다 — 어느 단계가 느린지 실측해야 개선 대상을 정한다.

## 상태 관리 방침

채팅 관련 상태를 `useChat` 훅 하나로 모은다.

```
useChat()
  messages, isLoading, currentStage, error
  sendMessage(text, useAcademicData)
  retry()
```

컴포넌트 여러 곳에서 로딩 플래그를 각자 들고 있으면 비동기 순서가 꼬였을 때
어디서 어긋났는지 추적이 안 된다. 이전 프로젝트에서 겪은 문제라 처음부터 한 곳으로 모은다.

## AI 보류 판정과 안내 답 표시 (#101)

조각 전송(SSE, 서버가 답을 조각으로 흘려보내는 방식)은 meta 이벤트를 먼저 보낸다. 서버는 AI 답을
다 받은 뒤에야 조문으로 답할 수 없다고 판정할 수 있어서, 화면은 최종 모양을 done 이벤트에서 정한다.
택배 송장(meta)에 「도착 예정」이 찍혀 있어도 실제 수령 여부는 받는 순간(done)에 확인하는 것과 같다.

- `requestChatAnswer()`는 done의 값을 보관한다. `done.answered`가 boolean이면 meta 값보다 앞서고,
  없으면 meta 값을 따른다. 안내 답은 SSE에서는 `done.guided === true`, JSON 주소에서는 응답 본문의
  `guided === true`일 때만 인정한다. meta에 들어온 `guided`는 쓰지 않는다.
- 보류는 근거 상자와 notice 없이 `fallback` 모양으로 그린다. 글은 서버가 보낸 보류 문구를 그대로 쓰고,
  서버 글이 없거나 공백뿐일 때만 화면의 고정 보류 문구를 고른 언어로 쓴다(#116). done까지 정상으로 받은
  응답이라 JSON 주소로 다시 묻지 않는다.
- 안내 답은 받은 글 그대로 일반 말풍선에 그린다. 근거 상자와 notice는 붙이지 않고 테크모는 보류 상태로 둔다.
  안내 글이 비었거나 공백뿐이면 보류로 그린다.
- 서버 글은 지금처럼 `textContent`로만 넣는다.

### 기록

- 답 말풍선 기록에는 보류와 안내 답 모두 `answered:false`, 안내 답이면 `guided:true`를 더한다.
  일반 답에는 두 필드를 넣지 않는다.
- `trimConversations()`는 답 말풍선의 `answered === false`, `guided === true`만 복사한다. 문자열 값,
  질문 말풍선의 값, `answered:false` 없이 들어온 `guided`는 버린다.
- 저장한 대화를 다시 열면 보류는 `reply fallback`, 안내 답은 `reply` 모양으로 그린다. 필드가 없는 옛 기록은
  글이 보류 문구여도 보류로 바꾸지 않는다.

## 대화 메뉴·보관함·삭제 확인 창 (#104)

대화 목록의 휴지통 버튼 자리에 점 세 개 `대화 메뉴` 버튼을 둔다. 브라우저 기본 확인 창(`window.confirm`)은
사이트 주소를 띄우므로 쓰지 않는다. 대신 `chat.js`가 만든 화면 안 확인 창이 삭제를 묻는다.

### 대화 메뉴

- 우클릭, 500ms 길게 누르기, 메뉴 키·Shift+F10, `대화 메뉴` 버튼이 모두 같은 메뉴(`role=menu`)를 연다.
  항목(`role=menuitem`)은 보통 대화에서 `보관하기`·`삭제`, 보관된 대화에서 `보관 해제`·`삭제`다.
- 메뉴는 누른 자리나 버튼 아래에 뜬다. 화면 가장자리 8px 밖으로 나가면 스크립트가 안쪽으로 민다.
  좌표는 `style.setProperty()`로 `--conversation-menu-x`·`--conversation-menu-y` 변수에만 넘긴다.
- 위아래 화살표가 항목을 옮기고 끝에서 반대쪽으로 돈다. Home·End는 처음과 끝, Enter는 실행, Tab은 닫기다.
- Esc·바깥 누르기·스크롤로 닫고 초점을 연 자리로 돌린다. 메뉴를 연 버튼을 다시 누르면 닫는다.
- 기본 우클릭 메뉴는 대화 항목과 대화 메뉴 안에서만 막는다. 문서 전체에는 막는 처리기를 두지 않는다.
- 길게 누르기는 손가락과 펜만 센다. 손을 떼거나 벗어나거나 10px 넘게 움직이거나 스크롤하거나
  `pointercancel`이 오면 취소한다. 메뉴를 연 뒤 손을 떼면 따라오는 클릭 한 번은 대화를 열지 않는다.
- 메뉴와 확인 창은 처음 열 때 `body` 끝에 한 번 만들고 다시 쓴다. 서랍 안에서도 같은 노드가 서랍 위에 뜬다.

### 보관함

보관은 책장 한 칸을 따로 비우는 대신 책등에 스티커만 붙이는 것과 같다. 대화는 같은 `conversations` 배열에 남는다.
늦은 답은 `conversations.includes(record)`로 유효성을 보므로, 보관은 같은 객체의 `archived`만 바꾼다.

- 전체를 최근 순으로 정렬한 뒤 보관하지 않은 대화를 먼저 그린다. 그 아래에 처음에는 접힌 `보관함 (N)`이 온다.
- 계정을 바꾸면 보관함은 다시 접힌다. 접힌 보관함에 읽지 않은 답이 있으면 묶음 버튼에 노란 점을 붙인다.
- `trimConversations()`는 `archived === true`만 보관으로 복사한다. 없거나 문자열·숫자 같은 깨진 값은 보관 안 됨이다.
  최근 20개 한도와 오래된 것부터 버리는 규칙은 보관 여부와 관계없다.
- 보관·해제는 시각과 내용을 바꾸지 않는다. 해제하면 원래 최근 순 자리로 돌아온다.
- 보던 대화를 보관하면 `startNewConversation()`으로 새 대화 화면을 열고 초점을 입력창에 둔다.
  다른 대화를 보관하면 초점은 그 항목이 보이면 그 항목, 접힌 보관함으로 들어가면 목록의 다음 항목으로 간다.
- 보관된 대화를 열기만 해서는 보관이 풀리지 않는다. 입력 검사를 통과해 전송을 받아들일 때 보관을 풀고 저장한다.
  빈 질문이나 답을 기다리는 중이라 거부된 전송은 보관을 유지한다.
- 보관된 대화에도 늦은 답·답 도착 알림·읽지 않음 점이 그대로 붙는다.

### 삭제 확인 창

| 구분 | 제목 | 설명 |
|---|---|---|
| 하나 삭제 | 정말로 삭제하시겠습니까? | ‘{첫 질문 앞 20자}’ 대화를 지우면 되돌릴 수 없어요. |
| 모두 삭제 | 대화 기록을 모두 삭제하시겠습니까? | 보관함을 포함한 대화 N개가 지워지고 되돌릴 수 없어요. |

- 가림막(`confirm-scrim`)과 `role=alertdialog` 상자 하나를 다시 쓴다. `aria-modal="true"`를 두고
  제목과 설명을 `aria-labelledby`·`aria-describedby`로 잇는다. 제목이 비면 `새 대화`로 부른다.
- 버튼은 위험 색(`--bad`·`--bad-bg`) `삭제`와 `취소`다. 열리면 초점이 `취소`로 가고 Tab·Shift+Tab은 두 버튼 사이만 돈다.
- 열린 동안 `body`의 다른 자식에 `inert`를 걸고, 닫을 때 각 노드의 원래 값을 되돌린다. 서랍이 걸어 둔 `inert`도 그대로 남는다.
- Esc·가림막 클릭은 취소다. 취소는 기록과 진행 중 요청을 바꾸지 않는다. 기다리던 요청이 있는 대화를 지우면
  기존 유효성 검사가 늦은 답을 버린다. 되돌리기 알림은 만들지 않는다.
- 닫히면 연 자리로 초점을 돌린다. 목록을 다시 그리면 노드가 바뀌므로 대화 ID와 버튼 종류로 다시 찾는다.
  삭제로 항목이 없어졌으면 목록의 다음 항목, 그것도 없으면 `새 대화` 버튼으로 간다. 모두 지우기는 `기록 모두 지우기` 버튼으로 돌아간다.
- Esc는 확인 창 → 메뉴 → 서랍 순으로 맨 위의 하나만 닫는다. 문서의 keydown 처리기 하나가 이 순서를 맡는다.
- 브라우저 뒤로 가기는 `inert`로 막지 못한다. `setChatView()`는 화면을 바꾸기 전에 열린 확인 창을 취소로,
  메뉴는 그냥 닫는다. 초점은 바로 옮기지 않는다. 좁은 화면에서는 이때 서랍이 입력창 쪽에 건 `inert`가
  남아 있어 초점 이동이 조용히 실패하기 때문이다. 화면 전환과 서랍 닫기를 마친 `apply` 끝에서
  입력창으로 초점을 보낸다. 숨거나 `inert`가 된 목록에 초점이 남은 경우도 같은 자리에서 입력창으로 옮긴다.
  초점 복귀 함수도 목록이 숨었거나 `inert`이면 목록 버튼 대신 입력창을 고른다.
- `chat_screen.test.mjs`의 가짜 노드는 `append()`에서 부모를 기억한다. `focus()`는 자신이나 조상이
  `inert`면 초점을 옮기지 않아, 실제 브라우저에서만 드러나던 초점 실패를 테스트에서 재현한다.
- 메뉴(30)와 가림막(40)은 서랍(11)·알림(12)·테크모(20)보다 위에 뜬다. 움직임과 전환은 넣지 않는다.

### 테스트 모형 보완

- `chat_screen.test.mjs`의 가짜 문서와 노드는 같은 종류 이벤트의 처리기를 여러 개 모아 순서대로 부른다.
  예전 모형은 마지막 처리기만 남겨 처리기 덮어쓰기 회귀를 놓칠 수 있었다.
- 가짜 노드에 `contains()`·`style.setProperty()`·`fire()`, 가짜 문서에 `activeElement`를 더했다.
  저장 기록 모형은 `archived`·`unread`도 보존한다. 가짜 `window.confirm`은 부르면 실패한다.
- 스크립트의 `.style` 사용 검사는 `--techmo-`와 `--conversation-menu-` 변수 설정만 허용한다.
  고정 위치 선택자 목록에는 `.conversation-menu`와 `.confirm-scrim`을 더했다.

### 밝은 로고와 이어지는 판

밝은 로고 그림 `kumoh-signature-light.png`를 받으면 남색 위에 바로 표시한다. 실패하면

## 입력 상자 안 답변 모드와 반투명 패널 (#110)

### 답변 모드 선택기

- 입력 상자 밖의 `fieldset#ai-mode` 라디오를 없앴다. `.composer-row` 안의 `#question`과 `#send` 사이에
  알약 버튼 `#ai-mode-button.mode-pill`을 둔다. 빠르게는 번개 아이콘과 「빠르게」, 깊이는 네 갈래 별(✦)과
  「깊이 생각」을 보이고 끝에 꺾쇠를 둔다. 아이콘 SVG는 `index.html`에 직접 둔다. 보안 정책
  `default-src 'self'`가 CSS 안의 `data:` 그림을 막기 때문이다.
- 누르면 버튼 위쪽에 「답변 모드」 메뉴가 뜬다. 항목은 아이콘·이름·한 줄 설명·체크 표시다.
  - 빠르게 — 바로 답해요 · 보통 1~3초
  - 깊이 생각하기 — 생각 과정을 보여 주며 꼼꼼히 답해요 · 10~30초
- 키보드: 위아래 화살표로 이동하고 끝에서 처음으로 돈다. Enter·Space로 고른다. Esc는 메뉴만 닫고
  버튼으로 초점을 돌린다. 대화 메뉴나 서랍까지 닫지 않는다. 바깥 클릭과 Tab은 닫되, 사용자가 옮긴 초점을 빼앗지 않는다.
- 저장: 키 `kumoh-chat-ai-mode:v1`과 요청 본문의 `mode` 값은 그대로다. 저장에 실패하면 상태·버튼 글자·
  `aria-label`·체크·깊이 표시를 모두 빠르게로 되돌린다.
- 진행 중 변경: 답을 받는 중에 바꾸면 다음 질문부터 적용한다. 요청마다 보낼 때의 모드를 기억한다.
- 메뉴는 버튼·머리글·항목 목록·선택 콜백을 받는 작은 함수(`openChoiceMenu` 꼴)다. 답변 모드 전용 값은 함수 밖에 둔다.
  다음 이슈의 머리글 언어 선택이 같은 함수와 `.choice-menu` 스타일을 다시 쓴다.

### 스크립트와 스타일이 함께 지키는 이름

| 이름 | 붙이는 쪽 | 뜻 |
| --- | --- | --- |
| `#ai-mode-button.mode-pill[data-mode=fast\|deep]` | chat.js | 현재 모드. CSS는 `data-mode`로 아이콘 하나만 보인다 |
| `.mode-icon[data-icon=fast\|deep]`, `.mode-pill-label`, `.mode-pill-chevron` | index.html | 버튼 안쪽 |
| `body > .choice-menu` | chat.js | 메뉴. 안쪽은 `.choice-menu-title`, `.choice-menu-item[data-choice-value]`, `.choice-menu-icon`·`.choice-menu-name`·`.choice-menu-desc`·`.choice-menu-check` |
| `--choice-menu-x`, `--choice-menu-y` | chat.js(`style.setProperty`) | 메뉴 좌표. 화면 안쪽 보정과 초점은 JS, 너비·최대 높이·겹침 순서는 CSS |
| `.composer-row.is-deep`, `.mode-pill[data-mode=deep]` | chat.js | 고정 표시. 움직임 설정과 상관없이 1px 그라데이션 테두리를 그린다 |
| `.mode-pill.is-bursting`, `.mode-spark`, `.composer-row.is-deep-enter` | chat.js | 고르는 순간의 효과. 0.7초·0.9초 뒤 뗀다 |
| `.mode-pill.is-flowing` | chat.js | 깊이 모드인 동안 테두리가 흐르고 3초마다 빛줄기가 지난다 |
| `.thinking.is-waiting` | chat.js | 첫 생각 조각 전부터 「생각하는 중」 글자 위로 빛이 흐른다 |

- 효과 클래스는 움직임이 허용될 때만 붙는다. CSS도 `prefers-reduced-motion: reduce`에서 효과의 `animation`을 끄고
  별·빛줄기·감싸는 빛을 그리지 않는다. 고정 그라데이션 테두리만 남는다.
- 메뉴는 서랍(z-index 11)과 테크모(20) 위, 삭제 확인 창(40) 아래인 30에 뜬다. 너비는 `min(320px, calc(100vw - 32px))`다.
- 480px 이하에서는 버튼 글자(`.mode-pill-label`)를 숨기고 아이콘과 꺾쇠만 남긴다. 현재 값은 `aria-label`이 읽는다.
- 깊이 색은 학교 파랑 `#00A3D9`(`--sky`) → 보라 `#6A4BD8`(`--deep-violet`) → 노랑 `#F7C500`(`--deep-gold`)다.
  고정 표시는 버튼 자신의 배경에 100% 크기로 깔아 세 색을 모두 보인다. 효과 클래스는 버튼 배경을 바꾸지 않는다.
  흐르는 고리는 버튼 위에 겹친 별도 층(`.mode-pill.is-flowing::after`)에서만 3배로 늘려 옮긴다.
  `.is-flowing`이 붙은 채 움직임 줄이기를 켜도 이 층만 사라지고 고정 테두리가 남는다.

### 반투명 기준

반투명 면은 간유리 창과 같다. 한 장이면 바깥이 흐리게 보이지만 두세 장 겹치면 벽이 된다.

| 면 | 토큰 | 불투명도 | 흐림 |
| --- | --- | --- | --- |
| 큰 면: 첫 화면 `.layout`, 채팅 화면 `#conversation-sidebar`·대화 영역 | `--main-surface` | .50 | `blur(16px) saturate(1.3)` |
| 말풍선·카드·패널·바닥·상태 줄 | `--main-bubble` (마우스 `--main-bubble-hover`, 현재 항목 `--main-bubble-active`) | .66 (.68) | 말풍선·카드는 `blur(10px)` |
| 말풍선 안 근거·표·사진 읽기 상자 | `--main-inset` | .30 | 없음 |
| 입력 안내 줄 `.composer-meta` | `--main-backing` | .80 | `blur(10px)` |

- 큰 면끼리 겹치지 않는다. 첫 화면은 판 한 장이고 대화 영역은 투명하다. 채팅 화면은 판과 흐림 층을 비우고
  목록과 대화 영역이 각자 큰 면이 된다. 960px 이하에서 서랍을 열 때만 목록이 가림막 위에 잠시 겹친다.
- `.layout`에는 `backdrop-filter: none`을 유지한다. 판에 흐림을 주면 안쪽의 고정 서랍과 가림막의 위치 기준이
  화면에서 판으로 바뀐다. 흐림은 판 뒤에 까는 `.layout::before`(z-index -1)가 맡고, 판과 같은 56px 경계에서 마스크로 시작한다.
- 흐림을 지원하지 않는 브라우저는 `@supports not ((backdrop-filter: blur(1px)) or (-webkit-backdrop-filter: blur(1px)))`
  안에서 이전 값을 쓴다. 판 `--panel-surface`, 목록·말풍선·카드·안내 줄 `--glass-dense`다. Safari를 위해
  `-webkit-backdrop-filter`를 함께 적는다.
- 로그인 화면의 `--glass-*` 값과 `.login-card`·`.masthead`의 `blur(1.5px) saturate(1.2)`는 바꾸지 않았다.
- 메인 화면의 초점 테두리는 흰색(`#main-screen :focus-visible`)이다. 기존 하늘색 `--focus-ink`는 흰 사진 가정에서
  판(.50)과 약 2.1:1이라 3:1에 못 미친다. 밝은 입력 상자 안은 지금처럼 `--blue`를 쓴다.

## 화면 언어 설정 — 한국어 · English · 中文 (#116)

외국인 유학생도 로그인부터 답변까지 읽을 수 있게 화면 언어를 고른다. 사전은 `chat.js` 맨 앞에 하나로 두고,
한국어 원문을 열쇠로 쓴다. 여행 회화집처럼 왼쪽에 한국어 문장, 오른쪽에 번역을 적는 방식이다. 그래서 한국어 화면은
사전이 없을 때와 글자 하나까지 같고, 표에 없는 문구는 한국어로 남는다.

### 선택기

- 머리글 `.masthead-actions` 첫 자리(`#lang-button`)와 로그인 화면 오른쪽 위(`#login-lang-button`)에 알약 버튼을 둔다.
  안쪽은 지구본 SVG(`.lang-pill-globe`)·현재 언어(`.lang-pill-label`)·꺾쇠(`.lang-pill-chevron`)다. 기본 드롭다운(select)은 쓰지 않는다.
- 두 버튼은 같은 언어 상태를 쓰고, 메뉴는 답변 모드와 같은 `openChoiceMenu`다. 모양·키보드(위아래 화살표, Enter·Space,
  Esc, Tab, 바깥 클릭)·읽기 도구용 속성(ARIA, `role="menu"`·`menuitemradio`·`aria-checked`) 규칙이 같다.
- 메뉴 머리글은 언어와 상관없이 `언어 / Language`다. 항목은 자기 이름(`한국어`·`English`·`中文(简体)`)이고 아래에
  `Korean`·`영어`·`Chinese (Simplified)`를 작게 쓴다. 항목 이름에는 `lang` 속성을 붙여 읽기 도구가 그 언어로 읽는다.
- `openChoiceMenu`는 버튼 위에 메뉴가 들어갈 자리가 있으면 위로, 없으면 아래로 연다. 둘 다 모자라면 넓은 쪽이다.
  입력 상자 안 답변 모드는 지금처럼 위로, 머리글과 로그인 화면의 언어 메뉴는 아래로 열린다.
- 480px 이하 머리글에서도 현재 언어 이름을 보인다. 간격·글자 크기·지구본만 줄인다. 읽기 도구는 `aria-label`(`언어 / Language: 한국어` 꼴)을 읽는다.

### 저장과 첫 방문

- 키는 `kumoh-chat-lang:v1`, 값은 `ko`·`en`·`zh`다. 고를 때만 저장한다.
- 저장값이 없으면 `navigator.language`가 `en`으로 시작할 때 영어, `zh`로 시작할 때 중국어, 나머지는 한국어다.
- 저장소가 없거나, 읽기·쓰기에 실패하거나, 모르는 값이 저장돼 있으면 한국어다. 답변 모드가 저장 실패 때 빠르게로 돌아가는 것과 같다.
- `html lang`은 `ko`·`en`·`zh-Hans`로 바꾼다. 중국어 화면은 `html:lang(zh)` 규칙이 `"PingFang SC"`·`"Microsoft YaHei"`·
  `"Noto Sans SC"`를 앞에 둔다. 기본 글꼴 목록에도 세 글꼴을 더했다. 보안 정책이 외부 글꼴을 막으므로 기기 글꼴만 쓴다.

### 바꾸는 즉시 다시 그리는 것

새로고침 없이 아래를 바꾼다. 한국어로 시작한 화면은 문서를 한 번도 건드리지 않는다.

- 두 버튼의 글자와 `aria-label`, `html lang`, 탭 제목(숨은 탭의 `(n)` 표시는 유지)
- 문서의 고정 문구와 `aria-label`·`placeholder`·`alt`. 처음 바꿀 때 한국어 원문을 기억했다가 한국어로 돌아오면 되돌린다.
  대화 말풍선(`.turn`), 대화 목록, 패널 안 서버 내용(`[data-panel-content]`), 답변 모드 버튼, 메뉴·확인 창은 건너뛴다.
- 제목 그림: 두 제목 그림(`title-lettering`, `main-lettering`)은 한국어와 영어 두 벌이다(#122, 아래 「언어별 제목 그림」).
  영어 그림을 받기 전이거나 받지 못하면, 그리고 중국어 화면에서는 그림 자리를 숨기고 바로 뒤 글자 제목을 번역한 글자로 바꾼다.
- 열린 대화 메뉴, 삭제 확인 창, 도착 알림, 테크모 말풍선, 로그인 안내·오류 줄, 인사 줄, 요청 상태 줄(`#status`),
  사진 안내 줄(`#photo-note`, 오류와 「행사를 찾았어요」 같은 결과 안내 모두), 대화 목록, 답변 모드 버튼. 줄마다 마지막 원문을 기억했다가(`say`) 다시 쓰고,
  그 사이 다른 코드가 글을 바꾼 줄은 건드리지 않는다.
- 좁은 화면에서 대기 말풍선을 숨기는 판정은 한국어 대기 문구와 그 번역을 모두 대기로 본다.

### 서버 글과 원문

- 채팅 요청 본문에 `lang`을 싣는다. 값은 보낼 때의 화면 언어이고, SSE(서버가 글을 조각으로 흘려보내는 방식)가 실패해
  JSON 주소로 다시 물을 때도 같은 본문을 쓴다. 답을 기다리는 동안 언어를 바꾸면 다음 질문부터 적용한다.
- 서버가 만든 `answer`·`notice`는 덮어쓰지 않는다. 보류도 서버 문구를 그대로 그린다. 화면 사전은 연결 실패·형식 오류처럼
  화면이 직접 만드는 안내에만 쓴다.
- 인용 카드의 문서명·조문 위치·조문 원문은 번역하지 않는다. 한국어가 아닌 화면에서만 원문 위에 `원문(한국어)` 표시를
  그 언어로 붙이고, 원문 `blockquote`에 `lang="ko"`를 단다.
- 대화 기록에 저장된 예전 질문과 답은 다시 번역하지 않는다. 이미 그린 말풍선의 「다시 시도」 같은 고정 문구도
  그때의 언어로 남고, 새로 그리는 말풍선부터 바뀐다.

### 이번에 옮기지 않아 한국어로 남는 문구

로그인·채팅·메뉴·알림의 문구와 `aria-label`은 모두 옮겼다(`chat_stream.test.mjs`가 `index.html`의 한국어 고정 문구가
모두 사전에 있는지 검사한다). 아래 기능 결과 화면의 세부 문구는 다음 작업으로 남긴다.

- 졸업 체크 결과 표: 열 이름(항목·상태·현재 / 기준…), 상태 배지(충족·부족·확인 필요), 표 제목·안내 문단, 「적용 기준 확인 전」 등
- BISKIT 추천 카드: 「BISKIT 추천 · n점 부족」, 신청·행사 날짜 줄, 마일리지, 대상·마감 확인 필요 배지, 공지·신청 링크 이름
- 사진 행사 카드와 읽은 글자 칸: 확인 단서, 행사일·공식 신청 마감, 마감 불일치 안내, 「사진에서 읽은 글자」·「고쳐서 다시 묻기」 등
- 학사 일정·캠퍼스 안내 패널 안 내용: 학기 제목, 「남은 일정이 없어요」, 장소 항목 이름(지도 번호·운영 시간…), 「목록으로」, 출처 안내
- 날짜 표기: `2026년 11월 26일`처럼 한국어 날짜 꼴로 쓴다.
- 캠퍼스 사진 배경의 장소 이름 자막과, 스크립트를 끈 브라우저의 안내(`noscript`)

## 언어별 제목 글자 그림과 교내 주요 사이트 퀵링크 캐러셀 (#122)

### 언어별 제목 그림

- 영어 그림 두 장(`title-lettering-en.png`·`main-lettering-en.png`)을 배포 준비 때 그린다. 주소는 제목 `img`의 `data-lettering-en`에 적는다.
- 중국어 그림은 이번 이슈에서 뺐다. 글꼴 ZCOOL KuaiLe의 지문(SHA-256, 파일 내용으로 계산한 값)을 아직 고정하지 못했기 때문이다.
  중국어 화면은 늘 글자 제목을 보인다. `letteringSwitcher`는 그림이 있는 언어를 영어 하나로 정해 두어, 중국어 주소 속성이 생겨도 받지 않는다.
  운영자가 글꼴 지문을 확인해 넘겨주면 다음 이슈에서 다시 넣는다.
- 서버는 영어 그림 두 장을 `image/png`로 내주고, 파일이 없으면 404다. 중국어 그림 이름은 허용 목록에 없어 늘 404다. 준비된 그림의 주소에는 HTML 안에서 내용 지문(`?v=`)을 붙인다
  (`FINGERPRINTED_IMAGES`). 그림을 다시 그리면 주소가 바뀌어 브라우저가 옛 그림을 쓰지 않는다.
- 영어로 바꾸면 `chat.js`의 `letteringSwitcher`가 영어 그림을 별도 `Image`로 먼저 받는다. 받은 뒤 요청 번호와 지금 언어가
  둘 다 맞을 때만 `src`와 `alt`를 바꾼다. 제목 그림은 언어별 그림의 원래 비율로 표시한다.
- 받는 중이거나 404·깨짐이면 그림 자리를 숨기고 그 언어의 글자 제목을 보인다. 한국어로 돌아오면 처음 주소와 대체 글을 다시 쓴다.
- ko→en→zh처럼 빠르게 바꾸면 요청 번호가 앞서 나가므로, 늦게 도착한 영어 그림은 버리고 중국어 글자 제목을 남긴다.
- 스크립트가 그림 주소를 바꾸는 곳은 `letteringSwitcher` 하나이고, `setAttribute("src")`로 `data-lettering-en` 주소만 넣는다.
  `.src =` 대입 금지 검사는 그대로 두고, `techmo_assistant.test.mjs`가 이 예외의 자리와 개수를 확인한다.
- 받지 못한 언어 그림은 언어를 다시 고르기 전까지 다시 받지 않는다. 일시적인 실패 뒤 자동으로 다시 받는 일은 다음 작업으로 남긴다.

### 퀵링크 캐러셀 동작

로그인·메인 바닥의 「교내 주요 사이트」 링크 세 줄을 좌우로 넘기는 카드 줄(quick-link carousel, 클래스 접두사 `quicklink-`)로 바꿨다.
사이드바의 작은 링크 세 개(`#sidebar-campus-site-links`)는 그대로다.

- 목록은 `chat.js`의 `quickLinks` 한 곳에 두고 두 바닥(`#login-campus-site-links`, `#main-campus-site-links`)이 같은 카드를 그린다.
  `index.html`에는 빈 카드 줄(`.quicklink-track`)과 숨긴 버튼 두 개만 있다.
- 카드(`a.quicklink-card`)는 선 아이콘 SVG·이름·한 줄 설명·새 창 표시로 이뤄진다. `target="_blank"`, `rel="noopener noreferrer"`이고
  읽기 이름 끝에 화면 낭독용 「(새 창)」이 붙는다. 두 아이콘은 읽지 않는다. 카드는 링크라 Tab으로 차례로 옮겨 간다.
- 에브리타임은 학교 공식 사이트가 아니라 카드에 「외부 서비스」 표시(`.quicklink-badge`)를 붙인다.
- 이름·설명·「외부 서비스」·버튼 이름(`이전 사이트 보기`·`다음 사이트 보기`)은 세 언어 사전에 있다. 언어를 바꾸면 카드를 다시 그린다.
- ‹ › 원형 버튼(`.quicklink-prev`·`.quicklink-next`)은 보이는 폭(`clientWidth`)만큼 `scrollBy`로 부드럽게 넘긴다.
  멈출 자리는 `scroll-snap`이 카드 앞 끝에 맞춘다. CSS `scroll-behavior`는 쓰지 않고, 움직임 줄이기 설정이면 즉시 옮긴다.
- 끝에 닿은 쪽 버튼은 `aria-disabled="true"`이고 눌러도 움직이지 않는다. 카드가 다 보이면 두 버튼을 숨긴다. 끝 판정에는 1px 오차를 허용한다.
- 버튼 상태는 스크롤·크기 변화(`ResizeObserver`, 없으면 창 크기 신호)·언어 변경·화면 전환·첫 화면 복귀 때 다시 잰다.
  숨은 화면처럼 폭이 0이면 판정을 미룬다.
- 터치·트랙패드는 브라우저 기본 가로 스크롤 그대로다. 스크롤 막대는 숨긴다.
- 양 끝은 바닥 면 색에서 투명으로 흐려지는 층을 덮는다. `pointer-events: none`이라 클릭을 막지 않고, 끝에 닿은 쪽 흐림은 지운다.
- 카드와 흐림에는 `transition`을 걸지 않는다. 움직임은 넘김 하나뿐이다.

## 손글씨 입력 필기 패드 (#134)

태블릿에서 질문을 손으로 쓰고, 보내기 전에 인식 결과를 입력창에서 고칠 수 있게 한다. 서버 약속은 API_SPEC.md의
`POST /api/v1/handwriting`이다.

### 와이어프레임 결정

```text
넓은 화면 · 입력 줄 바로 위        좁은 화면(680px 이하) · 하단 시트
┌ 손글씨로 입력 ──────────┐      ┌ 손글씨로 입력 ──────────┐
│        필기 영역         │      │        필기 영역         │
│   읽는 중 / 오류 문구    │      │   읽는 중 / 오류 문구    │
│ 되돌리기 지우기 취소 넣기│      │ 되돌리기 지우기 취소 넣기│
└──────────────────────────┘      └──────────────────────────┘
[사진][펜][ 질문 입력 ][모드][전송]   화면 아래 안전 영역
```

- 펜 버튼(`#handwriting-button`, 이름 「손글씨로 입력」)은 사진 버튼 바로 뒤에 둔다. `.attach-button`을 함께 써서 44×44px 조작 영역과
  경계 3:1을 그대로 받는다. 390px 채팅 화면 입력 줄은 사진·펜·모드 버튼 44px 셋과 보내기를 두고 남는 폭을 질문 칸이 쓴다.
- 패드(`#handwriting-pad`)는 질문 폼 밖, `<main>` 밖의 `role="dialog"` 상자다. 유리 판의 backdrop-filter가 고정 위치의 기준을
  바꾸지 않게 판 밖에 둔다. 넓은 화면에서는 chat.js가 입력 줄 좌표를 재 폭을 맞추고 언제나 바로 위에 놓는다. 위에 자리가 모자라면 위쪽 남은 높이 안에서 스크롤하고, 160px도 안 남으면 문서를 굴려 자리를 만든다(아래 「교차 검토로 고친 점」).
  좁은 화면은 CSS가 폭 전체 시트로 넓히고, 입력 줄 위(자리가 모자라면 굴리거나 줄 아래)에 붙여 입력 줄을 덮지 않는다. 위·아래 모두 모자라거나 입력 줄을 잴 수 없을 때만 화면 아래에 붙이고
  `env(safe-area-inset-bottom)`만큼 아래를 비운다. 테크모(20) 위, 선택 메뉴(30) 아래(25)다.
- 패드는 전환 효과 없이 열고 닫는다. 불투명 면(`--popup`)에 얇은 선(`--line`)만 두르고 그림자는 쓰지 않는다.
- 초점 순서는 펜 버튼 → 캔버스 → 되돌리기 → 지우기 → 취소 → 넣기다. 열면 캔버스로 초점이 가고, Esc·취소는 패드를 닫아 펜 버튼으로 돌려준다.
  열린 동안 펜 버튼을 다시 누르면 캔버스로 초점만 옮긴다(획을 잃지 않게).
- 상태 줄(`role="status"`)은 늘 문서에 있고, 읽는 중이거나 오류일 때만 글이 들어간다. 숨겼다 보이면 읽기 도구가 놓치기 쉽다.

### 그리기

- `touch-action: none`은 캔버스에만 준다. 질문 칸(textarea)에는 덮개·포인터 처리기·touch-action을 두지 않는다.
  iPad 기본 손글씨 입력(Scribble)은 진짜 텍스트 칸에서만 동작하므로, 패드를 쓰지 않는 사람은 질문 칸에 바로 Apple Pencil로 써도 된다.
- Pointer Events로 그린다. 획마다 `setPointerCapture`를 걸고, `getCoalescedEvents`가 있으면 묶인 신호를 모두 점으로 쓴다.
  캔버스 화소는 보이는 크기 × `devicePixelRatio`이고, 획은 CSS 픽셀 좌표로 저장해 되돌리기·크기 변화 때 다시 그린다.
- 굵기는 펜이면 `1.2 + 4 × pressure`px, 압력을 주지 않는 손가락·마우스는 3px이다. 화면 잉크는 캔버스의 글자색(`--ink`)을 따른다.
- 손바닥 거부: 이번 패드에서 펜을 한 번 보면 진행 중인 손가락 획을 지우고(포인터 잡기도 푼다) 이후 손가락은 무시한다.
  패드를 닫았다 다시 열면 처음부터 다시 판단한다. 이미 끝난 손가락 획은 남긴다.
  읽는 동안에는 새 획을 받지 않지만 그 사이 닿은 펜도 기록하므로, 읽기가 실패한 뒤에도 손가락 입력은 계속 무시한다.
- 되돌리기는 마지막 획 하나, 지우기는 모든 획을 지운다. 획이 없으면 되돌리기·지우기·넣기가 잠긴다.

### 넣기

- 잉크 범위(굵기 절반 포함)에 16px 여백을 더해 잘라, 흰 바탕에 검은 잉크로 다시 그린 PNG를 만든다. 화면 테마와 상관없이 같은 그림이 나간다.
  배율은 기기 화소 비율을 따르되 긴 변이 1024px를 넘지 않게 줄인다. `toBlob` 결과가 2,000,000바이트를 넘으면 보내지 않고 안내한다.
- `FormData`로 `image`(handwriting.png)와 `lang`(화면 언어 ko·en·zh)을 보낸다. 경계 문자열은 브라우저가 정하므로 Content-Type을 적지 않는다.
- 읽는 동안 「글씨를 읽는 중…」을 띄우고 넣기·되돌리기·지우기와 새 획을 막는다. 취소는 열어 둔다. 시간 제한은 30초다.
- 취소·Esc는 `AbortController`로 요청을 끊는다. 패드를 열 때마다 회차를 올리므로, 닫은 뒤 늦게 온 응답은 버린다.
- 실패하면 획을 그대로 두고 오류 문구를 띄운 뒤 넣기 버튼으로 초점을 옮긴다. 413은 크기, 422와 빈 글자는 읽지 못함, 503은 지금 읽을 수 없음,
  연결 실패·시간 초과·그 밖의 상태는 각각의 문구다.
- 성공하면 패드를 열기 전에 적어 둔 `selectionStart/End` 자리에 `setRangeText(…, "end")`로 넣는다. 선택한 글자가 있으면 바꾼다.
  `input` 이벤트를 보내 보내기 버튼 상태를 맞추고, 질문 칸으로 초점을 옮긴다. 자동 전송은 하지 않는다. 받은 글자의 앞뒤 공백만 걷는다.
- 그림과 인식 글자는 화면 기록·저장소에 남기지 않는다. 대화 기록에는 학생이 실제로 보낸 질문만 남는다.

### 대비

- 패드 글자(`--ink`)·제목·상태 문구·오류(`--bad`)는 `--popup` 위 4.5:1, 버튼 경계(`--control-line`)·패드 선(`--line`)·캔버스 선은 3:1 이상이다.
  넣기 버튼은 보내기 버튼과 같은 학교 파랑 채움(`--control-start`→`--control-end`)에 흰 글자라 다크에서도 밝은 면을 새로 만들지 않는다.
  `landing_design.test.mjs`가 네 테마에서 계산한다.

### 교차 검토로 고친 점

- 넣기를 누르면 버튼이 잠기면서 브라우저가 초점을 놓친다. 잠그기 전에 취소로 초점을 옮겨 읽는 동안에도 Esc·취소가 듣는다.
- Tab은 가로채지 않는다. 펜 버튼을 누르면 초점이 캔버스로 옮겨 가 펜 버튼 → 캔버스 → 되돌리기 → 지우기 → 취소 → 넣기가 되고,
  넣기 다음은 문서 순서대로 테크모로 나간다. 펜 버튼에서 누른 Tab은 원래대로 질문 칸·답변 모드·보내기로 간다.
  Tab을 이어 붙였더니 입력 줄을 건너뛰거나(펜 버튼 → 캔버스) 입력 줄과 패드 사이를 맴돌아(넣기 → 질문 칸) 둘 다 막혔다.
- 패드를 연 사이 Scribble이나 키보드로 질문 칸의 글이 바뀌어도 지금 커서가 아니라 열기 전에 고른 범위에 넣는다.
  질문 칸의 input 처리기(하나뿐이고 포인터 처리기가 아니다)가 고칠 때마다 고친 직후의 커서를 기준으로 바뀐 구간을 정해 범위를 옮긴다.
  커서 뒤 글자는 그 편집에서 그대로이므로, 같은 글을 앞에 붙였는지 뒤에 붙였는지도 가른다.
  실행 취소·다시 실행은 브라우저가 input 이벤트에 붙이는 입력 종류(`inputType`의 historyUndo·historyRedo)로만 알아보고,
  편집마다 직전 글과 범위를 모두 쌓아 두고, 실행 취소 신호가 오면 지금 글과 같은 가장 최근 기록의 범위로 되돌린다.
  브라우저가 실행 취소를 어떻게 묶는지(이어 친 삭제, 커서 이동, Delete·Backspace)는 추측하지 않는다. 묶는 규칙을 추측했더니 경우마다 어긋났다.
  브라우저가 몇 개를 한 번에 되돌려도 돌아간 글은 기록 가운데 하나다. 실행 취소·다시 실행이 오면 직전 범위를 반대쪽 목록에 먼저 쌓으므로,
  패드를 열기 전 글(기록에 없는 글)로 실행 취소했다가 다시 실행해도 열 때 고른 범위로 돌아온다. 상한은 1,000개이고, 넘치면 패드를 열 때의 첫 기록은 남기고 가장 오래된 중간 기록부터 버린다. 고른 글자를 지웠다 되살려도 범위가 산다.
  브라우저가 이어 친 삭제처럼 여러 편집을 한 번에 되돌리면, 지금 글과 같은 기록을 위에서부터 찾아 그 범위로 돌아간다.
  같은 글이 다시 나왔다는 것만으로는 되돌리지 않는다. 앞에 A를 붙이고 끝의 A를 지운 보통 편집을 실행 취소로 잘못 보기 때문이다.
  고른 범위의 경계에 끼워 쓴 글은 범위 밖이다. 시작 경계에 쓰면 시작을 그 글 뒤로, 끝 경계에 쓰면 끝을 그 글 앞에 두고, 커서만 있었으면 쓴 글 뒤에 둔다.
  input 신호 없이 스크립트가 글을 바꾼 경우에만 아래 글자 비교 방식으로 다시 찾는다.
  후보 자리마다 열기 전 범위 바로 앞 글자(32자까지)와 바로 뒤 글자가 새 글에서 얼마나 이어지는지 세어 가장 많이 이어지는 곳을 고른다.
  고른 글자가 있으면 같은 글자가 나오는 곳만, 커서만 있었으면 모든 자리가 후보다. 같은 글을 통째로 반복해 점수가 같으면
  늘어난 글이 범위 앞에 붙었다고 보고, 원래 자리에서 길이 차만큼 민 곳에 가까운 후보를 고른다.
  그래서 양끝 바깥을 함께 고치거나, 고른 말·커서 앞 말과 같은 말을 맨 앞에 새로 붙여도 원래 범위 쪽에 넣는다.
  이어지는 글자가 하나도 없을 때만 앞뒤 공통 글자로 바뀐 구간을 정해, 앞쪽 자리는 그대로·뒤쪽은 길이 차만큼 밀고·구간 안은 구간 끝으로 보낸다.
- 좁은 화면 서랍을 열거나 첫 화면·채팅 화면을 오가면 입력 줄 자리가 바뀌므로 패드를 닫는다(초점은 옮기지 않는다).
- 로그아웃·둘러보기처럼 기록 계정이 바뀌거나 로그인 화면으로 돌아가면 패드를 닫고 읽던 요청을 끊는다.
  늦게 온 응답은 패드 회차와 계정을 함께 견줘 버리므로 다른 계정의 질문 칸에 들어가지 않는다.
- 읽는 중 Tab으로 질문 칸에 나가도 열린 동안의 Esc는 문서 단계에서 패드를 닫고 요청을 끊는다.
  선택 메뉴·확인 창처럼 Esc를 먼저 처리한 곳은 건드리지 않는다.
- 획이 캔버스 밖으로 나갔다 돌아와도 서버로 보내는 그림은 보이는 칸 안만 잘라 그린다. 잉크가 모두 칸 밖이면 보내지 않고 읽을 글씨가 없다고 알린다.
  자르기 범위도 선분을 잘라(Liang–Barsky 선분 자르기) 보이는 조각만 세므로, 칸 밖 점이 그림 높이·너비를 늘리지 않는다.
  잉크는 중심선에서 굵기 절반만큼 퍼지므로 칸을 그만큼 넓힌 상자로 자른다. 중심선이 칸 바로 밖이어도 칸 안에 보이는 잉크는 남는다.
- 사이드바에서 새 대화나 다른 대화를 열거나, 첫 화면의 「새 대화」를 누르거나, 보고 있던 대화를 지우거나 기록을 모두 지우면 패드를 닫는다.
  질문을 보내면 같은 대화든 새 대화든 닫는다. 쓰던 초안이 끝났으므로 늦은 인식 글자가 비운 질문 칸(다음 질문의 초안)에 들어가면 안 된다. 패드는 연 순간의 계정·대화에 묶여, 넣기를 누를 때 그 대화가 아니면 보내지 않고 닫는다.
- 넓은 화면의 패드는 화면에 고정돼 있으므로 문서나 안쪽 칸이 스크롤되면(캡처 단계 scroll 신호) 입력 줄 바로 위로 다시 옮긴다.
  입력 줄이 화면 밖으로 나가도 패드는 위아래 8px 안에 남긴다.
  수용 조건대로 넓은 화면에서는 언제나 입력 줄 위에 연다. 연 뒤 학생이 스크롤해 입력 줄이 화면 위쪽에 붙어 위쪽이 160px보다 좁아지고
  아래쪽이 더 넓을 때만 줄 아래로 옮겨(위 끝 고정) 필기 칸과 버튼이 0px로 접히지 않게 하고, 다시 자리가 나면 위로 돌아온다. 아래 끝은 입력 줄 위 8px에 묶되 화면 안(위아래 8px)에 가두고,
  최대 높이는 입력 줄 위쪽 남은 높이와 화면 안 남은 높이 중 작은 쪽이다. 그래서 입력 줄이 스크롤로 화면 아래로 내려가도 패드는 화면 아래 끝에 머물러
  버튼이 화면 밖으로 나가지 않고, 상태 줄이 생겨도 입력 줄을 덮지 않는다. 위쪽이 필기 칸 최소 높이(160px)보다 좁으면 열 때 한 번, 문서를 모자란 만큼
  위로 굴려 자리를 만든다. 실제 화면에서는 입력 줄 위에 머리글(76px 이상)이 있어 문서 맨 위에서 위쪽이 그보다 좁아지지 않는다.
  질문 칸을 늘리거나 판 폭이 바뀌어 입력 줄·필기 칸 크기만 바뀔 때도 크기 변화(ResizeObserver)를 받아 다시 놓고 그리기 버퍼를 새 크기에 맞춘다. 위에 놓을 때는 아래 끝(`--handwriting-bottom`)을,
  아래에 놓을 때는 위 끝(`--handwriting-top`)을 입력 줄에서 8px 띄워 묶고, 그 쪽 남은 높이를 최대 높이(`--handwriting-max-height`)로 준다.
  상태 줄이 생겨 내용이 커져도 패드는 입력 줄 쪽으로 밀려나지 않고 안에서 스크롤된다. 상태 줄이 바뀔 때마다 자리를 다시 잰다.
- 좌표는 그대로이고 압력만 바뀐 펜 신호는 길이 0인 선이라 캔버스가 그리지 않는다. 그런 조각은 점으로 찍어 화면과 보내는 그림 모두에 남긴다.
- 열린 채 테마가 바뀌면 `applyTheme`이 패드를 불러 이미 쓴 획을 새 글자색으로 바로 다시 그린다. 다음 획을 기다리지 않는다. 넣기를 누른 뒤 계정이나 보고 있는 대화가 바뀌면 응답을 받을 때 패드를 닫고 버리므로,
  인식 글자는 넣기를 누른 대화의 질문 칸에만 들어간다.
- 대화 상자 전체에 `aria-busy`를 걸지 않는다. 걸면 읽기 도구가 안의 상태 줄 안내(「글씨를 읽는 중…」)를 미룰 수 있다.
  성공하면 패드와 함께 상태 줄도 사라지므로, 「읽은 글자를 입력창에 넣었어요」는 늘 문서에 있는 알림 줄(`#conversation-announce`)에 남긴다.
- 회전·창 크기 변화로 캔버스가 바뀌어도 그리던 획은 끝내지 않는다. 그 뒤 브라우저가 포인터를 취소하면 그 획을 찾아 버린다.
- 점은 캔버스 왼쪽 위 기준 CSS 픽셀로 저장하고, 칸 크기가 바뀌어도 배율을 곱하지 않는다. 600px 칸의 x=110 점은 400px로 줄여도
  x=110에 있고, 지금 칸 밖으로 나간 잉크만 가려진다(보내지도 않는다). 예전의 "본 적 있는 가장 큰 칸" 배율 방식은 줄일 때 점을 밀어
  (110→73.3) 없앴다.
- 점마다 그 점을 찍을 때 보이던 칸을 함께 저장하고, 화면에 그릴 때와 보내는 그림을 만들 때 선분마다 그 칸으로 캔버스 `clip()`을 건 뒤 그린다.
  잉크 범위 계산도 같은 칸 안으로 가둔다. 그래서 칸을 넓혀도(읽기 실패 뒤든 긋는 도중이든) 그을 때 보이지 않던 픽셀
  (칸 밖으로 그은 부분, 경계에 걸친 둥근 끝·굵기 절반)은 화면에도 그림에도 나타나지 않는다.
  예전에는 그리던 획의 칸을 새 칸으로 넓혀, 떼기 전에 넓히면 잘린 3px이 되살아났다(87→93).
  선분은 끝 점을 찍을 때(그 선분을 그을 때)의 칸으로 자른다. 긋는 도중 칸을 넓히면 이미 저장한 점·선분은 옛 칸 그대로이고,
  넓힌 뒤 그은 선분은 앞 점이 옛 경계 바로 안(599.9)에 있어도 새 칸에서 굵기 전체가 보인다. 칸 밖에 나갔다 들어온 자리에서는 앞 조각과 잇지 않는다.
  앞 포인터 자리가 그때 칸 밖이었고 그 사이 칸이 바뀌었으면(넓힘·줄임·패드 스크롤), 그 자리에서 출발하는 선분은 옛 칸과 지금 칸이
  겹치는 곳에서만 자르고 그린다. 600→750에서 x=700·800에서 돌아와도 새로 드러난 600~750에는 선이 생기지 않고, 옛 경계에서 (590,130)으로
  돌아온 부분과 끝 점은 남는다. 왼쪽 밖 x=−100에서 600→400으로 줄였다 돌아오면 겹치는 400 칸 안의 복귀선을 그린다.
  예전에는 경우마다 규칙(선분 버리기, 점 찍고 다시 시작)을 따로 붙여 새 경우마다 잉크가 빠지거나 생겼다. 이제 "그 선분이 지나는 동안 계속 보였던 곳"
  한 가지 규칙만 쓴다. 칸이 바뀌었는지는 값으로 비교한다. 600→400→600처럼 같은 크기로 돌아오면 바뀌지 않은 것으로 본다.
- 보이는 칸은 캔버스 ∩ 패드 스크롤 상자 안쪽 ∩ 화면(세로)이다. 위쪽이 좁아 패드 안이 스크롤되면 캔버스 위·아래가 가려지는데,
  펜을 댄 채 가려진 곳으로 끌어도 그 잉크는 기록하지 않는다. 패드를 스크롤해 가려졌던 곳이 보여도 잉크가 새로 나타나거나 서버로 가지 않는다.
  가로는 캔버스 폭이 100%라 가려지지 않는다. 패드 안쪽 스크롤은 패드를 옮기지 않고 보이는 칸만 다시 잰다.
  보이는 띠는 쓸 때만 쓴다(점마다 저장). 보내는 그림은 지금 캔버스 전체 크기로 자르므로, 넣기 버튼까지 스크롤해 위쪽 획이 가려져도 그 획은 그대로 간다.
  두 띠가 겹치지 않으면(0~50 → 52~100) 그 사이 선분은 넓이 없는 칸으로 보고 그리지 않는다. 높이가 음수인 사각형으로 clip()하면 캔버스가 틈에 잉크를 그리기 때문이다.
  칸이 바뀐 직후 선분 끝에는 좌표를 따지지 않고 늘 지금 칸으로 끝 점을 제 굵기로 새로 찍어 다시 시작한다(끝 점이 지금 칸에서 보일 때).
  예전에는 "선이 끝 점에 닿았나·앞 점과 좌표가 같나"로 갈랐는데, 실제 그리기는 겹치는 칸으로 잘리므로 닿았다고 판단해도
  새 칸에서는 보이지 않았다(600→750 뒤 (601.5,130), 스크롤 뒤 같은 자리 (100,52.4)). 같은 자리에 한 번 더 찍어도 모양은 바뀌지 않는다.
- 크기 감시(`ResizeObserver`)는 지켜보기 시작할 때와 패드를 보일 때 크기가 그대로여도 첫 알림을 보낸다. 입력 줄의 자리·크기나 캔버스 크기가
  마지막으로 잰 값과 다를 때만 자리를 다시 재므로, 첫 알림만으로는 입력 줄 위에 연 패드가 아래로 옮겨 가지 않는다.
  연 뒤 자리를 다시 재는 길은 `relayout` 하나다. 문서·패드 안쪽 스크롤, 크기 감시 알림, 창 크기 변화, 질문 칸 입력·첨부 변화가 모두 이 함수를 거친다.
  입력 줄 자리·크기, 캔버스 크기, 창 크기가 그대로면 아무것도 하지 않는다. 신호마다 비교를 따로 붙이다 빠뜨려, 바뀐 것 없이 패드가 줄 아래로 옮겨 가는 결함이
  첫 알림·글자 입력·패드 안쪽 스크롤에서 차례로 되풀이됐기 때문이다.
- 첨부 제거 버튼처럼 입력 줄 크기는 그대로인 채 자리만 바뀌는 변화는 크기 변화 신호가 오지 않는다. 그래서 첨부 상태를 바꾸는 한 곳(`updateSend`)이
  열린 패드 자리를 바로 다시 재고(`placeHandwritingPad`, 그리기 버퍼는 건드리지 않음), 질문 폼 전체 크기도 함께 지켜본다.
- 획의 첫 점과 다시 시작한 점은 그 점의 굵기로 점을 찍어 다시 그린 화면과 보내는 그림에도 남긴다. 세게 눌러 시작해 약하게 이어 간 획의
  첫 점(반지름 2.6px)이 다시 그릴 때 빠지던 결함을 막는다.
- 경계에 정확히 닿은 점(경계에서 잘라 저장한 끝점)은 폭이 0이어도 범위 계산에 넣는다. 빼면 선분 한쪽 끝만 남아 그림이 줄어든다.
- 경계 결함이 되풀이된 공통 원인은 두 가지였다. 하나는 화면의 칸 모양이 코드가 계산하는 칸과 달랐던 것이다.
  캔버스 자체에 1px 테두리와 10px 둥근 모서리가 있어, 브라우저가 모서리 잉크를 가리고 그리는 칸도 잰 사각형보다 작았다.
  다른 하나는 그리기·자르기·범위 계산이 압력에서 굵기를 각자 다시 계산한 것이다(큰 쪽, 평균, 새 점 하나).
- 그래서 둥근 모서리를 계산으로 흉내 내지 않고, 칸 모양 자체를 사각형으로 바꿨다. 테두리와 둥근 모서리는 캔버스를 감싼 판(`.handwriting-well`)에만 둔다.
  판 안쪽 여백 3px는 안쪽 곡선(반지름 9px)이 캔버스 모서리에 닿지 않는 최소값 약 2.64px보다 크다.
  이제 캔버스에 보이는 칸은 `getBoundingClientRect` 사각형과 같고, 모서리 끝에 찍은 점도 화면에 보이는 그대로 보낸다.
- 굵기는 긋는 순간 선분마다 한 번 정해 점에 `w`로 적고, 그리기·자르기·범위 계산이 모두 이 값을 읽는다(`handwritingDrawnWidth`).
  칸 경계에서 잘라 만든 점도 자르기 전 선분 굵기를 그대로 가진다. 그래서 세게 누르다 약하게 경계 밖을 오가도 굵기가 바뀌지 않고, 칸 안 잉크가 남는다.
- 칸에 닿는지는 굵기만큼 넓힌 상자가 아니라 칸까지의 실제 거리로 따진다. 줄인 칸 밖의 선만 남았을 때는 빈 흰 그림을 보내지 않고 「읽을 글씨가 없어요」를 띄운다.
- 화면 픽셀을 읽어 범위를 정하는 방식(`getImageData`)도 검토했다. 표준 기능이지만 가짜 캔버스로는 픽셀을 검사할 수 없어 테스트로 지키기 어렵다.
  칸이 사각형이 된 지금은 거리 계산이 정확하므로 쓰지 않았다.
- 획을 긋는 동안 휠·스크롤로 패드가 움직일 수 있어, 포인터가 움직일 때마다 캔버스의 화면 위치를 다시 재서 점을 캔버스 좌표로 바꾼다.
- 브라우저가 포인터를 취소하면(`pointercancel`, 손바닥·스크롤 몸짓 판정 등) 쓰다 만 그 획은 버린다. 손을 뗀 획(`pointerup`)만 남는다.
- 넣기를 누르면 그 순간 그리던 획을 끝낸다. 다른 손가락으로 넣기를 누른 채 펜이 닿아 있어도 그 뒤 움직임은 획에 붙지 않아, 화면과 보내는 그림이 같다.
  창 크기 신호는 테크모 resize 처리기 하나가 받아 `refreshHandwritingPad()`를 부른다. 처리기를 따로 늘리지 않는다.
- 획을 시작할 때도 잉크색이 바뀌었는지 한 번 더 보고, 다르면 기존 획을 다시 그린다.
- 좁은 화면(680px 이하) 시트는 폭 전체를 쓰고, 입력 줄을 덮지 않게 다음 순서로 놓는다. 채팅 화면은 입력 줄이 화면 아래에 있어,
  시트를 `bottom: 0`에 두면 390×844에서 질문 칸과 입력 줄 버튼을 덮어 누를 수 없었다.
  1) 열 때 입력 줄 위쪽이 최소 높이(160px)보다 좁으면 문서를 굴려 자리를 만든다(넓은 화면과 같은 `makeRoom`).
  2) 위쪽이 160px 이상이면 줄 바로 위, 3) 아니고 아래쪽이 160px 이상이면 줄 바로 아래, 4) 둘 다 모자라면 더 넓은 쪽(96px 이상일 때),
  5) 그마저 없으면 화면 아래 시트(안전 영역만큼 띄움).
  예전에는 좁은 화면에서 늘 줄 위에 두어, 390×500에서 입력 줄이 화면 위 20px에 있으면 시트 최대 높이가 4px로 접혔다.
  줄 위·아래에 둘 때는 입력 줄이 아래 안전 영역을 비우므로 시트 아래 여백은 14px다. 입력 줄을 잴 수 없을 때도 화면 아래에 붙인다.
  줄 아래 자리는 입력 줄 아래 끝이 아니라, 사진을 붙이면 그 바로 아래에 나타나는 「첨부 제거」 버튼 아래 끝부터 잰다(넓은 화면도 같다).
  예전에는 390×500에서 시트가 입력 줄 아래 8px에 붙어 그 버튼을 덮었다. 버튼이 나타나고 사라지는 것도 자리 재기 비교 값에 넣는다.
- 패드를 연 채 질문 칸에서 고른 범위 안쪽을 건드리면 범위를 넓히지 않고 바뀐 구간 끝 한 점으로 접는다.
  고른 글자 일부라도 지운 편집: 「ABCD」에서 B를 고른 뒤 BC를 XY로 바꾸고 OCR을 넣으면 「AXYOCRD」다(예전에는 「AOCRD」).
  고른 범위 안쪽(경계가 아닌 자리)에 끼워 넣은 글: 「ABCD」에서 BC를 고른 뒤 B와 C 사이에 X를 쓰면 「ABX가상CD」다(예전에는 「A가상D」).
  범위 바로 앞·뒤 경계에 끼워 넣은 글은 예전처럼 범위 밖으로 둔다.
- 무엇이 바뀌었는지는 먼저 브라우저가 알려 준 값으로 정한다. 질문 칸에 입력이 들어오기 직전(`beforeinput`)의 선택 범위가 곧 바뀔 범위다.
  질문 칸에는 처리기를 달지 않고(Scribble 보존 조건) 문서 캡처 단계에서 읽기만 한다. 편집 전후 글자 비교는 이 값이 없을 때
  (선택 없이 Backspace·Delete로 지울 때, 패드를 연 뒤 신호 없이 글이 바뀔 때)만 쓴다. 글자 비교로는 결과 글이 같은 편집을 가를 수 없어,
  「ABCD」에서 B를 다시 골라 「BXY」를 붙여넣으면 새 B를 옛 B로 보고 지웠다(「A가상XYCD」). 이제 「ABXY가상CD」다.
  편집 전후 글이 같아도 브라우저가 교체 범위를 알려 줬으면 편집으로 본다. B를 다시 골라 같은 「B」를 붙여넣으면 「AB가상CD」다
  (예전에는 글이 같다는 이유로 범위 정보를 보기 전에 끝나 「A가상CD」). 범위 정보 없이 같은 글로 온 신호는 예전처럼 무시한다.
- 좁은 화면에서 위·아래 모두 160px에 못 미쳐도 더 넓은 쪽이 96px 이상이면 그쪽에 두고 패드 안에서 스크롤한다.
  화면 아래 시트는 질문 칸과 「첨부 제거」 버튼을 덮으므로 위·아래 모두 96px에 못 미칠 때만 쓴다.
  예전에는 둘 다 160px 미만이면 곧장 화면 아래 시트로 가, 질문 칸을 100px로 늘리고 사진을 붙인 390×500(위 154px·아래 146px)에서 입력 줄을 덮었다.
- 상태 200을 받은 뒤 본문을 기다리는 동안 시간 제한(30초)이 지나면 시간 초과 문구를 띄운다. 본문 받기(`text()`)와 JSON 해석을 나눠,
  받는 도중의 실패는 시간 초과·연결 문구로, 받은 본문이 JSON이 아닐 때만 「서버가 글씨를 처리하지 못했어요」로 알린다.
- 후속 확인: 폭 600px에서 압력 0.1로 x=600.5까지 긋고 펜을 댄 채 750px로 넓힌 뒤 압력만 1로 올리면, 마지막 잉크를 600 칸으로 자르되
  굵기가 늘어난 만큼 옛 경계 안쪽 픽셀이 조금 늘어난다. 이번 PR에서는 고치지 않고 남긴다.
- 펜을 떼는 신호(`pointerup`)의 좌표도 획에 잇는다. 마지막 이동 신호와 떼는 자리가 다르면(브라우저가 이동을 묶어 보내거나 빠르게 뗄 때) 그 선분이 빠졌다.
  펜이 움직였는지는 이동·떼기 모두 화면 좌표로 가린다. 화면 좌표가 마지막 신호와 같으면(압력만 바뀐 신호) 선분 처리(자르기·칸 비교)를 아예 타지 않는다.
  새 위치를 만들지 않고, 이미 기록한 마지막 잉크가 마지막 포인터 자리에 있을 때만 그 잉크를 기록할 때의 칸으로 굵기를 갱신한다. 떼기라면 아무것도 더하지 않는다.
  예전에는 압력만 바뀐 신호도 선분 처리를 타서, 스크롤 뒤에는 가짜 선이, 칸을 넓힌 뒤에는 옛 칸 밖 자리(600 칸의 x=700)에 새 점이 생겼다.
  펜이 화면에서 실제로 움직인 신호는 지금 캔버스 위치로 잰다.
  펜은 뗄 때 압력을 0으로 보내므로 이 마지막 선분은 앞 신호의 압력으로 그려 끝이 가늘어지지 않게 한다. 포인터 잡기를 잃은 신호(`lostpointercapture`)는 좌표를 더하지 않는다.
- 읽기 실패 뒤의 오류 문구는 새 획을 시작할 때가 아니라 펜을 뗀 뒤(모든 획이 끝났을 때) 지운다. 누르는 순간 지우면 상태 줄이 사라져 패드가 줄고
  캔버스가 움직이는데, 움직인 위치로 이미 누른 점을 재서 첫 점이 위로 밀려(20px 이동이면 y=5 → −15) 잘렸다. 이제 긋는 동안 캔버스는 움직이지 않는다.
- 200 응답의 본문이 JSON이 아니거나 그림을 만들지 못하면 연결·크기 문구 대신 「서버가 글씨를 처리하지 못했어요」를 띄운다.

## 질문 수정·다시 답하기와 답변 버전 (#140)

팀 피드백(2026-11-18) 5단계다. 질문을 고치거나 답을 다시 받아도 이전 질문과 답을 버전으로 남기고 `‹ 1/2 ›`로 넘겨 본다.
동작과 기록 형식은 `chat.js`가, 모양은 `chat.css` 끝의 #140 절이 맡는다. 서버 API는 바꾸지 않는다.

### 와이어프레임

이슈 #140의 와이어프레임은 「수정」을 질문 옆에 두었다. 실제 화면(`chat.js`)은 수정·다시 답하기·버전 선택을 답 아래 조작 줄 하나에 모으고,
실패 문구는 편집 폼 밖, 조작 줄 바로 다음에 둔다. 아래 그림은 그 실제 배치다.

```text
                                  내 질문
아이오 답변 · 출처
[‹] 1/2 [›]          [수정] [다시 답하기]

수정 중
                [기존 질문을 채운 입력 칸 ]
                       [취소] [저장하고 묻기]
[‹] 1/2 [›]          [수정] [다시 답하기]

실패 뒤
                [고친 초안이 남은 입력 칸 ]   ← 편집 칸 선만 위험 색
                         [취소] [다시 시도]
[‹] 1/2 [›]          [수정] [다시 답하기]
[답을 받지 못했어요 …                     ]   ← .version-error
```

- 넓은 화면은 조작 줄 한 줄에 항목을 양 끝으로 벌려 둔다(`justify-content: space-between`, 줄 폭은 답 말풍선과 같은 670px).
- 390px 이하에서는 조작 줄의 항목이 말풍선 아래 한 줄씩 내려가고, 버전 선택은 화살표를 양 끝에, 편집 폼의 취소·저장하고 묻기는 같은 폭으로 나눈다.
- 편집 폼은 질문 말풍선 자리에 오른쪽 정렬로 놓이고 폭은 질문 말풍선과 같은 530px까지다.
- 실패 문구는 조작 줄과 8px 띄우고 폭은 조작 줄과 같은 670px까지다.
- 680px 이하에서 대화 칸(`.transcript`)은 좌우 여백이 0이고 가로 넘침을 숨긴다. 차례 밖으로 나간 선은 잘리므로,
  조작 줄 안쪽에 6px 여백을 두고(위쪽 간격은 8px에서 2px+6px로 그대로 유지), 대기 점선은 조작 줄 상자 안쪽에 긋는다.
  초점 고리가 닿는 거리는 간격 2px와 굵기 2px를 더한 4px라 이 여백 안에 들어간다.
  편집 폼은 안쪽 여백이 12px이라 그 안의 초점 고리가 폼 밖으로 나가지 않는다.

### 모양과 상태

- 대화 칸은 사진이 비치는 반투명 면이라 버튼·버전 번호·편집 폼·실패 문구를 모두 불투명한 `--surface` 위에 그린다. 글자 대비는 그 `--surface` 위에서 잰다.
- 조작 줄(`.turn-actions`)과 편집 폼(`form.turn-editor`)도 불투명 `--surface` 면이다. 그래서 버튼 경계·편집 칸 선·초점 고리·대기 점선은
  사진에 닿지 않고 언제나 `--surface`(또는 버튼 자신의 바탕)와 맞닿는다. 편집 폼에는 바깥 선을 긋지 않는다.
  반투명 대화 면 너머의 사진은 색을 정할 수 없다. 덮개가 가장 옅은 화면 높이 42% 지점(`--overlay-mid`)에서는 다크 화면에 밝은 사진이 깔리면
  대화 면이 상대 휘도 약 0.1까지 밝아진다. 그 면과 hover 경계가 약 2.97:1이었다(교차 검토 지적).
  그 전에는 선 색을 바꿔(`--control-line` → `--text-muted`) 단색 대체 배경과의 대비만 맞췄는데, 사진마다 다시 떨어질 수 있어 면을 깔아 끊었다.
- 버튼은 높이·폭 44px 이상, `1px solid var(--text-muted)` 경계, 굵은 본문색 글자다. hover는 경계를 `--focus-ink`, 바탕을 `--tint`로 바꾼다.
- 저장하고 묻기(실패 뒤 다시 시도 포함)는 `--accent` 채움에 `--surface` 글자다. 라이트는 학교 파랑 위 흰 글자, 다크는 밝은 하늘색 위 짙은 판 색 글자다.
  채움이 곧 경계라 채움 색이 둘레 `--surface`와 3:1을 넘는다. hover는 밑줄로 알린다. 채움 위에 다른 색 선을 그으면 라이트에서 약 2.2:1이고,
  채움을 본문색으로 바꾸면 다크에서 밝은 면이 새로 생기기 때문이다.
- 초점은 공통 2px `--focus-ring` 고리를 버튼에서 2px 띄워 그리고, 그림자 띠는 깔지 않는다(#140 그림자 금지).
  처음에는 `box-shadow`로 `--surface` 6px 띠를 깔았는데 그림자 금지 규칙에 어긋났다(교차 검토 지적).
  고리 양옆에는 조작 줄이나 편집 폼의 `--surface`만 닿는다. 라이트 남색 고리와 다크 흰 고리는 그 면과 3:1을 넘는다.
- 잠긴 버튼(끝 버전 화살표, 답을 받는 동안의 수정·다시 답하기·버전 버튼)은 공통 `opacity: .65`를 되돌리고 `--text-muted` 글자와 점선 경계로 보인다. 반투명으로 흐리면 글자 뒤로 사진이 비친다.
- 기본: 위 모양 그대로다.
- pending: 잠긴 조작 줄(`.turn-actions`)을 `1px dashed var(--text-muted)` 외곽선으로 상자 안쪽(-1px)에 두르고, 잠긴 버튼에 기다림 커서를 보인다.
  첫 답 전에 정지한 기록은 답 없이 질문만 복원되어 `.reply`가 없지만 조작 줄은 있으므로 조작 줄에 긋는다.
  처음에는 차례 밖 4px에 그었는데 좁은 화면에서 좌우가 잘렸다(교차 검토 지적). outline은 자리를 차지하지 않아 상태가 바뀌어도 줄이 밀리지 않는다.
  움직이는 표시는 넣지 않는다. 이미 있는 버전 글은 그대로 읽힌다.
- failed: 폼 안 `--surface`에만 닿는 편집 칸(`textarea`) 선을 `--danger`로 바꾼다.
  조작 줄 다음의 `.version-error`는 바깥 선 없이 `--surface` 면에 `--danger` 글자로 쓴다.
  예전에는 폼 바깥 선을 `--danger`로 그어 남색 대체 배경 위 대화 면과 약 2.9:1이었다(교차 검토 지적).
- 그림자·그라데이션·이모지·새 움직임(transition·animation)은 없다. 색은 #131 토큰만 쓴다.

### 배치

- 주 줄(`.acal-week`)은 `repeat(7, minmax(max(44px, 2.75rem), 1fr))` 열과 `2.25rem 1.375rem 1.375rem minmax(1.375rem, auto)` 행이다(기본 글꼴 16px에서 36·22·22px).
  날짜 칸은 네 행을 모두 덮고(`grid-row: 1 / 5`), 숫자는 1행, 막대는 2·3행, 「+N개」는 4행이다.
- 날짜 버튼 안도 같은 행 격자다(`calc(2.25rem - 2px) 1.375rem 1.375rem`, 첫 행만 위 테두리 2px를 뺀다). 그래서 버튼 4행이 주 줄 4행과 같은 높이에서 시작하고,
  「+N개」(`grid-row: 4`)는 글꼴 크기와 상관없이 두 번째 막대 아래에 놓인다. 점 묶음은 5행이다. 「+N개」가 두 줄이면 버튼 내용이 늘고, 칸이 덮은 주 줄 4행(auto)이 함께 는다.
- 오늘 원 지름은 1.75rem과 칸 안쪽 폭(버튼 테두리 안에서 좌우 2px씩 띄운 폭) 가운데 작은 값이다. 좌우를 2px에 걸고(`inset-inline: 2px`)
  `max-width: 1.75rem`과 `margin-inline: auto`로 가운데 두며, 높이는 `aspect-ratio: 1`로 폭을 따른다. 세로 중심은 숫자 행 가운데(`translate: 0 -50%`)다.
  처음에는 지름이 1.75rem 고정이라 기본 글꼴 32px에서 56px(테두리 포함 60px)가 되어 44px 칸과 오른쪽 여백을 넘었다(교차 검토 지적).
  `test_today_circle_fits_the_cell_at_any_text_size`가 기본 글꼴 16·24·32·48px와 그 글꼴의 가장 좁은 칸·60·80·120px에서 원이 칸과 숫자 행 안에 들고 가운데에 오는지 계산한다.
- 행 높이·줄 높이·오늘 원 최대 크기는 rem이라 브라우저 기본 글꼴을 키우면 함께 커진다. 처음에는 px 행에 flex 열 끝으로 「+N개」를 밀었는데(`margin-top: auto`),
  칸 내용이 네 행보다 짧으면 4행이 늘지 않아, 기본 글꼴 32px의 영어 화면에서 두 줄 「+10 more」가 64px에서 시작해 두 번째 막대(59~79px)에 가렸다(교차 검토 지적).
  `test_more_label_never_overlaps_the_second_bar_at_any_text_size`가 기본 글꼴 16·24·32·48px에서 실제 선언의 px·rem·calc·max를 풀어 「+N개」 위 끝과 두 번째 막대 아래 끝을 비교한다.
- 44px 칸에서 「+N개」가 쓸 수 있는 글 폭은 36px(좌우 안쪽 여백 2px·테두리 2px)다. 영어 「+10 more」는 약 57px라 칸 안에서 두 줄로 나누고,
  띄어 쓰지 않은 긴 글도 글자 단위로 끊는다(`white-space: normal`, `overflow-wrap: anywhere`, `max-width: 100%`). 4행은 `minmax(1.375rem, auto)`라 두 줄이면 주 줄이 늘어난다.
  처음에는 `nowrap`이라 영어 화면에서 이웃 칸의 「+N more」와 겹쳤다(교차 검토 지적). `test_more_label_wraps_inside_a_44px_cell_in_every_language`가
  ko·en·zh 글 폭을 넉넉하게 어림해 선언에서 계산한 칸 폭과 비교한다.
- 막대 위치는 인라인 style 없이 `data-col` → `grid-column-start`, `data-span` → `grid-column-end: span N`, `data-lane` 0·1 → `grid-row` 2·3 선택자로만 정한다.
  페이지 보안 정책이 `default-src 'self'`이고, 선언만 읽어도 배치를 검사할 수 있어서다. 막대는 칸 위에 겹쳐 그리고 `pointer-events: none`이라 막대를 눌러도 그 아래 날짜가 골라진다.
- 긴 이름은 막대 끝에서 잘린다. 말줄임(`text-overflow`)은 전역 검사(`motion_layout.test.mjs`)가 두 요소 밖에서 막아 쓰지 않는다. 전체 이름은 고른 날 목록에 있다.
- 좁은 패널 전환은 화면 폭이 아니라 `.acal`의 안쪽 폭으로 한다(`@container acal (width < 560px)`). 막대·점·고른 날 목록은 스크립트가 늘 함께 그리고,
  좁으면 막대를 숨기고 날짜 버튼 아래 줄에 점을 보인다. 고른 날 목록은 두 폭 모두 보인다.

### 색과 대비

- 헤어라인은 `color-mix(in srgb, var(--text) 9%, transparent)`(`--acal-line`)이다. 장식 선이라 3:1 대상이 아니고, 날짜 칸은 숫자와 자리로 알아본다.
  3:1은 머리 버튼 경계(`--text-muted`, hover `--focus-ink`, 눌림 `--accent`), 선택 테두리(`--accent`), 초점 고리(`--focus-ring`), 오늘 원 선(`--accent`)에 건다.
- 배경으로 쓰는 새 색은 맨 위 세 색 블록의 6자리 색 이름표다(`--acal-weekend`, `--acal-today-fill`, 분류별 `-bg`·`-ink`·`-dot`).
  `landing_design.test.mjs`의 다크 밝은 면 검사는 배경 변수를 그 블록에서만 풀고 `color-mix`의 비율을 읽지 않아, 틴트를 `color-mix(var(--text) …)`로 쓰면 다크에서 밝은 면으로 잡힌다.
- 다크의 칩 글자색은 휘도 .5를 넘어 점 배경으로 쓰면 밝은 면이 된다. 그래서 점은 따로 중간 밝기 색(`-dot`)을 둔다.
- 분류 칩 글자와 채움의 대비(손 계산, 소수 첫째 자리 반올림)는 다음과 같다. 테스트는 이 표를 옮겨 적지 않고 선언에서 다시 계산한다.

### 움직임

- 새 transition·animation은 없다. 달 이동과 보기 전환은 바로 다시 그린다. 움직임 줄이기 설정에서 끌 것이 없고, reduced-motion 블록 수(3개 고정)도 늘리지 않는다.
  처음에는 날짜 버튼과 머리 버튼에 120ms 색 전환을 두었는데, 전역 검사가 대화 목록 서랍과 카드 밖의 transition을 막아 뺐다.

### 검사

- `api/tests/test_academic_calendar_style.py`가 `chat.css`의 #143 절을 작은 선택자 판정기로 가상 요소(날짜 칸·날짜 버튼·막대·점·머리 버튼·고른 날 목록)에 걸어
  실제 선언을 모은다. 사용자 변수와 `color-mix`도 물려받은 값으로 풀어 라이트·다크(속성)·다크(시스템) 대비를 계산한다.
- 같은 파일이 7열·44px, `data-col`·`data-span`·`data-lane` 전 범위의 배치, 9% 헤어라인, 주말 틴트, 이웃 달 흐린 글자, 오늘 원, 안쪽 초점 고리와 선택 테두리,
  7칸 최소 폭 아래 요일 머리·격자 함께 스크롤, 기본 글꼴 16·24·32·48px에서 두 자리 날짜·오늘 원·「+N개」가 칸과 행 안에 드는지(`test_two_digit_date_stays_on_one_line_inside_the_circle_at_any_text_size` 등), 좁은 패널의 막대↔점 전환, 목록 보기 전환, 움직임 없음, 토큰만 쓴 색, 세 색 블록의 새 이름표 순서를 본다.
- 판정기는 자식(`>`)과 자손을 구별하고 `:has(…)`를 가상 요소의 표시로 읽는다. 가상 요소는 `chat.js`의 실제 구조(루트 직속 머리 줄·본문 상자·고른 날 목록, 월 보기 `.acal-body` 안 요일 머리·격자,
  버튼 안 숫자 → 「+N개」 → 점 묶음, 고른 날 목록 안 `section.evidence`)를 따른다.
- 교차 검토로 고친 점: 달 보기에서 고른 날 일정까지 접던 규칙, 점 묶음에 걸려 「+N개」가 막대에 가리던 `:last-child` 규칙,
  요일 머리와 어긋나던 격자 스크롤, 그리고 본문 상자를 놓쳐 달력 전체가 밀리던 루트 스크롤.
  처음 판정기는 `>`를 자손처럼 보고 「+N개」를 마지막 자식으로 꾸몄고, 다음 판은 요일 머리를 루트 직속으로 꾸며 결함을 잡지 못했다.
- 반복된 공통 원인은 테스트가 선언 값만 확인하고, 그 선언이 실제 화면 구조에서 어떤 동작을 낳는지는 재지 않았다는 점이다.
  그래서 지금은 요소마다 조상 가운데 가로 스크롤 상자가 있는지를 overflow 선언으로 계산한다(`test_horizontal_scroll_starts_only_on_weekdays_and_grid`).
  요일 칸·날짜·막대·점은 `.acal-body`를 움직이고, 고른 날 목록과 그 안 일정 글·출처 링크, 목록 보기 줄, 머리 줄은 조상에 가로 스크롤 상자가 없어야 한다.
  터치·트랙패드·휠은 모두 포인터 아래에서 가장 가까운 스크롤 상자를 움직이므로, 이 계산은 입력 방식과 상관없다.
  앞선 재현 사례도 `test_earlier_cross_review_repros_stay_fixed`에 함께 둔다.
- `test_chat_versions_style.py`의 #140 절 범위는 #143 머리 주석에서 끝나게 고쳤다. 전에는 파일 끝까지라 뒤에 붙인 절이 #140 규칙으로 검사됐다.
