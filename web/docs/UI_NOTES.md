## 시연 계정 로그인과 둘러보기

로그인 화면은 소개와 440px 카드를 56px 간격으로 놓는다. 학번과 비밀번호를 입력하거나 시연 계정을 눌러
칸을 채운 뒤 로그인한다. 서버가 성공을 확인한 뒤 학생 ID 하나만 탭 저장 공간(`sessionStorage`)의
`demo-student-id`에 남긴다. 실제 학교 인증이 아니며 학번·비밀번호·둘러보기 상태는 저장하지 않는다.

소개에는 붓글씨 제목 그림 `/chat-assets/calligraphy-title.png`와
`근거 조문과 함께 답하는 금오공대 학사 안내` 한 줄을 둔다. 그림이 없으면 `졸업까지,`와
`테크모와 함께`를 두 줄 제목으로 보인다. 기능 이름 알약 여섯 개는 제거했다.
시연 학번은 `20990002`, `20990003`, `20990004`다. 입력란은 숫자 키보드·최대 여덟 자리이며,
이 세 값에 정확히 일치해야 로그인 요청을 보낸다. 다른 학번은 요청 전에 같은 계정 불일치 문구를 보인다.

- **성공과 오류** — `POST /api/v1/demo-login`의 200 응답에서 가상 학생을 확인한다. 틀린 계정은
  `학번 또는 비밀번호가 맞지 않아요`를 표시한다. 성공하면 테크모가 `OO 이수 내역으로 들어왔어요`라고
  알리고 기존 축하 예약을 이용해 0.65초 뒤 메인으로 간다. `OO`는 응답의 학생 이름이다.
- **테크모** — 평소에는 `학번으로 들어와 보세요!`, 시연 계정으로 채우면 `좋아요, 로그인을 눌러 보세요`,
  오류에는 정숙 자세로 `쉿, 시연 계정으로만 들어올 수 있어요`를 표시한다. 폭 112px, 카드 오른쪽 -30px·
  위 -92px에 놓고 3.6초마다 8px 오르내린다. 움직임 줄이기에서는 멈춘다.
- **둘러보기** — `로그인 없이 둘러보기`로 규정 질문·사진으로 묻기·학사 일정·캠퍼스 안내를 쓴다.
  졸업 체크·비교과 추천은 로그인 화면으로 안내하며 상단에는 `로그인` 버튼을 둔다.
- **나가기와 복원** — 로그아웃은 입력값·선택한 학생·저장 ID·졸업 결과를 지운다. 일반 질문은 남긴다.
  새로고침하면 기존 학생 목록으로 ID를 확인한다. 사라진 ID는 지우고 일시적인 조회 실패에는 남긴다.
  재제출·로그아웃·둘러보기 이후 늦은 응답과 축하 콜백은 학생이나 화면을 되살리지 못한다.
- **배치** — 메인 질문 입력창을 기능 카드보다 위에 둔다. 입력창은 밝은 판 위 경계에 걸치고 카드 여섯 개는
  3열, 880px 이하는 2열이다. 로고는 로그인 카드와 넓은 상단에서 30px, 390px 상단에서 138×20px이다.
- **색과 대비** — 학번·비밀번호 입력란과 버튼 안쪽은 불투명 흰색, 테두리는 #8A8D8F이다.
  로그인·보내기 버튼은 #005B96→#0077b8만 쓴다. #00A3D9는 테두리 강조와 장식에만 쓴다.
  로그인 카드 .74, 상단 띠 .72, 메인 판 .72, 기능 카드·패널 .80, 질문 입력창 .92, 시연 계정 칸 .82의
  투명도를 쓴다. 유리 흐림은 7px이며 답변·표의 바탕은 .90 이상이다.
  색은 반투명 색까지 `:root` 변수로 모으고 어두운 사진 #041426과 흰 사진 양쪽에 섞어 글자 4.5:1을
  검사한다. 테두리와 초점은 3:1을 검사한다.

## 캠퍼스 사진 배경

로그인과 메인은 고정된 전체 화면 배경을 함께 쓴다. 학교 사진은 저장소에 넣지 않으며 사진이 없어도
남색 바탕에서 로그인과 기능을 계속 쓴다. 사진 이름은 양호동 캠퍼스 → 디지털관과 금오산 자락 → 정문의 밤 →
대운동장의 저녁 순서다. 파일 이름은 `campus-aerial.jpg`, `campus-hill.jpg`, `campus-gate.jpg`,
`campus-field.jpg`이며 `/chat-assets/`에서 읽는다.

- **사진과 물결** — 멈춘 CSS 배경을 먼저 보여 주고 브라우저 그래픽 기능(WebGL)이 준비되면 캔버스를 보인다.
  사진은 9초 머물고 3.2초 겹쳐 넘어간다. 포인터가 110ms 이상 간격으로 46px 이상 움직이거나 누를 때
  물방울을 넣고 최근 16개를 그린다. 처음 0.3·0.9·1.5초에 자동 물방울 세 개를 넣는다.
  물결은 더 넓은 간격과 작은 굴절·명암으로 부드럽게 그린다. 포인터 입력은 패널 위에서도 받는다.
- **사진 흐름** — 한 사진은 나타나기 시작해 사라질 때까지 15.4초 동안 같은 방향으로 흐른다.
  교체 직전 다음 사진 위치와 교체 직후 현재 사진 위치를 같은 식으로 계산한다. 방향은 누적 순서의
  홀짝으로 정하며 사진 이름·진행 칸은 합성 비율이 0.5를 넘을 때 다음 사진으로 바꾼다.
  다음 그림이 준비되지 않은 주기는 현재 그림을 유지한다.
- **시계** — 사진 교체와 물방울은 그리기 반복의 시각만 쓴다. 탭이 가려지면 멈추고 가려진 시간은 빼고 잇는다.
  움직임 줄이기에서는 사진 흐름·물결·물방울을 모두 끄고 사진 한 장만 남긴다.
- **실패 대체** — 캔버스·그래픽 기능·셰이더·사진 중 하나라도 실패하면 멈춘 배경으로 돌아간다.
  사진은 `fetch`·`createImageBitmap`으로 받고 텍스처 가장자리를 고정하며 선형 보간만 쓴다. 화면 배율은
  1.5까지만 반영한다. 외부 라이브러리, 문서 안 실행 코드·스타일, style 속성은 추가하지 않는다.
- **가독성** — 사진 위 남색 그러데이션과 `0 2px 18px rgba(4,20,38,.55)` 글자 그림자를 고정한다.
  사진 위 흰 글자는 자동 대비 계산 대신 실제 사진 네 장을 브라우저에서 보고 확인해야 한다.
- **브라우저 확인** — 1280×800에서 카드 위·아래(목표 165px·734px), 390×844에서 상단 띠 100px 이하와
  질문 입력창의 첫 화면 노출을 잰다. 가로 넘침 없음·로고 20px 이상·버튼 44px 이상도 확인한다.
  실제 실행 결과와 확인하지 못한 항목은 아래 검증 기록에 구분해 남긴다.

## 세 가지 메시지 상태

동일한 말풍선 컴포넌트로 처리하지 않는다. 상태마다 의미가 다르다.

### 1. 근거 기반 답변 (`answered: true`)
답변 + 인용 카드. 인용은 접지 않고 항상 펼쳐둔다.

### 2. 답변 불가 (`answered: false`)
```
┌─────────────────────────────────────┐
│ 보유한 규정 문서에서 확인할 수 없는   │
│ 내용입니다.                          │
│                                     │
│ 학사지원팀 054-478-XXXX  [전화 걸기] │
└─────────────────────────────────────┘
```
**빨간 에러 스타일을 쓰지 않는다.** 정상 동작이다.
근거 없이 답을 지어내지 않는 게 이 시스템의 설계 의도이므로, UI가 그걸 실패로 보이게 하면 안 된다.

### 3. 시스템 오류 (HTTP 5xx)
이때만 에러 스타일. 재시도 버튼 제공.

## 학적 연동 토글

입력창 옆에 상시 노출. 기본값 **off**.

- off → `use_academic_data: false`. 일반 규정 답변만.
- on → 개인 학적 조회 후 맞춤 답변. 켤 때 최초 1회 안내 모달.

**요청마다 사용자가 통제하게 만드는 이유** — 개인 학적 조회가 사용자 모르게 일어나면
편의성보다 신뢰 문제가 먼저 생긴다. 토글 상태가 화면에 보이면 지금 무엇이 조회되는지 명확해진다.

## 인용 카드

```
📄 학사운영규정 제30조(전과) ①
   시행일 2025-03-01
   "전과는 2학년 이상인 학생으로서..."
   공식 원문 보기
```

- **시행일을 반드시 표시한다.** 학칙은 개정되고, 학번에 따라 적용 기준이 다르다.
  시행일이 없으면 학생이 자기에게 해당되는 조문인지 판단할 수 없다.
- 스니펫은 2줄까지, 클릭하면 전체 펼침.

### 공식 원문 보기 링크

서버가 인용마다 주는 주소(`source_url`)가 안전한 HTTPS일 때만 카드에 링크를 붙인다.
문 앞에서 신분증을 한 번 더 보는 것과 같다. 서버가 시작할 때 주소를 검사하지만,
화면도 받은 값을 그대로 믿지 않고 같은 규칙으로 다시 본다.

- **보이는 글자** — `공식 원문 보기`. 화면 낭독기만 읽는 숨김 글자로 문서명·조문과
  새 탭으로 열린다는 안내를 덧붙인다. 카드가 여러 개여도 링크를 구분할 수 있다.
- **새 탭** — `target="_blank"`와 `rel="noopener noreferrer"`로 연다. 대화 내용은 페이지
  메모리에만 있어, 같은 탭으로 열면 학생이 읽던 대화를 잃는다.
- **붙이는 조건** — 아래를 모두 만족해야 한다. 서버의 주소 검사와 같은 규칙이다.
  - 값이 문자열이고 공백·제어 문자가 없다.
  - 입력 글자가 `https://`로 시작한다. 대소문자는 가리지 않아 `HTTPS://example.invalid/`도
    받는다.
  - 호스트(주소에서 서버 이름 부분)가 비어 있지 않고, 점으로만 이루어지지 않았으며,
    그 자리에 `@`와 역슬래시가 없다. `https://./`는 호스트가 점뿐이라 받지 않는다.
  - 브라우저의 주소 읽기 기능(`URL`)으로 읽은 결과가 `https:`이고 아이디·비밀번호가 없다.
- **숨기는 경우** — `null`, 필드 없음, 빈 문자열, `javascript:`·`data:`·`http://`, 상대 경로,
  `//`로 시작하는 주소, `https:example.invalid`, 호스트가 비었거나 점뿐인 주소,
  아이디·비밀번호가 든 주소, 공백이나 탭이 든 주소, 문자열이 아닌 값. 이때 카드는 링크가
  없던 때와 같은 요소만 가진다. 빈 자리나 비활성 버튼을 남기지 않는다.
- **주소는 고치지 않는다** — 통과한 주소는 입력 글자 그대로 `href`에 넣는다.
- **내용 보존** — 링크가 있든 없든 문서명·조문 경로·시행일·인용문은 서버 응답과 같다.
- **가상 데모** — 배포 데모의 인용은 `source_url`이 `null`이라 링크가 없다. 링크는 가상
  목록으로 로컬에서 확인한다. 절차는 `api/docs/RENDER_DEPLOY.md`에 있다.

## 졸업 체크 아래 BISKIT 추천 카드

졸업 체크 응답에 교내 비교과 시스템(BISKIT) 추천(`biskit_recommendations`)이 들어 있으면
졸업 표와 가상 데이터 안내 문구 아래, 같은 답변 안에 추천 영역을 그린다. 요청은 졸업 체크 한 번뿐이다.

```text
BISKIT 추천 · 20점 부족
목록 확인 2026년 11월 13일 · 접수 상태와 정원은 공식 페이지에서 확인

┌ 2026학년도 제2차 학습법 특강
│ 학부 재학생 · 신청 11월 26일까지
│ 마일리지 지급 공지 · 정확한 점수 확인 필요
│ 공식 공지 보기   BISKIT 로그인 후 프로그램명으로 검색
└
BISKIT 열기
```

추천은 식당 메뉴판과 같다. 서버가 오늘 주문할 수 있는 것만 골라 적고, 화면은 적힌 대로 보여 준다.
화면은 프로그램을 고르거나 줄 세우지 않고, 점수를 더하지도 않는다.

- **제목 줄** — `BISKIT 추천 · N점 부족`. N은 서버가 준 정수(`shortfall_points`)이고 표의
  부족 글자를 다시 읽지 않는다.
- **목록 확인일** — `listed_on`을 `2026년 11월 13일` 꼴로 적고 접수 상태와 정원은 공식
  페이지에서 확인하라고 덧붙인다. 확인일이 없으면 뒤 문구만 적는다.
- **대상·날짜 줄** — `대상 · 신청 11월 26일까지 · 행사 2026년 11월 23일`. 행사일은 연도를
  함께 적는다. 제목의 연도와 행사 연도가 다른 공지가 있어서다. 날짜가 `2026-11-26` 꼴이
  아니면 받은 글자를 그대로 보여 주고, 마감일이 없으면 `신청 마감 확인 필요`라고 적는다.
- **확인 필요 표시** — `eligibility`가 `eligible`이 아니면 `대상 확인 필요`,
  `deadline_status`가 `open`이 아니면 `마감 시각 확인 필요`를 졸업 표의 확인 필요와 같은
  노란 표시로 붙인다. 모르는 값도 확인 필요로 본다.
- **점수 문구**
  - `published`이고 점수가 1 이상 정수 — `마일리지 N점`
  - `announced` — `마일리지 지급 공지 · 정확한 점수 확인 필요`
  - `undisclosed`, 모르는 값, 점수가 빠진 `published` — `마일리지 미공개`
  - 부족 점수를 채운다거나 졸업 요건을 충족한다고 약속하는 문구는 쓰지 않는다.
- **링크** — 인용 카드와 같은 안전 주소 검사를 통과한 주소만 새 탭 링크로 만든다. 학교
  주소인지는 서버가 판정한다.
  - `notice_url` — `공식 공지 보기`. 주소가 없거나 위험하면 링크 대신 `공식 공지 확인 필요`.
  - `application_url` — `신청 페이지 열기`. 주소는 받은 그대로 쓴다. `login_required`가
    참이면 링크 옆에 `BISKIT 로그인 필요`를 눈에 보이는 글자로 적는다. 로그인 화면을 거치는
    주소여도 학생이 누르기 전에 알 수 있다.
  - 신청 주소가 없고 `login_required`가 참이면 `BISKIT 로그인 후 프로그램명으로 검색`.
  - `portal_url` — 영역 맨 아래 `BISKIT 열기`. 안전하지 않으면 링크를 숨긴다.
- **빈 목록** — `지금 신청할 수 있는 프로그램을 확인하지 못했어요`와 `BISKIT 열기` 링크.
- **추천 영역을 그리지 않는 경우** — 항목이 없거나 `null`일 때, 부족 점수가 1 이상 정수가
  아닐 때, `programs`가 배열이 아닐 때, 프로그램이 객체가 아니거나 제목이 비지 않은 글자가 아닐 때(숫자 제목 포함),
  `login_required`가 참·거짓 값이 아닐 때(`"true"` 같은 글자, 숫자, `null`, 누락). 이때도
  졸업 표는 그대로 나오고 오류 문구를 띄우지 않는다.
- **지우기** — 추천 영역은 졸업 체크 답변 안에 있어, 버튼을 다시 누르면 새 결과로 바뀌고
  `새 대화`를 누르면 표와 함께 사라진다.

## 채팅 입력창의 사진 첨부

별도의 `현수막으로 행사 찾기` 칸은 없앴다. 질문 입력창 아래 `사진 첨부`에서 사진 한 장을
고르고 `보내기`를 누른다. 사진만 보내도 되고 질문과 함께 보내도 된다. 화면은 택배 접수
창구와 같다. 상자 크기와 종류만 보고 받아 넘기고, 안에 든 것이 행사인지 규정 질문인지
장소 질문인지는 서버가 판정한다.

### 요청 순서

1. **사진 주소** — 사진이 붙어 있으면 `POST /api/v1/photo-input`에 사진 바이트를 한 번 보낸다.
   응답은 기존 행사 필드에 사진에서 읽은 글자(`recognized_text`, 아래에서는 판독문)가 더해진 모양이다.
2. **행사 확인** — `event_match`가 `confirmed`면 아래 행사 카드를 그리고 요청을 끝낸다.
   질문을 함께 보냈더라도 글자 주소를 부르지 않고, 질문은 편집 칸에 남긴다.
3. **글자 주소** — 행사가 확인되지 않았으면 사진 없이 `POST /api/v1/photo-question`에
   `question`, `recognized_text`, `session_id`만 보낸다. 사진만 보냈으면 `question`은 빈 글자이고
   판독문이 질문 노릇을 한다.
4. **보내지 않는 경우** — 질문과 판독문이 모두 비었거나 판독문이 2,000자를 넘으면 글자 주소를
   부르지 않고 노란 확인 필요 카드와 편집 칸만 보여 준다.

질문만 보내면 전과 같이 `POST /api/v1/chat`으로만 간다.

### 글자 주소의 응답 표시

`kind` 값에 따라 그린다. 모르는 값이거나 필요한 필드가 빠졌으면 서버 오류 문구를 보여 준다.

- `event` — `event` 필드로 사진 주소와 같은 행사 카드를 그린다. 응답에 `reasons`와
  `identified_by`가 있으면 마감 차이 안내와 확인 단서 줄에 쓴다.
- `regulation`, `campus` — 제목(`규정 검색`, `캠퍼스 안내`), 답변 글, 출처 목록. 출처는
  `sources`의 `title`과 `url`만 쓴다. 안전 주소 검사(`sourceLink`)를 통과한 주소만 링크가 되고,
  통과하지 못하면 `제목 · 링크 확인 필요`를 글자로 적는다.
- `hold` — 노란 확인 필요 카드. 서버가 출처나 행사를 함께 보냈더라도 그리지 않는다.
  `hold_reason`이 화면이 아는 사유 이름(`no_readable_clue` 등)이면 그 문구를, 아니면 일반
  보류 문구를 적는다. 받은 값을 그대로 화면에 적지는 않는다. 빨간 오류 스타일은 쓰지 않는다.

### 읽은 글자 고쳐 다시 묻기

사진 답변 아래에 편집 칸을 붙인다.

```text
사진에서 읽은 글자
읽은 글자     [ 가상관 101호            ]
함께 물을 질문 [ 여기 어디야?            ]
[고쳐서 다시 묻기]
```

- **일반 글자** — 판독문은 입력 칸의 값으로만 넣는다. 주소처럼 생긴 글자가 들어 있어도 링크가
  되지 않고, 화면이 그 주소를 열지도 않는다. 링크는 서버가 응답에 실어 준 출처로만 만든다.
- **다시 묻기** — `고쳐서 다시 묻기`는 두 칸의 글자만 글자 주소로 보낸다. 사진은 다시 보내지
  않는다. 새 답은 같은 대화 칸의 답변 자리를 바꿔 그린다.
- **2,000자 한도** — 서버처럼 글자 수로 센다. 넘으면 요청을 보내지 않고 편집 칸 아래에 줄여
  달라고 적는다. 두 칸이 모두 비어도 보내지 않는다.
- **글자 질의 실패** — 통신 실패나 서버 오류면 `다시 시도`가 같은 글자만 다시 보낸다. 사진은
  이미 읽었으므로 다시 올리지 않는다. 서버가 글자를 거절(422)하면 `다시 시도` 없이 고쳐
  달라고 안내한다.
- **읽지 못한 까닭** — 사진 주소가 `text_reader_unavailable` 같은 사유를 보냈는데 질문이 있어
  글자 주소로 넘어간 경우, 그 사유 문구를 편집 칸 위쪽에 적는다.

### 행사 카드

```text
가상 해외 취업 설명회
확인 단서 · 사진 글자
행사일 2026년 11월 23일
공식 신청 마감 2026년 11월 22일
[확인 필요] 사진에는 마감이 11월 20일로 적혀 있어요. 공식 공지의 마감을 따르세요.
[신청 접수 중]
마일리지 미공개 · 공식 공지에서 확인
공식 공지 보기   신청 페이지 열기   BISKIT 로그인 필요
확인일 2026년 11월 13일 · 현재 정원과 접수 상태는 공식 링크에서 다시 확인
```

- **보내는 것** — 고른 파일의 바이트를 본문에 그대로 싣고 형식은 `Content-Type`으로 알린다.
  파일에서 바이트만 잘라 내 보내므로 파일명은 요청에 실리지 않고 화면에도 적지 않는다.
  질문 말풍선에는 `사진 1장`이라고만 적는다.
- **보내기 전 검사** — JPEG·PNG가 아니거나 5MB(서버 한도와 같은 5,000,000바이트)를 넘으면 사진도
  질문도 보내지 않고 입력 칸 아래 알림 영역에 이유를 적는다. 적어 둔 질문과 고른 사진은 그대로
  남는다. 서버도 같은 제한으로 다시 검사한다.
- **중복 제출 방지** — 질문·졸업 체크와 같은 잠금(`setBusy`)을 쓴다. 사진 주소와 글자 주소가
  이어지는 동안 잠금을 한 번 걸고 한 번 푼다. 그동안 `보내기`, `사진 첨부`, `첨부 제거`,
  `고쳐서 다시 묻기`, `다시 시도`, 첫 화면의 소개 버튼과 패널 안 시작 버튼(`내 졸업 체크 보기` 등), `새 대화`가 함께 잠긴다.
- **첨부 비우기** — 사진은 보내는 즉시 입력창에서 비운다. 남겨 두면 다음 질문에 같은 사진이 또
  실린다. `첨부 제거`는 사진을 고른 동안에만 보이고, 누르면 고른 사진만 비운다.
- **날짜 순서** — 제목, 행사일, 공식 신청 마감 순으로 적는다. 서버가 `deadline_mismatch`를
  붙였을 때만 그 아래에 사진 마감을 `11월 20일` 꼴로 적는다. 사진 마감에는 연도를 붙이지 않는다.
- **신청 상태** — `open`은 `신청 접수 중`, `closed`는 `신청 마감`, `needs_check`과 모르는 값은
  `신청 상태 확인 필요`. `deadline_day`가 있으면 오늘이 마감일이라는 안내를 덧붙인다.
- **링크** — 인용 카드와 같은 안전 주소 검사(`sourceLink`)를 통과한 주소만 새 탭 링크로 만든다.
  - `notice_url` — `공식 공지 보기`. 통과하지 못하면 `공식 공지 확인 필요`.
  - `application_url` — `신청 페이지 열기`. `login_required`가 참이면 옆에 `BISKIT 로그인 필요`.
  - 신청 주소가 없고 `login_required`가 참이면 `BISKIT 로그인 필요 · 로그인 후 프로그램명으로 검색`.
    링크를 만들지 못해도 로그인이 필요하다는 말은 빠뜨리지 않는다.
- **새 대화** — 결과 카드와 알림을 지우고 고른 사진과 적어 둔 질문도 비운다. 요청 중에는
  `새 대화`가 잠겨 있어 아무것도 바뀌지 않는다.
- **확인 필요** — `event_match`가 `confirmed`가 아니면 서버가 행사 정보를 함께 보냈더라도 제목과
  링크를 그리지 않는다. 물을 글자가 있으면 글자 주소로 넘어가고, 없으면 노란 카드에 사유별
  문구만 적는다. 빨간 오류 스타일은 쓰지 않는다.
  - `no_readable_clue` — 글자나 QR을 찾지 못함
  - `ambiguous_event` — 행사를 하나로 정하지 못함
  - `text_reader_unavailable` — 서버가 글자를 읽을 수 없어 QR 사진이나 직접 입력을 권함
- **사진 주소의 오류** — 문구를 다섯 가지로 나눈다.
  - 413 크기 초과, 415 형식 불일치, 422 열 수 없는 사진·화소 초과. 같은 사진을 다시 보내도
    결과가 같아 `다시 시도` 버튼을 두지 않는다.
  - 통신 실패와 그 밖의 서버 오류(형식이 어긋난 응답 포함). `다시 시도`가 같은 바이트와 함께
    보낸 질문으로 처음부터 다시 한다.
  - 상태 코드는 받았지만 본문을 받는 중에 연결이 끊기거나 시간이 넘으면 통신 실패로 알린다.
    본문을 다 받고도 해석하지 못했을 때만 서버 오류로 알린다.
- **형식이 어긋난 확정 응답** — 행사가 객체가 아니거나, 제목이 비었거나, `login_required`가
  참·거짓 값이 아니면 카드를 그리지 않고 서버 오류 문구를 보여 준다.
- **알림** — 진행 중 문구(`사진에서 글자를 읽는 중…`, `읽은 글자로 답을 찾는 중…`)는 기존 상태
  줄(`#status`)에, 보내기 전 안내와 결과 한 줄은 입력 칸 아래 알림 영역(`#photo-note`,
  `role="status"`)에 써서 화면 낭독기가 읽게 한다.
- **하지 않는 것** — 사진 미리보기, 여러 장 올리기, 사진 보관, 글자 없는 사진 알아보기(건물 등),
  판독문 속 주소나 QR 주소 열기.

## 테크모 펫과 말풍선

배포 화면(`api/app/chat_web/`)의 테크모는 누를 수 있는 작은 펫이다. 지금 무슨 일이 일어나는지 자세와 말풍선의
한 줄 말로 알리고, 누르면 질문 입력창으로 데려간다. 왼쪽 칸의 비서와 `테크모에게 묻기` 글자 버튼은 없앴다.

- **자리** — 펫 줄(`#pet-dock`)은 대화 내용과 메인 판 뒤에 있다. 판의 유리 흐림이 고정 위치의 기준을 바꾸지 않게
  판 밖에 둔다. 질문 입력창은 기능 카드 위로 옮겼다. 첫 화면(`#empty`) 밖이라 첫 질문을 보낸
  뒤에도 남는다.
  - 960px 이하 — 입력창 바로 앞의 낮은 줄이다. 줄이 자리를 차지하므로 입력창을 덮지 않는다. 입력창이 화면
    아래로 밀려나 있으면 화면 아래 가장자리에 붙어 떠 있는다.
  - 961px 이상 — 화면 오른쪽 아래에 고정한다. 본문 격자에 펫 너비(168px)만큼 빈 칸을 두어 채팅과 겹치지
    않는다. 말풍선은 펫 위에 온다.
- **누르면** — 입력창에 초점을 주고 입력창까지 화면을 옮긴다. 답변을 기다리는 중에도 눌린다. 요청은 보내지 않는다.

| 상태 | 자세 | 한 줄 말 | 언제 |
|---|---|---|---|
| 평소 | 안내 | 궁금한 점을 물어보세요 | 처음, `새 대화` |
| 찾는 중 | 정숙 | 쉿, 찾아보는 중이에요… | 요청 잠금(`setBusy`)을 거는 순간 |
| 찾음 | 축하 | 찾았어요! 함께 확인해 봐요 | 답·졸업 표·확정된 행사·일정이나 장소 목록을 그린 직후 |
| 답변 표시 | 안내 | 근거와 함께 안내해 드릴게요 | 축하 1.2초 뒤 |
| 답변 보류 | 정숙 | 확인할 근거가 더 필요해요 | 근거 없음, 글자 주소의 보류, 읽은 글자가 없는 사진, 남은 일정이나 장소 없음 |
| 오류 | 안내 | 잠시 문제가 생겼어요. 다시 시도해 주세요 | 통신 실패, 서버 오류, 형식이 어긋난 일정·장소 응답, 서버가 거절한 사진·글자 |

- **한 곳에서만 바꾼다** — 자세·말·대기 점은 `showAssistant`만 바꾼다. 일반 질문, 사진 질문,
  읽은 글자 재질문, 졸업 체크, 학사 일정·캠퍼스 안내 조회가 같은 표를 쓴다.
- **그림은 갈아 끼우지 않는다** — 자세 다섯 개(기본형·정숙·안내·축하·음악회)를 가로로 이어 붙인 그림 한 장
  (스프라이트 시트, 960×192px)을 펫의 배경으로 깔고, 펫 줄의 `data-pose` 값에 따라 배경의 가로 위치만
  0·25·50·75·100%로 옮긴다. 필름 한 줄을 창 뒤에서 한 칸씩 당겨 보는 것과 같다. 그림 주소를 바꾸지
  않으므로 늦게 도착한 그림이 지금 자세를 바꾸지 못한다.
- **그림이 없어도 동작한다** — 펫 버튼은 로고와 같은 방식(`data-brand-slot`)으로 숨긴 채 시작하고, 버튼 안에
  둔 같은 주소의 그림이 로드에 성공해야 보인다. 그림이 없으면 버튼만 숨고 말풍선은 남는다. 버튼 크기는
  고정(기본 56px, 680px 이하 48px, 961px 이상 128px)이라 그림이 늦게 와도 말풍선과 입력창이 밀리지 않는다.
- **움직임** — 서로 다른 요소에 하나씩 건다. 한 요소에 겹치면 뒤 규칙이 앞 규칙을 덮기 때문이다.
  - 떠 있기 — 제자리에서 조금 오르내린다.
  - 눌렸다 튀기 — `data-pose` 값이 달라질 때 한 번. 같은 자세에서 말만 바뀌면 다시 움직이지 않는다.
  - 쉬는 자세 — 평소와 답변 표시가 이어지면 24초마다 음악회 칸과 기본형 칸을 잠깐 보인다. 스크립트
    타이머 없이 화면 꾸밈 규칙(CSS)이 `data-state` 값을 읽어 돌린다.
- **대기 점** — 찾는 중일 때만 말 옆에 점 세 개가 움직인다. 찾음·보류·오류에서 사라진다.
- **움직임 줄이기** — 기기의 움직임 줄이기 설정(`prefers-reduced-motion: reduce`)이 켜져 있으면
  떠 있기·튀기·쉬는 자세·점의 움직임을 끄고, 펫을 눌렀을 때도 화면을 부드럽게 옮기지 않는다. 상태에 따라
  정지 그림 칸이 바뀌는 것과 말·점 표시는 그대로 남는다.
- **잠금을 풀 때** — 요청이 남긴 축하·보류·오류를 덮어쓰지 않는다. 결과를 남기지 않고 끝난 요청이
  있을 때만 평소로 돌려 대기 점이 남지 않게 한다.
- **예약 취소** — 축하 뒤 전환을 기다리는 동안 새 질문이나 `새 대화`가 시작되면 예약한 전환을 취소한다.
- **낭독** — 진행 알림은 기존 상태 줄(`#status`)이 읽어 준다. 말풍선에는 알림 역할을 두지 않아
  화면 낭독기가 같은 일을 두 번 읽지 않는다. 펫 버튼의 읽기용 이름은 `테크모에게 묻기`이고, 그림은
  꾸밈이라 낭독에서 뺀다.
- **예전 안내 상자** — 채팅 맨 위의 `학사 규정에 질문하기` 상자와 `가상 학생 졸업 체크` 버튼은 없앴다.
  졸업 체크는 소개 영역의 `내 졸업 체크 보기`와 패널의 `졸업 체크 시작`으로 부른다. 채팅 영역 제목은
  화면에서만 감춘 제목으로 남겨 화면 낭독기가 영역 이름을 읽는다.

## 기능 카드와 패널

첫 화면의 카드 여섯 개는 기능을 바로 부르지 않고 설명 패널을 연다. 카드는 책갈피다. 당기면 카드 목록이
있던 자리에 그 카드의 쪽이 펼쳐진다.

| 식별자 | 카드 | 패널 내용 | 시작 버튼 → 부르는 기능 |
|---|---|---|---|
| `graduation` | 졸업 체크 | 가상 학생의 이수 내역으로 남은 조건을 계산한다 | `졸업 체크 시작` → 졸업 체크 |
| `biskit` | 비교과 추천 | 졸업 체크 결과 아래에 부족한 점수를 채울 프로그램이 함께 나온다 | `졸업 체크와 추천 보기` → 졸업 체크 |
| `photo` | 사진으로 묻기 | 글자가 보이는 JPEG·PNG 한 장, 5MB 이하, 개인정보 제외 | `사진 선택` → 사진 선택 창 |
| `ask` | 규정 질문 | 질문을 적으면 근거 조문과 함께 답한다 | `질문 입력하기` → 입력창 초점 |
| `calendar` | 학사 일정 | 조회 범위의 남은 수강신청 일정과 출처 | 패널을 열 때 한 번 조회 |
| `campus` | 캠퍼스 안내 | 장소 이름·용도 목록과 선택한 장소의 상세 안내 | 패널을 열 때 한 번 조회 |

- **자리** — 패널은 `#empty` 안, 카드 목록 바로 뒤의 글 흐름에 있다. 화면 위에 띄우지 않으므로 펫·말풍선·
  입력창을 가리지 않는다. 화면을 덮는 `<dialog>`와 접는 `<details>`는 쓰지 않는다.
- **이름** — 화면(`index.html`)과 스크립트(`chat.js`)가 함께 지킨다.
  - 카드 — `button.card[data-feature=식별자]`, `aria-controls=panel-식별자`, `aria-expanded`. 카드에는
    `data-action`을 두지 않는다.
  - 카드 목록 — `ul.cards#feature-cards`.
  - 패널 — `section.feature-panel#panel-식별자[data-panel=식별자][hidden]`. 제목은 `[data-panel-title]`,
    닫기는 `button[data-panel-close]`, 시작 버튼은 `button[data-action]`.
- **열기** — 카드를 누르거나 초점을 두고 Enter·Space를 누르면 카드 목록 대신 그 패널이 보이고, 초점이 패널
  제목으로 간다. 제목은 `tabindex="-1"`이라 스크립트로만 초점을 받고 Tab 순서에는 들지 않는다.
- **닫기** — `닫기` 버튼이나 패널 안에서 누른 Escape로 닫는다. 초점은 눌렀던 카드로 돌아간다.
- **시작 버튼** — 패널을 닫고 이미 있는 기능을 부른다. `data-action` 버튼이라 요청 중에는 다른 버튼과 함께
  잠기고, 연달아 눌러도 졸업 체크 요청은 하나만 나간다.
- **일정·장소 조회** — 두 패널은 `[data-panel-content]`에 결과를 그린다. 패널을 열 때 기존 요청 잠금
  (`setBusy`, `whileBusy`)으로 한 번 조회한다. 다른 요청 중에 열면 안내와 `다시 시도`만 보여 주고 펫 상태는
  바꾸지 않는다. 실패하면 패널 안에서 다시 시도하며, 연달아 눌러도 요청은 하나만 나간다. 닫거나 다른 패널로
  옮긴 뒤 도착한 응답은 화면과 펫 상태에 반영하지 않는다.
- **학사 일정** — 스크립트의 조회 범위 상수로 학년도·학기 표시를 만든다. 한국 표준시의 오늘을 기준으로
  종료일이 오늘 이후인 일정을 시작일순으로 적고, 날짜는 연·월·일만 표시한다. 연도 없는 날짜와 실제로 없는
  날짜, 시작일보다 이른 종료일은 응답 전체의 형식 오류로 처리한다. 남은 일정이 없으면 조회 범위와 함께 알린다.
  출처에는 제목과 확인일, `공식 페이지에서 다시 확인` 안내를 붙인다.
- **캠퍼스 안내** — 서버 순서대로 장소의 이름·용도를 버튼 목록으로 적는다. 선택하면 같은 응답에서 `id`로
  찾아 위치와 값이 있는 선택 항목만 보여 준다. 새 요청은 보내지 않는다. 선택 시 상세 제목으로, `목록으로`를
  누르면 고른 장소 버튼으로 초점을 옮긴다. 장소 목록이나 필수 글자 필드가 어긋나면 형식 오류로 처리한다.
- **출처와 글자** — 안전 주소 검사(`isSafeSourceUrl`)를 통과하고 확인일이 날짜 꼴인 출처만 링크로 만든다.
  나머지는 제목만 적는다. 서버의 안내 글은 글자로 넣으므로 주소처럼 생긴 글자도 링크로 바뀌지 않는다.
- **새 대화** — 패널을 연 채 질문을 보냈더라도 카드 목록이 보이는 첫 화면을 되돌린다.
- **커지는 전환** — 브라우저가 바뀌기 전후 화면을 이어 그려 주는 기능(View Transitions,
  `document.startViewTransition`)이 있으면 카드가 패널로 커지고, 닫을 때는 카드로 줄어든다. 기능이 없거나
  전환이 실패하면 같은 상태 변경을 바로 한다.
  - 스크립트는 누른 카드에 `data-morph`를 붙였다 뗄 뿐이다. 이어 그릴 짝을 정하는 이름
    (`view-transition-name: feature-morph`)은 CSS가 `.card[data-morph]`와 열린 패널에만 준다.
  - 같은 이름을 가진 요소가 한 화면에 둘 보이면 브라우저가 전환을 건너뛴다. 그래서 패널이 열려 있는 동안
    카드 목록은 그리지 않는다.
- **펫 줄에 가리지 않기** — 960px 이하의 펫 줄은 화면 아래에 붙어 그 밑의 내용을 가린다. 첫 화면의 버튼과
  패널 제목에 아래쪽 여유(`scroll-margin`, 120px)를 두어, 초점을 받아 화면에 들어올 때 펫 줄 위에 멈춘다.
- **움직임 줄이기** — 스크립트는 전환을 시작하지 않고, CSS도 전환의 움직임을 끈다. 패널은 바로 열리고 닫힌다.

## 로그인과 카드 움직임

로그인 카드는 아래에서 0.8초 떠오르고 테크모는 3.6초마다 8px 오르내린다. 기능 카드는 마우스를 올리면
4px 떠오른다. 규칙 이름은 각각 `login-rise`, `login-float`, `card-lift`다.
모두 `animation`을 쓰며 `transition` 선언은 추가하지 않는다. 움직임 줄이기 묶음 한 곳에서
기존 펫·대기 점·화면 전환과 함께 끈다. 작은 화면에서도 제목과 안내를 자르지 않는다.

## 로딩 상태

Agent 루프는 여러 단계를 거쳐 응답이 2초를 넘길 수 있다. 스피너 하나로 두면 멈춘 것처럼 보인다.
단계를 텍스트로 노출한다.

```
규정 문서 검색 중...
→ 학적 정보 확인 중...
→ 답변 작성 중...
```

`latency_ms`를 응답에 포함시킨 이유도 여기 있다 — 어느 단계가 느린지 실측해야 개선 대상을 정한다.

## 상태 관리 방침

채팅 관련 상태를 `useChat` 훅 하나로 모은다.

```
useChat()
  messages, isLoading, currentStage, error
  sendMessage(text, useAcademicData)
  retry()
```

컴포넌트 여러 곳에서 로딩 플래그를 각자 들고 있으면 비동기 순서가 꼬였을 때
어디서 어긋났는지 추적이 안 된다. 이전 프로젝트에서 겪은 문제라 처음부터 한 곳으로 모은다.

## 접근성

- 새 메시지 도착 시 `aria-live="polite"` 로 스크린리더 알림
- 입력창 Enter 전송 / Shift+Enter 줄바꿈
- 인용 카드의 `공식 원문 보기`는 버튼이 아닌 링크로 (항상 새 탭으로 이동, Tab으로 초점·Enter로 열기)
- 대비비 4.5:1 이상

## 시연 화면 검증 기록 (2026-11-14)

- 화면 테스트 파일 11개를 서버·네트워크 없이 실행해 336개 검사 통과·실패 0개를 확인했다.
  가상 학생과 가짜 그림·그리기 시각만 사용했다.
- 파이썬 통합 테스트의 예전 비밀번호 금지 단언을 로그인 폼 안 정확히 한 개·자동완성 끄기 검사로 바꿨다.
  전체 명령은 실행했으나 `fastapi`·`pydantic`·`PIL` 의존성이 없는 환경에서 38개 검사 중 가져오기 오류
  23개로 실패했다. 새 HTML 검사만 분리해 정상·중복·자동완성·다른 폼 변형을 확인했다.
- 브라우저 실측은 미확인이다. 설치된 Edge를 화면 없이 실행했으나 문서 출력 없이 비정상 종료해
  1280×800 카드 위·아래, 390×844 상단 띠 높이·입력창 위치·가로 넘침·로고와 버튼 크기를 확보하지 못했다.
  CSS 선언을 브라우저 실측값으로 적지 않았다.
- 사진 네 장과 붓글씨·로고·테크모 그림은 이 체크아웃에 없다. 실제 사진 위 흰 글자 가독성도 미확인이다.
  남색 덮개·그림자 선언, 대비 조합, 사진 실패 시 정지 배경은 자동 검사로 확인했다.
