# 공식 로고·테크모·캠퍼스 사진·제목 그림 준비

첫 화면에 쓸 그림은 배포 준비 때 준비한다. 저장소 루트에서 `python -B api/scripts/prepare_brand_assets.py`를 실행한다. 서버와 테스트는 그림을 내려받지 않는다.

저장소에 넣은 그림은 테크모 동작 시트 한 장(`api/app/chat_web/art/techmo-sprite.png`)뿐이다. 로고와 캠퍼스 사진은 배포 준비 때만 받고, 그렇게 받거나 복사해 만든 `api/app/chat_web/assets/` 아래의 PNG와 JPG는 저장소에 넣지 않는다.

### 밝은 로고

남색 상단 띠와 로그인 카드에는 흰 판 없이 바로 올리는 `kumoh-signature-light.png`를 쓴다. 같은 스크립트가 위 공식 로고로 만든다.

- **받기** — 원본과 주소가 같아 한 번 받은 바이트를 다시 쓴다. 원본 지문을 통과한 PNG만 바꾼다. 원본을 받지 못하거나 지문이 다르면 밝은 로고도 같은 사유로 실패하고 기존 파일이 남는다.
- **바꾸는 규칙** — 픽셀마다 HSV(색상·채도·명도)로 본다. 채도가 0.35보다 크고 파랑이 빨강보다 20 넘게 크면(파란 공) 그대로 둔다. 나머지는 흰색(255, 255, 255)으로 바꾸고 알파를 `round(원래 알파 × min(1, (1 − 명도) × 1.15))`로 정한다. 흰 바탕은 투명이 되고, 검정 kit는 흰색, 회색 학교 이름은 밝은 회색처럼 보인다.
- **지문** — 원본과 달리 결과 바이트의 지문은 고정하지 않는다. PNG 압축 결과가 Pillow 판마다 달라질 수 있어서다. 테스트는 원본 지문과 픽셀 규칙을 본다. 서버는 시작할 때 파일 내용으로 주소에 지문을 붙인다.
- **그림이 없을 때** — 서버가 404로 답하고 화면은 「금오공대 학사 안내」 글자를 보여 준다.
- **원래 로고** — `kumoh-signature.png`도 계속 만들고 내준다. 화면은 더 요청하지 않는다.

## 테크모 동작 시트

출처: 공식 테크모를 바탕으로 새로 그린 동작 시트, 저장소에 보관. 바탕이 된 공식 테크모는 학교의 [캐릭터 소개](https://www.kumoh.ac.kr/ko/sub01_01_02_02.do)에 있다.

동작마다 그림 칸(프레임)을 한 줄씩 놓은 한 장(스프라이트 시트)이다. 넘기면 움직이는 플립북을 한 장에 펼쳐 놓은 것과 같다. 한 줄이 한 동작이고, 화면은 그 줄의 칸을 차례로 넘겨 보여 준다.

| 항목 | 값 |
| --- | --- |
| 원본 | `api/app/chat_web/art/techmo-sprite.png` (PR #94) |
| 형식 | PNG, RGBA, 1536×960 |
| 지문(SHA-256) | `8c514828197766d281f0eb60a9f6af5d015f4c44a5a4cc3bee1a7754133258af` |
| 내려 주는 자리 | `api/app/chat_web/assets/techmo-sprite.png` |

칸 크기, 한 줄의 칸 수, 동작별 프레임 수는 `api/app/chat_web/techmo_layout.json` 한 곳에 둔다. 준비 스크립트가 이 파일로 그림 크기를 확인하고, 서버가 같은 파일을 화면에 넘긴다. 지금 값으로는 192×192 칸이 가로 8칸, 세로 5줄이라 전체 1536×960이다.

| 줄 | 동작 | 프레임 |
| ---: | --- | ---: |
| 0 | `idle` 대기 | 8 |
| 1 | `guide` 안내 | 6 |
| 2 | `celebrate` 축하 | 8 |
| 3 | `quiet` 정숙 | 4 |
| 4 | `drag` 끌려가는 중 | 6 |

준비 스크립트는 이 그림을 만들지 않는다. 저장소의 원본을 검사한 뒤 내려 주는 자리에 복사한다.

- **내려받지 않음** — 원본이 저장소에 있어 학교 서버가 필요 없다. 내려받기보다 먼저 준비하므로 로고와 사진을 전부 받지 못해도 시트는 준비된다.
- **검사 순서** — 원본을 한 번 읽어 지문, PNG 형식, 색 모드(RGBA), 크기, 전체 디코딩(그림 끝까지 풀어 보기) 순서로 본다. 크기는 칸 배치 파일의 `한 줄의 칸 수 × 칸 크기`, `줄 수 × 칸 크기`와 같아야 한다.
- **바꿔서 통과시키지 않음** — 색 모드가 RGBA가 아닌 그림을 RGBA로 바꿔 받아들이지 않는다.
- **같은 바이트** — 다시 저장하지 않고 검사한 바이트를 그대로 쓴다. 내려 주는 파일의 지문이 표의 값과 같다.
- **남는 칸** — 프레임이 8칸보다 적은 줄의 나머지 칸은 화면이 쓰지 않는다. 화면은 줄마다 프레임 수까지만 넘긴다. 좌우 뒤집기도 화면이 바라보는 방향에 맞춰 한다.
- **실패 처리** — 원본이 없거나, 지문·형식·색 모드·크기가 다르거나, 쓰기에 실패하면 기존 시트를 그대로 두고 `techmo-sprite.png: 준비 실패 (사유)` 한 줄을 남긴다. 종료 코드는 0이다.
- **그림을 바꿀 때** — 원본 파일, 스크립트의 `TECHMO_SPRITE_HASH`, 위 표의 지문을 함께 고친다. 줄이나 칸 수가 달라지면 칸 배치 파일도 고친다.

공식 테크모 자세 모음(JPG)을 받아 자르고 기울여 프레임을 만들던 방식은 쓰지 않는다. 동작마다 옷과 크기가 달라 한 캐릭터로 보이지 않았고 흰 배경 조각이 남았기 때문이다. 그 그림에서 잘라 내던 낱장 자세 그림 네 장(`techmo-basic.png`, `techmo-quiet.png`, `techmo-guide.png`, `techmo-celebrate.png`)도 화면이 쓰지 않아 만들지 않고, 서버도 내주지 않는다.

서버는 시작할 때 칸 배치 파일을 검사한다. 버전이 1인지, 칸 크기와 칸 수가 양의 정수인지, 동작 이름이 겹치지 않는지, 프레임 수가 1 이상이고 한 줄의 칸 수 이하인지 본다. 통과하면 화면(`index.html`)의 `__TECHMO_LAYOUT__` 자리에 그 내용을 넣는다. 따옴표는 HTML 속성 값에 넣어도 안전한 글자로 바꾼다(HTML 이스케이프). 검사에 실패하거나 자리가 정확히 한 번 있지 않으면 서버를 시작하지 않는다. 칸 배치 파일과 원본 폴더(`art/`)는 `/chat-assets/` 주소로 내주지 않는다. 서버는 `assets/` 아래에서 허용 목록에 있는 이름만 내준다.

화면은 받은 그림의 실제 크기가 칸 배치와 같을 때만 새 재생을 켠다. 예전 960×192 그림이 남아 있거나 그림이 없어도 화면은 예전 방식으로 동작한다.

## 받기 한도와 내려 주는 주소

로고를 받을 때 요청별 제한 시간은 5초, 받기 전체 제한은 20초, 다운로드와 압축 내부 항목의 크기 상한은 각각 1MiB임. 주소 이동은 `https://www.kumoh.ac.kr` 안에서만 허용한다. 압축을 디스크에 풀지 않고 메모리에서 검사한다.

| 준비 경로 (`api/app/chat_web/assets/` 아래) | 요청 주소 | 응답 형식 |
| --- | --- | --- |
| `kumoh-signature.png` | `/chat-assets/kumoh-signature.png` | `image/png` |
| `kumoh-signature-light.png` | `/chat-assets/kumoh-signature-light.png` | `image/png` |
| `techmo-sprite.png` | `/chat-assets/techmo-sprite.png` | `image/png` |

화면의 `chat.css`·`chat.js` 주소에 파일 내용을 요약한 SHA-256 지문을 `?v=`로 붙임. 서버는 시작할 때 화면과 두 파일을 읽고, 주소가 각각 정확히 한 번 있는지 확인함. 그림 가운데는 메인 화면 제목 `main-lettering.png`와 밝은 로고 `kumoh-signature-light.png`에만 같은 지문을 붙임. 그림은 배포 준비 때 생기므로 서버가 시작할 때 파일이 있으면 붙이고, 없거나 읽지 못하면 주소를 그대로 둔 채 시작함. 화면과 `/chat-assets/` 응답에는 쓸 때마다 다시 확인하라는 `Cache-Control: no-cache` 지시를 보냄. 기존 화면 보안 정책은 유지함.

검증한 결과를 임시 파일에 모두 쓴 뒤 최종 파일로 교체한다. 도장을 확인한 봉투만 우편함에 넣는 것과 같다. 한 그림이 실패해도 다른 그림을 계속 준비하며 종료 코드 0으로 끝낸다. 실패한 그림의 기존 파일은 보존하고, 파일이 없으면 서버가 404로 답한다. 로그에는 그림별 성공 여부와 실패 종류만 한 줄로 남긴다.

## 캠퍼스 사진 네 장

로그인·메인 화면의 배경 사진도 같은 스크립트가 배포 준비 때만 받는다. JPG는 저장소에 넣지 않는다. 2026-11-14에 학교 공식 홈페이지에서 확인한 아래 값을 사용한다. 원본은 모두 `https://www.kumoh.ac.kr` 아래의 1920×280 JPEG이고, 화면은 표의 순서대로 보여 준다.

| 3 | `campus-gate.jpg` | 정문의 밤 | `/_res/ko/img/sub06/bg_subvisual_pc.jpg` | 346802 | `69f8c4620bf576cc8290a3bd122db80761a1e5e270edafbf7f77f9ff81cba3c1` |

- **요청 헤더** — 학교 서버는 브라우저가 보낸 것처럼 보이지 않는 사진 요청에 143바이트 HTML 오류를 준다. 그래서 사진 요청에만 브라우저형 `User-Agent`(요청한 프로그램 이름)와 `Referer: https://www.kumoh.ac.kr/ko/index.do`(어느 페이지에서 왔는지)를 붙인다. 로고 요청은 전과 같다.
- **저장 조건** — 바이트 수, 지문, JPEG 형식, 1920×280 크기가 모두 맞을 때만 저장한다. 바이트 수와 지문을 먼저 보므로 HTML 오류는 그림을 열기 전에 걸린다.
- **재압축 없음** — 받은 바이트를 그대로 쓴다. 저장한 파일의 지문이 표의 값과 같다.
- **시간 한도** — 사진은 요청 하나가 응답 없이 기다리는 시간 15초, 한 장 전체 60초로 로고의 한도(5초·20초)와 따로 둔다. 4초·10초였을 때 실제 배포 준비에서 한 장이 시간 초과로 빠져 늘렸다.
- **다시 시도** — 시간 초과나 연결 오류가 나면 한 장당 한 번 더 받는다. 다시 받을 때는 처음부터 새로 읽고, 두 번의 시간을 합쳐 한 장 전체 60초를 넘기지 않는다. 서버가 오류 상태로 답했거나 크기·주소·지문이 틀린 경우는 다시 받아도 같으므로 시도하지 않는다. 두 번째도 실패하면 그 사진만 건너뛴다.
- **빌드가 늘어나는 시간** — 네 장이 모두 끝까지 막혀도 4분 안쪽이다. 요청이 응답 없이 멈춘 흔한 경우는 한 장에 30초쯤이다.
- **한 장씩 처리** — 사진마다 따로 받고 따로 검사한다. 한 장이 실패해도 나머지를 계속 준비하고 종료 코드 0으로 끝낸다. 실패한 사진의 기존 파일은 그대로 둔다.
- **서버 응답** — `/chat-assets/<파일 이름>`을 `image/jpeg`로 낸다. 파일이 없으면 404로 답하고, 화면은 남색 바탕으로 동작한다.

학교가 사진을 바꾸면 지문이 달라져 준비가 실패한다. 그때는 새 사진을 눈으로 확인한 뒤 표와 스크립트의 바이트 수·지문을 함께 고친다.

- **그리기** — 글자 크기 172px, 줄 간격은 글자 크기의 1.12배, 줄은 모두 들여쓰기 없이 같은 왼쪽 끝에서 시작한다. 투명 바탕에 그린 뒤 글자가 실제로 차지한 영역에 16px 여백만 남기고 잘라 PNG로 저장한다. 시안에서 같은 값으로 그린 로그인 제목은 1014×376이다.
- **메인 제목의 크기** — 실제 글꼴로 그려야 알 수 있어 화면의 `img`에 가로·세로 값을 적지 않는다. 높이는 `chat.css`가 정한다.
- **받기** — 글꼴별 기대 바이트 수를 받기 상한으로 사용함. 응답에 적힌 크기가 상한을 넘으면 읽기 전에 차단하고, 크기 표시가 없어도 읽는 도중 상한을 넘으면 중단함. 주소 이동은 `https://raw.githubusercontent.com` 안에서만 허용함. 바이트 수와 지문이 모두 맞을 때만 글꼴을 여는 방식임.
- **빠진 글자 검사** — 각 글자의 모양과 글꼴의 '없는 글자' 모양을 비교함. 같은 모양이면 해당 그림만 실패 처리함. 공백은 비교에서 제외함.
- **한 번만 받기** — 한국어·영어 그림 네 장은 같은 Gugi를 사용함. 주소마다 한 번만 받으며 실패도 기억해 다시 받지 않는 방식임.
- **글꼴은 내려 주지 않는다** — 글꼴 파일은 그림을 그릴 때만 메모리에서 쓰고 디스크에 저장하지 않는다. 서버의 허용 파일 목록에도 없다. 저장소에도 넣지 않는다.
- **실패 처리** — 글꼴을 받지 못하거나 지문이 다르면 기존 그림을 그대로 두고 종료 코드 0으로 끝낸다. 그림이 없으면 서버가 404로 답하고 화면은 같은 글귀를 기본 글꼴 제목으로 보여 준다.
- **서버 응답** — `/chat-assets/title-lettering.png`과 `/chat-assets/main-lettering.png`을 `image/png`로 낸다.

이 라이선스는 글꼴로 만든 문서(여기서는 PNG)에는 같은 라이선스를 요구하지 않는다. 글꼴 파일을 함께 나눠 주지 않으므로 라이선스 사본을 저장소에 넣지 않고 위 표로 출처를 밝힌다.

## 검증

추가 의존성이나 외부 복사 코드 없이 기존 Pillow와 파이썬 표준 라이브러리(`colorsys` 포함)를 사용한다. 밝은 로고 검사는 몇 픽셀짜리 가짜 로고로 파란 픽셀 유지, 흰 바탕 투명, 검정 글자 흰색을 본다. 제목 글자 그리기 검사는 Pillow에 들어 있는 기본 글꼴과 영문 글귀로 한다. 동작 시트의 형식·색 모드·크기 검사는 메모리에서 만든 가상 그림으로 하고, 저장소의 실제 시트는 테스트 하나가 읽기만 해서 지문과 크기를 확인한다. 그 밖에는 가상 이미지와 가짜 응답만 사용한다. 검증 명령은 다음과 같음.

```powershell
node --test (Get-ChildItem api/tests/web -Filter *.test.mjs).FullName
python -B -m unittest discover -s api/tests
```
