# Agent 루프 설계

제안서 3단계(학적 데이터 연동)의 핵심. "검색 결과와 학적 데이터를 대조·연산"하는 부분이다.

---

## 왜 단순 RAG로는 부족한가

```
질문: "내 학적에서 졸업하려면 대면 과목 몇 학점 더 들어야 해?"
```

단순 RAG는 졸업 요건 조문을 찾아 "대면 과목 30학점 이상 이수" 라고 답한다.
질문에 대한 답이 아니다. 필요한 건:

1. 졸업 요건 조문 검색 → "대면 30학점"
2. 학적 조회 → "현재 대면 22학점 이수"
3. 연산 → "8학점 더 필요"
4. 여기서 끝나지 않는다 — 전공/학번별로 요건이 다르면 **다시 검색**해야 한다

3~4단계 때문에 루프가 필요하다.

---

## 루프 구조

```
      ┌─────────────────────────────────────┐
      │                                     │
질문 ─┴→ [계획] 필요한 정보가 무엇인가       │
         │                                  │
         ├→ 도구: search(query)              │
         ├→ 도구: get_academic_profile()     │
         ├→ 도구: calculate(expr)            │
         │                                  │
         ↓                                  │
      [평가] 답하기에 충분한가? ─── 아니오 ──┘
         │                          (최대 N회)
        예
         ↓
      [생성] 답변 + 인용
         ↓
      [검증] 근거 없는 서술 제거
```

### 종료 조건 (반드시 고정한다)

- 최대 반복 횟수 `N = 3`
- 동일 쿼리 재검색 금지 (무한 루프 방지)
- 총 지연 시간 상한 초과 시 강제 종료 → 부분 답변 또는 행정실 안내

**상한 없는 Agent 루프는 반드시 폭주한다.** 비용과 지연 양쪽에서 문제가 된다.

---

## 도구 정의

### `search(query: str) -> list[RetrievedChunk]`
rag-core 호출. Agent가 쿼리를 재작성할 수 있다.
예: "졸업 요건" → 학적 조회 후 → "컴퓨터공학전공 2022학번 졸업 요건"

### `get_academic_profile() -> AcademicProfile`
학적 API 호출. `use_academic_data=true` 일 때만 사용 가능.

```python
AcademicProfile:
    department: str      # 소속 학과·전공
    admission_year: int  # 학번 연도 (요건 적용 기준)
    grade: int
    credits: dict        # {"전공필수": 30, "대면": 22, ...}
    gpa: float
```

학번 연도가 중요하다. 학칙은 개정되고, 적용 기준은 입학년도를 따르는 경우가 많다.

### `calculate(expression: str) -> float`
학점 차감 등 산술. LLM에게 계산을 맡기지 않는다.
"30 - 22 = 8"을 틀리는 경우가 실제로 있고, 숫자가 틀리면 답변 전체가 무의미해진다.

## 개인화 판단

모든 질문에 학적을 조회하면 불필요한 개인정보 접근이 발생한다.
1차로 규칙 기반 판단 → 애매하면 LLM 판단.

| 신호 | 판단 |
|---|---|
| "내", "제가", "나는", "저는" 포함 | 개인화 필요 |
| "요건이 뭐야", "기준 알려줘" | 일반 답변 |
| "졸업 가능해?" | 개인화 필요 |

규칙을 먼저 두는 이유 — LLM 호출 1회를 아끼고, 판단이 결정적이라 디버깅이 쉽다.

---

## 실패 처리

| 상황 | 동작 |
|---|---|
| 학적 API 응답 없음 | 일반 답변으로 폴백 + "학적 연동 실패" 안내 |
| 검색 결과 없음 | 답변 생성하지 않음 → 행정실 안내 |
| N회 반복 후에도 정보 부족 | 확보한 만큼만 답변 + 나머지는 행정실 안내 |

**모든 실패 경로가 "행정실 안내"로 수렴한다.** 억지로 답을 만드는 경로를 두지 않는다.

---

## 테스트 전략

Agent 루프는 LLM 응답에 의존해 테스트가 어렵다. 두 층으로 나눈다.

1. **도구 레벨** — 각 도구를 개별 단위 테스트 (LLM 없이)
2. **루프 레벨** — LLM 응답을 고정 시나리오로 모킹해 종료 조건·폴백 검증

실제 LLM을 쓰는 검증은 `run_eval.py` 통합 평가에서 한다.
